# Harness 작성

규칙은 새 에이전트가 현재 사용자 지시와 실제 소스만으로 실행할 수 있게 쓴다. 필요한
맥락·완료 조건·비목표·확인 방법을 명시하고 사건 일지나 중복된 지침을 쌓지 않는다.

추가할 규칙은 실제 실패를 막는지, 코드에서 이미 알 수 없는지, 다른 규칙과 중복되지 않는지,
구체적 행동을 바꾸는지, 이후 작업에도 적용되는지 확인한다. 한 번의 사건을 막기 위해
새 신원·진행·완료 원장을 추가하지 않는다.

스킬의 순서·조건부 경로·효과·하위 스킬·재작업 지점은 core-skills.json에 정의한다.
본문과 정의의 phase ID를 일치시키고 supporting file을 실제 단계에서 참조한다. 하위 스킬의
필요 효과가 상위 phase에서 허용되지 않는 실행 불가능한 계약을 만들지 않는다.

기계는 실제 순서·상태·소유권·원문 일치·관측 결과를 강제한다. 에이전트의 의미 판단은
그 판단과 근거로 기록한다. 해시를 사용자 동의나 의미적 정확성의 증명이라고 주장하지 않는다.

Gate 변경에는 목적·비목표와 허용/거부 회귀를 함께 정의한다. 읽기·실패 보고·사용자 입력·
복구가 원래 업무 절차의 오류로 막히지 않게 한다. Claude와 Codex가 공유 코어를 사용하되
각 호스트의 실제 이벤트·권한·종료 계약을 확인한다. 설정 선언과 실제 활성화는 별개다.

파일 변경은 실제 대상 checkout의 writer lease와 native 경로를 사용한다. 현재 세션의
CWD를 바꾸거나 새 세션을 만들 필요는 없다. 검사는 대상 저장소 project.json의 등록된
native 명령과 개발 지침을 따른다. 특정 패키지 관리자·프레임워크·CI 구성을 일반 하네스의
기본값으로 강제하지 않는다. 경로를 이동할 때 참조와 실제 호출 테스트도 갱신한다.

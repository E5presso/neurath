# 평가와 재작업

평가는 원래 사용자 목표와 미충족 인수 조건을 확인한다. 테스트·자체 판단·독립 리뷰·
실제 외부 결과·사용자 승인은 각기 다른 근거이며 서로 대체하지 않는다. 별도의 평가
완료 원장을 만들지 않고 같은 Task의 단계·보고·재작업 이력에 연결한다.

먼저 현재 소스와 문서로 답할 수 있는 사실을 조사한다. 사용자가 결정해야 하는 범위·제품
의미·권한만 구체적인 영향과 권고를 붙여 질문한다. 이미 명확한 요구를 반복 질문하지 않는다.
답변 대기는 성공이 아니며 원래 작업을 보존한다.

구현자는 자신의 산출물을 독립 검토했다고 주장하지 않는다. Reviewer는 실제 별도 actor로
고정된 변경을 읽고 구체적 영향과 근거가 있는 finding을 보고한다. 구현에 참여했던 actor를
final reviewer로 재사용하지 않는다. 계보·표시 이름으로 판단의 독립성을 대신하지 않는다.

미달 조건이 있으면 정의된 phase로 돌아가 수정한다. 동일 원인과 같은 상태에서 재시도만
반복하지 말고 접근을 바꾼다. 유효 finding을 점수 평균·시간 제한·반복 횟수로 덮어 통과시키지
않는다. 변경과 무관한 문제를 완료 조건에 무한히 추가하지 않는다.

검증은 실제 위험에 맞는 실패/성공, 경계, 통합, 복구 시나리오를 사용한다. 실행되지 않은
검사·모의 호스트·정적 설정을 실제 배포 호스트의 증거라고 표현하지 않는다. 같은 입력과
소스의 유효 결과는 재사용한다. 새로운 변경·실패·구체적 우려가 없으면 검사를 반복하지 않는다.

결과는 출처와 대상 버전을 유지한다. 원래 인수 조건이 충족되면 완료하며, 실패한 시도나
차단 보고는 원래 목표를 취소하지 않는다. 관련 회고는 memory_checkpoint에 남길 수 있지만
회고 작성 자체를 별도의 종료 의무로 만들지 않는다.

# 태스크와 단계 강제

배포된 `.agents/skills/core-skills.json`은 스킬의 순서 있는 phase, 완료 조건, 허용 효과,
하위 스킬과 재작업 지점을 정의한다. 실행 때 정의를 Task에 고정한다. 정의·본문·행위
테스트를 함께 갱신하며 산문에만 완료 순서를 맡기지 않는다.

`skill_start` 이후 `phase_read`의 현재 단계만 수행한다. 실제 결과를 `phase_complete`에
연결하며 조건을 만족하지 않은 다음 단계 진입은 거부된다. 하위 스킬을 끝내면 부모의
현재 phase로 돌아온다. 임의 skip이나 별도의 workflow·adaptive 완료 원장을 만들지 않는다.

실패·차단·시간 초과·worker 반환은 사용자 목표의 완료가 아니다. Task의 원래 인수 조건,
모든 적용 스킬 단계, 위임 결과 정리를 마쳐야 `task_complete`한다. 미완료 Task를 소유한
에이전트의 정상 Stop은 거부한다. 물리적 종료와 사용자 인터럽트는 작업 기록을 보존하며
성공으로 바꾸지 않는다. 실제 사용자 철회만 원문에 근거해 별도로 기록한다.

재작업은 같은 Task의 정의된 restart_from부터 진행한다. Bounded worker의 결과나 취소를
정리하기 전에 attempt를 바꾸지 않는다. 과거 결과·출처를 지우지 않는다. Native 검사는
실행 시작 때의 Task/skill attempt와 소스에 연결한다. 입력이 바뀌었거나 영향 범위가
불명확하면 이전 실행을 새 성공으로 소비하지 않는다. 조건·입력·대상이 같은 유효 결과는
재실행하지 않고 재사용할 수 있다.

Native 효과는 현재 phase와 모든 상위 phase가 허용해야 한다. 읽기·상태 조회·실패 보고·
lease 반환은 복구를 위해 계속 가능하다. 쓰기 lease, 사용자 게시 승인, 호스트의 실제 권한은
각각 검사한다. 식별자·해시·에이전트 보고만으로 실제 실행이나 사용자 동의를 만들지 않는다.

잘못된 거부·phase 우회·종료 교착을 발견하면 공통 정책의 harness_bypass로 영향을 격리하고
원래 미완료 Task를 유지한다. 재현→수정→관련 회귀→실제 호스트 검증으로 복구한다.
검사 통과·패키지 설치·실제 활성화를 구분하고, 정상 경로를 확인한 뒤 bypass를 해제한다.

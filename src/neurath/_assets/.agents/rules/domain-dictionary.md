# 프로젝트 용어와 명명

## 하네스를 설명하는 말

receipt를 금전 거래처럼 번역하지 않습니다. 문맥에 따라 설치 이력(installation record),
실행 결과(execution result), 검증 기록(verification record), 처리 기록(processing record)으로 씁니다.
기록의 존재와 성공·승인은 다릅니다. 기록이 확인하는 사실과 결과를 함께 설명합니다.
provenance는 출처, attestation은 호스트 확인, evaluator는 검토자, invocation은 도구 호출,
checkpoint는 인계 기록으로 설명합니다. 명령·경로·JSON 필드·클래스명은 정확한 식별자를 보존합니다.

## 대상 프로젝트의 용어

제품 용어는 `.neurath/project.json`의 documents.glossary와 현재 사용자 결정에서 확인합니다.
용어집이 없으면 기존 문서·소스의 용례를 찾아 의미를 확인하고, 필요한 경우에만 새 용어를 제안합니다.

새 domain noun·action verb를 도입하기 전에 관련 제품 요구사항과 기존 코드 이름을 비교합니다.
충돌하는 의미를 조용히 합치지 않고 근거와 차이를 보고합니다. 용어 변경은 사용자의 승인된 의도를 따라야 합니다.
용어집을 갱신할 때는 정의, 출처, 피해야 할 표현을 기록하고 제품이 구분하는 내부·외부 표현을 존중합니다.
문서 언어, 번역 필드, 클래스 접두사, 함수 명명 규칙은 대상 프로젝트의 규칙을 따릅니다.
하네스는 특정 언어나 프레임워크의 명명 관습을 설치 대상에 강제하지 않습니다.

# 하네스 결함 복구

실제 하네스 결함이면 현재 정책의 `harness_bypass(enabled=true)`로 영향받는 실행 차단을
격리하고 사용자에게 관측한 원인과 미완료 요구를 알린다. Task·phase 완료 순서, writer 동시성,
사용자 승인과 호스트 보안은 유지한다. 실패를 완료로 바꾸거나 원장을 직접 수정하지 않는다.

재현 가능한 입력, 기대·실제 결과와 관련 소스를 확인한다. 제품 문제인지 공통 하네스
문제인지 구분하고 승인된 수정 범위 안에서 원인을 고친다. 다른 담당자에게 맡길 때는
정확한 Task/Assignment와 재현을 전달한다. 전달·접수는 원래 요구의 완료가 아니다.

관련 실패/성공 회귀와 실제 호스트 경로로 수정 효과를 확인한다. 이미 유효한 검사를
단순 기록 갱신 때문에 반복하지 않는다. 독립 리뷰에는 실제 변경과 목표·인수 조건·
재현·수정 근거를 제공한다. 해결되지 않은 finding을 반복 횟수나 상태 label로 없애지 않는다.

정상 경로가 확인되면 `harness_bypass(enabled=false)`로 복구한다. 공유할 수 있는 일반적인
원인·복구 방법은 Newsroom에 알리고 결정을 memory_checkpoint에 보존한다. 공개 보고는
기존 보고 동의와 실제 공개 범위를 확인하고 비공개 코드·대화·경로를 포함하지 않는다.

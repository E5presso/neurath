# 협업과 provider 실행

이 문서는 협업 라이브러리와 훅 연결, 공개 `collaboration` 그룹 CLI의 동작을 설명합니다. 현재 옵션과 실행 경로는 [CLI 가이드](interfaces.md)에서 확인합니다. 모델 실행과 사용자 작업의 성공 판정은 서로 다른 상태입니다.

## 피어와 메시지

피어는 실제 관찰한 `HostSession`과 네이티브 자식 ID로 식별합니다. 재연결은 같은 피어를 재사용합니다. 프로젝트 내부 발견은 그 프로젝트의 주소만 반환하고, 프로젝트 간 대화는 참가자를 명시해서 연결합니다. 과거 세션 인수 이후 원 세션의 신규 배정은 허용하지 않습니다.

대화의 참가자·종료, 원 메시지의 발신자·수신자·답장 참조, 전달 상태·본문 읽음·ACK를 별도로 보존합니다. 종료한 대화의 원문은 읽을 수 있으며 대화를 닫아도 미완료 태스크는 그대로 남습니다. 구독 발행은 대화 참가자 중 활성 구독자에게만 전달합니다. 이미 저장한 발행을 재시도해도 새 구독자를 과거 발행에 추가하지 않습니다. 명시적으로 지정한 비활성 피어에게는 메시지·배정을 보관해 다음 연결에서 전달하며, 구독 발행의 활성 조건을 직접 수신자에게 확대하지 않습니다.

연결된 피어의 다음 SessionStart·UserPromptSubmit·PreToolUse 훅에 메시지 ID와 제목을 전달합니다. 본문은 선택해서 읽습니다. 훅 응답에 요약을 넣은 것은 전달 시도이며 실제 본문 읽음이나 수락이 아닙니다. 인박스 조회는 메시지를 보내거나 피어를 깨우지 않습니다. 전달 결과가 불명이면 원 메시지를 조회하며, 명시적 재전송은 확인된 미전달 실패에만 허용합니다. 늦은 응답이 읽음·ACK를 되돌리지 않습니다.

## 배정과 보고

`PrepareDelegationUseCase`는 원 태스크의 요구 개정·출처·역할·맡긴 범위·수신 경로를 검증해 준비합니다. `DelegateTaskUseCase`는 그 계획을 피어 메시지 또는 독립 provider 실행에 연결합니다. 피어, 네이티브 자식, 독립 provider 중 경로를 명시하며 작업 폴더나 워크트리만 보고 새 세션을 만들지 않습니다.

네이티브 자식은 실제 부모 세션에 관찰된 자식 주소를 사용합니다. 읽기·검토 보고에는 부모 작업 폴더의 작성 임대가 필요하지 않습니다. 독립 provider 계획의 `parent_session_id`는 Neurath의 배정 책임을 뜻하며 네이티브 부모·자식 관계를 꾸미는 값이 아닙니다.

준비, 메시지 연결, 수신자의 수락, 진행 관찰, 결과 보고를 구분합니다. 수신자는 기존 원 지시와 배정 범위로 실행·검사·보고할 수 있고 추가 인간 발언·해시·승인 증명서를 요구하지 않습니다. 수행자와 검토자의 보고 역할·원 개정·근거·남은 일을 보존합니다. 보고를 받거나 provider 프로세스가 종료됐다는 이유로 원 태스크를 성공 처리하지 않습니다. 태스크 상세에서 관련 배정을 함께 조회합니다.

부모 태스크의 정정·취소는 표준 커밋 후 도메인 사건으로 해당 태스크의 배정에만 전파합니다. 수락·진행·재위임·provider 시작은 현재 요구를 다시 확인합니다. 취소 후 늦게 온 보고는 원 개정의 역사로 남고 현재 요구를 완료하지 않습니다. 외부 실행의 실제 중단이 관찰되지 않았으면 `stop_requested`와 미확인 상태를 유지합니다.

## 독립 provider

모델 목록은 Codex app-server의 `model/list`와 Claude의 초기화 제어 응답에서 조회합니다. 모델 목록을 조회하기 위해 추론 프롬프트를 보내지 않습니다. 모델과 실행 권한은 별개이며 지원하지 않는 정책이나 암묵적 상속을 다른 설정으로 바꾸지 않습니다.

계획 저장과 실행 요청을 먼저 커밋한 뒤 CLI 프로세스를 시작합니다. 실행 중 SQLite 쓰기 트랜잭션은 열어두지 않습니다. 배정별 디렉터리에 고정 계획·원 입력·출력·프로세스 신원·종료 관찰을 보존합니다. 같은 배정의 재요청·재연결은 그 실행을 조회하고 새 모델 턴을 만들지 않습니다. 실행 여부가 불명확한 디렉터리를 자동 삭제하거나 새 실행으로 덮어쓰지 않습니다.

Codex 실행은 `--no-daemon`으로 공유 데스크톱 실행과 분리하며, 명시한 sandbox와 `approval_policy=never`를 사용합니다. Claude는 명시한 permission mode와 `--permission-prompts none`을 사용합니다. 지원 정책은 설치된 CLI 도움말과 대조합니다.

취소는 관리 실행의 PID·시작 시각·프로세스 그룹을 대조한 뒤 그 그룹에만 전달합니다. 중단 신호 전송은 중단 완료가 아닙니다. 실제 종료 결과가 있어야 중단 상태를 확정합니다. 실행 전 취소는 이후 시작도 막습니다. 기존 사용자의 실행을 별도 프로세스로 동시에 재개하거나 앱 전체를 종료하지 않습니다.

## 검증 경계

회귀 시험은 실제 SQLite·프레임워크 트랜잭션, 격리된 프로세스 실행, 전달 재시도·늦은 응답, 원문·개정 보존과 취소 경합을 확인합니다. fixture 통과와 실제 설치된 공급자의 모델 응답·실행 결과는 별도로 기록합니다. 이 후보의 소스 검증은 사용자 프로젝트의 설치·기존 데스크톱 연결 활성화 완료를 뜻하지 않습니다.

수신자가 없는 `collaboration publish`는 `published=false`를 반환하고 발행을 저장하지 않습니다. 이후 같은 키로 호출하여 수신자가 선택되면 최초 발행이며, 저장된 발행의 재시도는 원 수신자를 유지합니다.

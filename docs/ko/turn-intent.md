# 현재 턴의 의도와 보존된 작업

훅은 사용자의 문장을 그대로 보존합니다. 자연어 키워드나 별도 모델 호출로 문장의 목적을 추측하지 않습니다. 원문을 읽은 에이전트가 기존 미완료 작업이나 평가에 영향을 주는 경우에만 용도와 이번 턴의 수행 범위를 연결합니다. 사용자가 모드나 내부 식별자를 관리할 필요는 없습니다.

```sh
neurath context show
neurath context show --section sources
neurath session interpret --kind status --pause \
  --reason '현재 원문은 상태 설명만 요청하고 이번 턴의 수행을 제외한다.'
```

`session interpret`는 기본적으로 현재 관찰 턴의 마지막 원문을 선택합니다. 필요하면 같은 턴의 `--source-id`를 지정합니다. `--kind status`는 결과 요구를 바꾸지 않는 상태 질문·설명·같은 작업의 턴 제어이며, 실제 새 요구나 혼합 요청은 `--kind prompt`로 남깁니다. 판단 이유와 이전 용도·원문 참조는 기존 Memory에 보존하고 본문·발신 맥락·출처는 바꾸지 않습니다. 이미 태스크 정의에 연결된 요구를 status로 바꾸어 완료 검사를 피할 수 없습니다.

`--pause`는 현재 실행의 `turn_control` 원인으로 이번 턴의 제어권을 반환합니다. 첫 Stop부터 작업을 계속하라고 요구하지 않으며, 반복 Stop도 원 태스크·phase를 취소하거나 성공 처리하지 않습니다. 외부 의존 대기를 꾸며 만들거나 일반 도구를 모두 차단하지 않습니다. 실제로 관찰된 다음 사용자 턴은 같은 작업을 유지한 채 실행 상태를 다시 연결하고, 현재 요청 범위의 명시적 재개는 기존 `session resume`을 사용합니다. 상태 질문이라도 작업을 계속하도록 한 원문이면 에이전트가 pause 여부를 구분합니다. 단순 대화에 영향을 받는 기존 작업이 없다면 새 태스크·workflow·해석 절차를 강제하지 않습니다.

독립 평가에는 status를 포함한 원문, 최신 정정, 에이전트 판단 근거, 전체 TODO와 누락 요구를 계속 제공합니다. status·과거 summary는 새로운 결과 요구로 후보 지문을 바꾸지 않습니다. 실제 새 prompt는 TODO에 아직 연결되지 않았어도 지문과 평가 입력에 포함됩니다. 관련 요구 개정이나 실제 산출물 변경은 기존 평가를 여전히 무효화하며 같은 원 작업에서 보완합니다. 에이전트의 잘못된 해석을 사용자 지시나 독립 평가의 승인으로 승격하지 않습니다.

## 세션 주소와 tool cwd

관찰된 provider/native 세션 주소가 하나의 세션을 가리키면, 도구를 다른 폴더에서 실행해도 그 원 작업을 조회합니다. 조회만으로 새 프로젝트나 세션을 만들거나 원 세션의 경로를 변경하지 않습니다. `context show`의 `host.session_directory`는 저장된 세션 경로, `host.invocation_directory`는 실제 호출 경로이며 `project_id`는 원 작업의 범위입니다.

같은 주소가 실제로 여러 프로젝트나 호스트에 관찰되어 있으면 현재 프로젝트 경로로 구분합니다. 그래도 모호하면 관찰된 provider와 project ID를 `context show --session ... --provider ... --project-id ...`에 지정합니다. 에이전트가 이미 조회한 맥락에서 선택하며, 무관한 프로젝트의 세션을 합치거나 새로운 네이티브 신원을 만들지 않습니다.

`core_0016`은 새 `turn_control` 실행 원인을 읽을 수 있는 버전 경계입니다. 물리적 원문·태스크 표는 유지하지만 공유 DB를 사용하는 구버전이 새 상태를 잘못 읽지 않도록 Alembic 호환 검사를 적용합니다. 해당 원인이 남은 실행의 downgrade는 자료를 버리지 않고 거절합니다. 설치·전환은 기존 [보존형 배포](distribution.md) 경로를 따릅니다.

회귀는 실제 CLI와 SQLite에서 첫 Stop 제어 반환, 원 TODO/run 보존과 재개, 다른 cwd와 중복 관찰 주소, 상태 질문 뒤 평가 재사용, 새 누락 요구·실제 산출물 변경의 무효화를 확인합니다. 원문 의미의 정확한 판단은 에이전트의 책임이며 이 시험을 네이티브 모델의 판단 품질이나 실제 호스트 활성화 증거로 취급하지 않습니다.

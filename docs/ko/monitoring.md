# 요청된 외부 의존 감시

[문서 안내](index.md) · [English](../en/monitoring.md)

감시는 Task의 실제 외부 대기와 원 조건·후속 범위에 연결합니다. 일반 대기는 감시를 시작하지 않습니다. 사용자가 감시를 요청한 경우 에이전트가 `task update --action wait --monitor output|pull_request`에 대상·조건·후속 범위·관찰을 전달합니다. 현재 실행·개정은 CLI가 조회하며, 잘못된 대상은 대기 변경과 함께 롤백합니다.

## 같은 대화로 돌아오는 흐름

응답의 `monitors[].callback`은 등록된 작업과 감시를 가리키는 `NEURATH_MONITOR_TICK <task-id> <number>`입니다. 이는 승인 토큰이 아니라 내부 콜백 문법입니다. 에이전트는 요청된 주기로 **호스트의 기존 스케줄러에서 같은 대화**에 이 콜백을 예약합니다. Neurath가 새 모델 세션이나 독립 데몬을 만들지 않습니다. 예약 응답만으로 실제 예약·전달 완료를 주장하지 않습니다.

`UserPromptSubmit` 훅은 콜백을 새 사용자 목표로 저장하지 않고 현재 소유 태스크의 감시를 한 번 조회합니다. 첫 완결 관찰과 같은 상태에는 `continue:false`를 반환하여 모델 작업을 시작하지 않습니다. 새 변화에만 원 대기의 조건·허용 후속 범위·실제 관찰을 `additionalContext`로 전달합니다. stdout 이후 해당 사건을 제출 상태로 저장하므로 같은 사건을 매 콜백에 다시 전달하지 않습니다. 새 관찰 실패·예산 종료도 변화로 한 번 알리며 반복 실패로 모델을 계속 깨우지 않습니다.

- `pull_request`: 정확한 GitHub PR URL을 `gh pr view`로 조회합니다. 상태·head·리뷰·체크만 비교하며 시각·로그는 제외합니다.
- `output`: 절대 파일의 마지막 64 KiB에서 마지막 완결 JSON 행의 문자열 `state`를 읽습니다. 출력 조각은 변화가 아닙니다.

변화는 조건 충족이나 작업 성공을 뜻하지 않습니다. 실행자는 실제 결과를 확인한 뒤 `task update --action resume --monitor-event N --reason ...`으로 정확한 사건에 근거해 대기를 해소합니다. 정상 대기 실행·피어도 같은 사건 흐름으로 재개합니다. 작업을 마쳤거나 취소·예산 종료가 확인되면 호스트 스케줄도 종료합니다.

## 상태·보존·복구

`context show`는 작업에 속한 감시와 사건을 보여 줍니다. `monitor status --task-id ... --monitor-number ...`은 상세 조회이며 `monitor tick`은 모델 호출 없이 한 번 관찰하는 진단 경로입니다. 프로젝트·세션·실행·세대 옵션은 명시적 진단에만 필요하고 기본값은 현재 호스트와 저장된 감시에서 찾습니다. 단일 tick의 stderr 알림은 네이티브 모델 전달 증거가 아닙니다.

관찰 예약은 커밋 후 실행하며 외부 조회 중 DB 트랜잭션을 유지하지 않습니다. 정정·취소·인계와 늦은 결과를 현재 원장에 대조합니다. 미확인 자원을 실제 종료로 꾸미지 않고, 인계는 기존 사건·잔여 예산·취소 상태를 보존합니다. 연결 종료 자체는 기존 감시의 취소가 아닙니다.

A37·A54·B23·B24는 변화·동일 상태·실패·취소·인계 보존을 검증합니다. `tests/test_host_flow.py`는 CLI→대기→콜백→출력 receipt→재개를 같은 SQLite에서 검사합니다. 호스트별 실제 예약 호출과 모델 이전 훅 실행은 설치·호스트 시험에서 별도로 확인해야 합니다. 지원되지 않는 호스트 스케줄을 설치됐다고 보고하지 않습니다.

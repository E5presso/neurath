# 요청된 외부 의존 감시

[문서 안내](index.md) · [English](../en/monitoring.md)

#146 후보는 태스크의 명시적인 외부 대기에 감시·사건·알림을 종속시킵니다. 대기 등록은 감시 시작 요청이 아니며, `RegisterMonitorUseCase`에 현재 원장 개정·소유 실행·정확한 대상·유한 관찰 예산을 전달해야 합니다. 대상은 기존 `ExternalWait.target`과 일치해야 하고 같은 대기에 활성 감시나 종료 미확인 자원이 있으면 중복 등록을 거부합니다. 조건과 후속 범위는 원 대기 이력을 그대로 사용합니다.

## 관찰과 후속 범위

내부 런타임은 `neurath monitor tick --project-id ... --session-id ... --task-id ... --monitor-number ... --execution-id ... --generation ...`으로 한 번 관찰합니다. 이 명령은 스케줄을 생성하거나 모델·사용자 훅을 실행하지 않습니다. 주기 호출은 호스트 런타임의 책임이며 후보 설치·자동 스케줄 등록은 이 변경에 포함하지 않습니다.

- `pull_request`: 정확한 `https://github.com/<owner>/<repo>/pull/<number>`에 `gh pr view`를 사용합니다. 인증은 기존 GitHub CLI 환경을 사용합니다. PR 상태·head 커밋·리뷰 판정·병합 상태·체크 상태만 정규화하고 시각·실행 로그는 변화 판단에서 제외합니다. 조회 프로세스 제한은 30초입니다.
- `output`: 명시한 절대 파일의 마지막 64KiB에서 마지막 완결 JSON 행의 문자열 `state`만 사용합니다. 예: `{"state":"waiting"}\n`, `{"state":"done"}\n`. 미완결 조각은 새 사건이 아닙니다. 다른 JSON 형식과 파일 접근 실패는 관찰 실패로 보존합니다.

첫 완결 상태는 `initial_state`와 `current_state`에 표시하며 변화 사건을 만들지 않습니다. 이후 실제 상태 변화만 순번을 가진 사건·근거·원 조건·허용 후속 범위를 남깁니다. 같은 상태와 출력 조각에는 새 사건·새 알림·모델 호출이 없습니다. 상태 변화가 조건 충족을 뜻한다고 자동 해석하지 않습니다.

`GetMonitorUseCase`, `GetTaskUseCase`, `neurath monitor status --project-id ... --session-id ... --task-id ... --monitor-number ...`은 현재 실제 상태·모든 정확한 사건·ACK·해소·알림 실패·필요한 조작·잔여 예산·미확인 자원을 조회합니다. 조회는 재관찰·재전송·재개가 아닙니다. `AcknowledgeMonitorEventUseCase`는 사건 하나의 소비만 기록합니다. `ResolveMonitorEventUseCase`는 현재 요구·대기·소유 실행을 대조하고 명시한 해소 근거를 저장한 뒤 같은 시도를 active로 돌립니다. ACK나 대기 해소는 태스크 성공이 아닙니다.

## 취소·복구·인계

관찰 예약과 예산 소비는 외부 조회 전에 커밋하고, 외부 관찰·알림 중 SQLite 쓰기 트랜잭션을 유지하지 않습니다. 예약 ID가 남으면 다른 tick은 중복 관찰하지 않습니다. 관찰 도중의 취소와 요구 정정은 최신 원장을 다시 읽어 확인하며 늦은 결과로 새 사건을 만들지 않습니다. 태스크 해소·결과 보고·요구 정정·무효화와 명시적인 실행 취소·실제 Interrupt는 새 관찰과 제출을 중지합니다.

`RecoverMonitorUseCase`는 정확한 예약 ID·현재 소유 실행·세대와 실제 종료 관찰을 요구합니다. RUNNING·UNKNOWN은 회수하지 않습니다. 이 명령은 내부 관찰 결과 계약이며 임의 사용자가 종료를 선언하는 공개 CLI가 아닙니다. 복구로 취소를 해제하거나 예산을 늘리지 않습니다. 실제 호스트 자원 종료 관찰은 해당 호스트 어댑터가 제공해야 하며, 후보의 단일 관찰 CLI 자체는 네이티브 스케줄러 자원을 추적하지 않습니다.

세션 인계는 기존 실제 실행 종료·작성 해제 조건에 더해 진행 관찰 또는 결과 불명 알림 제출이 있으면 거부합니다. 자원을 조정한 뒤 감시 소유 실행과 세대만 옮기고 취소·첫 관찰·미처리 사건·알림 시도·잔여 예산을 유지합니다. 원 세션의 재연결은 새 감시나 실행을 만들지 않습니다.

## 알림과 검증 경계

알림은 `written → submitting → submitted/failed`를 보존하며 실제 전달 확인이 있는 같은 제출만 `delivered`로 기록합니다. 기본 어댑터는 stderr 전체 출력과 flush의 반환을 `submitted`로 기록합니다. 이는 네이티브 알림 수신·사용자 열람·모델 맥락 전달 확인이 아닙니다. 실패는 원인·필요한 조작과 함께 조회에 남으며 같은 사건은 최대 세 번만 제출합니다. 결과 기록이 유실된 `submitting`은 자동 재제출하지 않습니다. 알림 실패·재연결·동일 대기를 이유로 실행자를 호출하지 않습니다.

`tests/test_monitoring.py`는 실제 스캔·SQLite·CLI 및 결정론적 외부 fixture로 A37·A54·B23·B24 경계를 검사합니다. `core_0011`은 기존 원장·원문·대기 이력을 보존하며 감시 이력이 있는 downgrade를 거부합니다. 소스 검증과 실제 설치·주기 스케줄·네이티브 알림·모델 전달 검증은 별개입니다.

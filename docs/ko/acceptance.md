# 요구사항 검증과 구현 순서

[명세](specification.md) · [구조](architecture.md) · [기능 대조](capability-continuity.md) · [English](../en/acceptance.md)

전체 제품의 검증 기준입니다. 현재 구현된 기반·태스크 시험의 범위는 [코어 기반](core-foundation.md)과 [태스크 원장](task-ledger.md)에 설명합니다. 목록 전체의 구현·통과를 뜻하지 않으며 매 실행에 모든 사례를 강제하지 않습니다.

## 1. 실제 행동 수용 사례

| ID | 상황 | 확인할 결과 |
| --- | --- | --- |
| A01 | 프롬프트·티켓·스펙과 실제 정정으로 작업 정의 | 각 요구의 원문과 남은 결과를 연결; 채팅마다 같은 직접 입력을 요구하지 않음 |
| A02 | 조사만 요청한 작업의 결과를 제3자가 평가 | 원문·최신 정정과 산출물을 대조해 요청 범위를 넘는 변경을 지적; 평가 보고를 새 사용자 지시로 취급하지 않음 |
| A03 | 사용자 요구가 처음부터 TODO에 빠짐 | 제3자가 원문과 전체 결과를 대조해 누락을 보고; 실행자가 같은 태스크 목록에 반영 |
| A04 | 상태 질문·사용자 정정·옛 요약이 섞임 | 정정한 부분만 변경; 질문을 새 목표로 만들거나 나머지 일을 버리지 않음 |
| A05 | 여러 작업의 TODO 상태가 바뀜 | 현재 전체 목록과 성공·실패·무효를 표시; 제출과 실제 결과 구분 |
| A06 | 실패한 시도 뒤 원래 요구가 남음 | 실패 기록과 후속 작업 보존; all-terminal과 all-successful 구분 |
| A07 | 선택한 스킬을 runner로 시작 | 정의 버전·입력·현재 단계·작업 조건을 읽고 실제 실행에 연결 |
| A08 | Phase의 명령이 실제 실패 | 실패 attempt 보존; 필수 다음 단계로 진행하지 않고 원인에 맞춰 재시도 |
| A09 | Phase가 독립 의미 검토를 요구 | 실제 후보와 담당 검토 결과를 소비한 뒤 진행; 말로 통과시키지 않음 |
| A10 | 외부 동작 후 응답 유실·runner 재시작 | 외부 결과 조회/중복 제거를 먼저 사용하고 둘 다 불가능하면 결과 불명으로 대기; 무조건 재전송하지 않음 |
| A11 | 선택 단계와 필수 단계를 건너뛰려 함 | 정의 조건·실제 정정이 있는 건너뛰기만 허용; 이유·원결과 보존 |
| A12 | 진행 중 사용자 지시 또는 검사 대상 변경 | 관련 phase·근거만 재판단; 이전 정의·결과를 유지 |
| A13 | 마지막 phase와 run·태스크 마무리 | 중복 finalize 없음; 절차 완료와 사용자 목표 성공을 구분 |
| A14 | 조회 후 새 태스크가 추가된 상태에서 Stop | 최신 목록의 모든 태스크 완료 여부를 결정론적으로 검사; 새 미완료 작업이나 옛 턴으로 잘못 종료하지 않음 |
| A15 | Stop 반복·사용자 중단·외부 대기·하네스 고장 | 미완료 보존과 실제 중단/대기; 거절로 무한 모델 실행을 만들지 않음 |
| A16 | 압축·재개·동시 enclave 수정 | 최신 사실·목표·runner 복원; stale 쓰기와 옛 기억의 덮어쓰기 거절 |
| A17 | 피어 발견·질문·본문 읽기·ACK·답장 | 실제 주소·발신자와 전달/읽기 구분; 구독·대화 종료도 보존 |
| A18 | 직접 사용자 입력 없는 배정 수신자 | 배정된 범위의 실행·검사·보고 가능; 원래 지시·책임 보존 |
| A19 | 전달 결과 불명·재연결·늦은 ACK | 원 메시지로 복구; 새 ACK 퇴행·중복 수행·무한 재전송 없음 |
| A20 | Newsroom 게시와 비활성 피어 | 활성 피어에 제목만 전달; 본문 선택 조회, 비활성 깨우기 없음 |
| A21 | 잘못된 기사 정정과 댓글 | 작성자·개정·이력 보존; 실제 사용한 작업에 영향 반영 |
| A22 | Provider 계획·실행·취소·복구 | 실제 모델·정책·부모관계 확인; 미지원 정책 몰래 대체하지 않음 |
| A23 | 독립 리뷰 결과 수용·게시 | 검토 후보·현재 HEAD·결과를 대조; 사용자 공개 권한 범위 준수 |
| A24 | 마지막 체크포인트 없이 세션 인수 | 원문·task·runner·enclave·writer 책임을 보존하고 중복 작성 차단 |
| A25 | 사용자가 요청한 회고의 개선을 다음 관련 세션에 적용 | 실제 효과 확인·잘못된 교훈 철회; 목표·권한·규칙 무단 변경 없음 |
| A26 | Graphify 업데이트에 문서 관계 포함 | 원래 의미 관계 보존·검사; 종료 코드만으로 성공 선언하지 않음 |
| A31 | 읽기·동시 작성·작성자 종료 | 읽기는 임대 없이; 작성 충돌 방지와 종료 후 안전한 회수 |
| A32 | 검사 성공 후 코드 변경·관련 실패 | 변경된 대상에 옛 성공만 재사용하지 않음; 필요한 검사만 재실행 |
| A33 | 검사 중단·타임아웃·큰 출력 | 실제 제한 시간·중단 결과·제한된 출력 저장과 재시도 지원 |
| A34 | 기존 DB와 미완료 자료의 이전 | 원본·WAL 보존, 기능별 대응·재개·rollback 확인; 미인식≠0개 |
| A35 | 다른 훅·CLI·프로젝트 지침과 함께 설치 | 정확한 소유 설정만 갱신·검증; 기존 설치 검증 후 재사용 |
| A36 | CLI 오류·저장 실패·우회·재시작 | 실제 실패와 재개 가능 상태 보존; 복구 때문에 원문 출처를 잃지 않음 |
| A37 | 변화 없는 대기·PR 감시·출력 조각 | 모델 추가 호출 0; 사건 변화 때만 의미 판단 |
| A39 | 기존 공개 작업·스킬의 전체 기능 대응 | 각 기능이 실제 유스케이스와 시험에 연결; 이름만 남기거나 수동화하지 않음 |
| A40 | 연결 프로젝트 전체 업데이트와 finish-session | 배포·설치·활성화·원래 일·runner·Git/그래프·소유권·조율 종료 확인 |
| A41 | 공개 보고·기여 준비와 제출 | 공개 범위·민감정보·실제 제출 결과 확인; 자동 공개로 확대하지 않음 |

### 경계·경합 반례

| ID | 상황 | 확인할 결과 |
| --- | --- | --- |
| A42 | TODO는 완료됐지만 사용자 의도를 충족하지 못한 결과 | 독립 결과 평가에서 미달 근거를 보고하고 같은 태스크 목록에 필요한 작업 반영 |
| A43 | 독립 결과 평가 중 관련 사용자 지시나 산출물 변경 | 영향받은 평가만 갱신; 무관한 변경과 평가 기록 자체로 재평가 루프를 만들지 않음 |
| A44 | 가짜 입력 대기와 실제 외부 대기, 독립 작업이 섞임 | 기존 지시로 해결 가능한 일과 독립 작업 수행; 실제 의존만 대기; 필요한 조작만 알림 |
| A47 | 부모 요청 정정/취소 후 늦은 수신·옛 결과·재위임 | 정정 부분만 전파; 취소 대상 신규 실행 없음; 실제 중단 확인 전 미확인 표시; 옛 결과로 현재 요구 완료 안 함 |
| A48 | Phase 시도 A 타임아웃 후 B 시작, A의 늦은 성공 도착 | A 이력 보존; B와 현재 정의의 조건을 만족한 것으로 처리하지 않음 |
| A49 | 외부 변경 응답 유실, 조회·중복 제거 경로 모두 없음 | 결과 불명 대기와 실제 알림; 자동 재실행 없음; 독립 작업 계속 |
| A50 | DB 전환 도중 옛 writer 재접속·새 사건 도착 | 구버전 쓰기 거절; 사건 보존/정상 순서 재생; 한 작성 경로; 정지 확인 실패 시 전환 없음 |
| A51 | 새 DB 기록 생성 뒤 구버전 rollback 시도 | 새 기록/미처리 사건 보존; 손실 없는 호환 복귀 또는 쓰기 중지/복구 버전 재개 |
| A52 | 독립 평가 대기·실패 또는 훅 장애 중 Stop | 미완료/검증 미확인 상태를 보존하고 제어권 반환; 반복 턴이나 가짜 성공 없음 |
| A53 | 사용자 중단·취소와 다른 턴의 늦은 응답 | 대상 실행의 실제 중단 확인; 이전 응답과 구분; 취소 후 자동 재개 없음 |
| A54 | 알림 제출 실패·동일 대기·재연결 | 실패와 필요한 조작을 조회 화면에 보존; 유한한 전달 재시도; 실행자 반복 호출 없음 |
| A55 | Dirty·미병합·untracked·필요 ignored 파일이 있는 워크트리 정리 | 범위 내 자료 보존·복원 검증 전에 삭제 없음; 원격 참조와 다른 작성자도 확인 |
| A56 | enclave 삭제/구독 해제/뉴스 새 개정/학습 보류 | stale 삭제 거절; 해제 후 발행 없음; 옛 seen은 새 개정 열람 아님; defer는 성공 아님 |
| A57 | 과거 기능을 선별한 새 공개·내부·호스트 경로로 수행 | 옛 128 작업/33 스킬의 필요한 결과를 관찰; 옛 이름을 요구하지 않으며 사용자 수동 처리로 떠넘긴 기능은 미구현 |
| A58 | 대기 중인 외부 실행 결과 확인 후 다른 요구만 정정 | 동일 attempt 결과를 반영하고 영향 없는 산출물 유지; 자동 재실행 없음 |
| A61 | DB 장애와 알림 전달 실패가 동시에 발생 | 가능한 호스트 오류/복구 기록에 미완료를 노출; 표시 불가능은 미확인으로 보고; 모델 루프 없음 |
| A62 | 관리 실행만 통과하고 실제 사용 연결은 검증하지 않음 | 실제 사용 연결의 훅·CLI·위임 결과가 확인되기 전 전체 적용 완료로 보고하지 않음 |
| A63 | 커밋·워크트리 생성·단순 코드 설명 요청 | 호스트 도구로 수행; 관련 없는 스킬/runner를 시작하지 않음 |
| A64 | 핵심 CLI 명령 목록과 기본 스킬 목록 조회 | 실제 기능별 명령·스킬 14개와 대응; MCP 서버/어댑터 없음; 내부 전이를 별칭으로 재노출하지 않음 |
| A65 | 임대·ACK·종결과 잘린 본문 | 실제 사건으로 내부 처리; 가짜 신원·동의·성공 입력 불가; 잘린 본문은 읽음 확정 안 함 |
| A66 | 선택한 기본 스킬과 프로젝트 전문 스킬 실행 | 해당 절차와 결과를 완주; 기본 제외가 기능 삭제나 사용자 수작업 전환이 아님 |
| A67 | 옛 스킬 run 실행 중 공개 목록 전환 | 고정 정의·원 작업 유지; 캐시 호출에 대체 경로 제시; 프로젝트 스킬 보존·반복 실패 없음 |
| A68 | 명세와 실행 계획을 정하고 UI를 포함해 구현 | define-spec에 요구/동작/실행 순서/검증 계획 통합; implement-spec에서 UI 검증 수행; 별도 plan/implement-ui 호출 불필요 |
| A69 | 같은 작업의 조회·수행/검토 보고·피어/provider 위임 | 조회는 제한된 맥락; 보고 역할·근거 유지; 같은 위임의 중복 실행 없음; 임의 연산 dispatcher 없음 |
| A70 | 공개 명령 이름과 도움말 확인 | 실제 기능별 neurath 명령 경로; 실제 도움말과 설치 가이드 일치 |
| A71 | 사용자가 요청한 회고에서 개선 후보를 검증·적용 | 일반 대화의 수행 지시로 시작; 정상 대조·효과 확인·철회; 사용자용 하네스 스킬/승인 증명 불필요 |
| A72 | 세션 맥락 유실 또는 명시적 재개/인수 | 자동 복원 또는 session resume으로 기존 원문/미완료/runner를 이어감; recover-session 스킬 불필요 |
| A73 | 피어가 기존 지시 범위의 작업을 전달 | 정상 수행; 비인간 발신만으로 거절·인간 재입력·해시/서명 요구 없음 |
| A74 | 문제가 드러난 세션 말미에 회고 제안 | 한 번 일반 질문; 수락 전 회고 평가/지속적 개선 실행 없음; 원래 작업 종료 가능 |
| A75 | 회고 요청이 없고 제안을 거절·무응답했거나 문제가 없는 세션 | 회고 미실행; 반복 질문/자동 재시도/미완료 의무/종료 차단 없음 |
| A76 | 사용자가 회고를 지시하거나 일반 문장으로 수락 | 스킬의 사용자 선택 분기에서 별도 서브에이전트 또는 다른 provider에게 회고 평가 위탁; 근거 있는 개선·검증·적용; 재승인·전용 토큰 불필요 |

## 2. 구현 순서와 결과물

1. Hook·CLI 요청 → SQLite 조회·전이 → 실제 호스트 집행을 일회용 작업으로 검증한다.
2. 원문/task/TODO → phase runner → 실제 결과 → 제3자 결과 평가 → 결정론적 Stop을 연결하고 enclave 복원을 검증한다. 결과 평가는 해당 스킬의 phase로 관리하고 연결된 태스크 상태에 반영한다.
3. 피어·자식·provider, Newsroom, 기억·인계·사용자가 요청한 회고의 제3자 평가·학습·Graphify와 선별한 스킬을 연결한다.
4. 정상 사례와 누락·범위 변경·취소·실패·압축·재시작 사례를 검증한다. 평가자의 오판과 잘못된 미달 보고도 확인하고, 사용자 지시·근거에 따라 처리한다.
5. 실제 자료의 복제본에서 이전·rollback·재개를 시험하고 요청된 배포·프로젝트 업데이트·실제 활성화·finish-session을 수행한다.

각 단계의 구현 결과와 미완료를 기록합니다. 문서나 모의 시험만으로 실제 호스트 검증·전체 구현 완료를 선언하지 않습니다.

# 원문·태스크·TODO 원장

[문서 안내](index.md) · [코어 기반](core-foundation.md) · [English](../en/task-ledger.md)

#140은 사용자 요구와 정정, 현재 작업, 실행 시도의 제출·관찰 결과를 같은 SQLite 원장에
연결합니다. 현재 내부 Python 요청 API이며 공개 CLI·호스트 훅·phase runner는 후속 범위입니다.

## 도메인과 저장

`RequestSource`는 원문·발신 맥락·참조·최초 세션·정정 대상을 보존합니다. 원문이 같은
프로젝트에 있으면 다른 세션도 출처 ID를 재사용할 수 있습니다. 작성자가 인간인지에 따른
인증이나 새 입력 요구는 없습니다. `status`와 `summary` 출처는 조회 맥락으로 보존하되
태스크 정의나 실제 정정으로 승격하지 않습니다.

`Task`는 현재 요구와 그 이전 개정, 모든 실행 시도, 외부 대기·해소 이력을 소유합니다.
시도와 정의에 독립 저장소를 만들지 않습니다. 두 aggregate는 Spakky의
`AbstractAggregateRoot`를 사용하고 소유 기록은 불변 값입니다. 저장 포트와 adapter는
`IGenericRepository`·`AbstractGenericRepository`의 기본 CRUD·배치·생성자를 상속합니다.
추가 SQL은 프로젝트별 전체 목록 조회뿐입니다.

`@Table`·`AbstractMappableTable`·소유 관계·`SchemaRegistry`가 전체 aggregate를 매핑합니다.
요청마다 실제 `ConnectionManager`·`SessionManager`·`Transaction`을 사용합니다. 성공한
요청은 한 번 commit하고 예외 시 부모·자식의 모든 변경을 함께 rollback합니다. 정수 revision과
기본 저장소의 낙관적 검사가 오래된 변경을 거부합니다.

## 상태와 관찰

| 상태 | 뜻 |
| --- | --- |
| pending | 수행할 결과가 남았고 새 시도를 시작할 수 있는 상태 |
| active | 현재 요구 개정에 연결된 시도를 수행하는 상태 |
| waiting | 현재 시도가 실제 외부 의존을 기다리는 상태 |
| succeeded | 현재 개정의 실제 관찰 결과가 성공인 상태 |
| failed | 실패한 시도와 남은 요구를 보존하며 재시도 가능한 상태 |
| invalidated | 실제 정정으로 무효화됐으며 성공이 아닌 상태 |

시작은 요구 개정과 세션을 시도에 고정하며 외부 명령을 실행하거나 재제출하지 않습니다.
제출은 후보 설명·참조를 저장할 뿐 성공 상태를 만들지 않습니다. 결과에는 관찰 참조가
필요하고 성공과 비정상 종료 코드·남은 일이 충돌하면 거부합니다. 실패·부분 수행은 남은
일을 요구합니다. 부분 수행은 pending으로 돌아가고 재시도는 이전 시도를 보존한 채 새 번호를
만듭니다. 같은 확정 결과의 재보고는 멱등적이며 다른 결과로 덮어쓰지 않습니다.

정정은 실제 correction 출처와 현재 요구를 연결하고 지정한 필드만 바꿉니다. 값이 바뀌지
않으면 이미 끝난 요구를 다시 열지 않습니다. 바뀌면 이전 개정과 시도는 유지하고 현재 요구는
pending이 됩니다. 정정 전 시도의 늦은 결과는 이력에 저장하지만 새 요구를 완료하지 않습니다.
무효화 후의 늦은 보고도 작업을 되살리지 않습니다. 다른 작업이나 원문 본문은 바꾸지 않습니다.

대기는 외부 대상·해소 조건·기존 지시의 후속 범위·실제 관찰을 함께 기록합니다. 재개는 해소
관찰을 추가하고 같은 시도를 이어가며 새 실행을 자동 제출하지 않습니다. 대기 중에도 독립
작업은 ready 목록에 남습니다. 의존은 같은 프로젝트의 실제 태스크만 가리키며 중복·자기 의존·
순환을 거부합니다. 선행 작업의 실제 성공만 시작 조건을 충족합니다.

## 내부 요청 API

모든 함수는 `neurath.transport.task_requests`에 있으며 입력은 해당 이름의 개별 use case
모듈에 정의한 불변 Command/Query입니다. 쓰기 입력은 프로젝트·소유 세션·대상·관찰 revision을
지정합니다. 원문 생성과 태스크 생성은 새 ID를 반환합니다.

| 요청 | 기능 |
| --- | --- |
| record_source | 원문·참조·발신 맥락과 실제 정정 관계 보존 |
| create_task | 기존 출처에 작업·필요 결과·의존·후속 관계 연결 |
| start_task | 현재 요구에 대응하는 새 시도 시작 |
| submit_result | 성공과 구분되는 후보 자료 제출 |
| report_result | 관찰 결과·실패·부분 수행·남은 일 보존 |
| correct_task | 실제 정정에 따라 지정한 필드만 변경 |
| wait_task | 현재 시도의 실제 외부 의존 대기 |
| resume_task | 해소 관찰을 기록하고 같은 시도 재개 |
| invalidate_task | 실제 정정으로 무효화하며 요구·이력 보존 |
| get_sources | 프로젝트 원문과 정정 계보 조회 |
| get_tasks | 같은 원장의 전체 현재 목록과 TODO 상태 조회 |
| get_task | 현재 상태와 전체 요구·시도·대기 이력 조회 |

TODO는 별도 원장이 아닙니다. `get_tasks`의 tasks는 소유 세션의 전체 현재 목록이며 준비 여부는
같은 프로젝트의 선행 작업 상태에서 계산합니다. 모든 종료 상태와 모든 성공을 구분하고 빈 목록을
완료 근거로 삼지 않습니다. 표시용 복사본이 상태를 축약하거나 표시가 실패해도 원장은 바뀌지 않습니다.

## 스키마·검증·경계

명시적 초기화가 기존 `core_0001`·`core_0002`를 바꾸지 않고 `core_0003`를 적용합니다.
기존 프로젝트·세션·정수 revision·원본 추가 테이블과 미완료 자료를 유지합니다. 실패하면 새 테이블과
revision도 함께 rollback합니다. 원장에 출처나 작업이 있으면 파괴적 downgrade를 거부합니다.
비어 있을 때만 후속 스키마를 제거할 수 있습니다. 일반 조회·수정은 암묵적으로 이전하지 않습니다.

A01/A04/A05/A06/A44/B04를 순수 도메인, 실제 SQLite/Spakky 요청, 독립 프로세스, 동시 시작,
실제 exit 7 실패와 실제 산출물 생성, 개정 후 늦은 결과, 원문 재사용, 범위·순환 거부,
원자적 rollback, 기존 자료 이전 시험으로 검증합니다. 전체 제품 소스의 라인·분기 100%와
제외 0 기준은 기존 필수 검사와 CI에서 그대로 강제합니다.

관찰 참조는 호출자가 실제 관찰한 자료를 기록합니다. 문자열 자체가 원격 실행이나 인간 인증을
입증하지 않습니다. 호스트 관찰 연결, runner, 종료·제3자 평가, 실제 설치·전환은 해당 후속 티켓에서
구현합니다. 이번 검증은 임시 DB이며 실제 사용자 DB나 설치 배포본을 바꾸지 않습니다.

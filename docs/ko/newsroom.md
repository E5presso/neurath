# 프로젝트 Newsroom

[문서 안내](index.md) · [English](../en/newsroom.md)

#145는 프로젝트 안에서 발견을 선택해 읽는 기사 라이브러리와 다섯 CLI 명령을 제공합니다. 같은 프로젝트에서 관찰한 피어만 기사를 조회·발행·정정·논의합니다. `Article`은 개정, 댓글, 전체 본문 열람, 실제 작업 사용과 제목 알림을 소유하며 각각에 별도 저장소를 만들지 않습니다.

## 선택 조회와 원문 보존

| 명령 | 주요 입력 | 실제 효과 |
| --- | --- | --- |
| `newsroom list` | `--peer-id`, `--text`, `--after-id`, `--limit` | 최신 제목·개정·그 개정의 seen·실제 사용 작업의 정정 영향을 조회합니다. 본문을 반환하거나 seen을 기록하지 않습니다. |
| `newsroom read` | `--peer-id`, `--article-id`, `--revision-number`, 선택적 `--task-id` | 지정한 개정의 전체 본문·근거·댓글을 출력한 뒤 그 개정의 열람을 기록합니다. |
| `newsroom publish` | `--peer-id`, `--title`, `--body`, 반복 `--reference` | 최초 원문·근거·작성자와 활성 구독자의 제목 알림을 함께 저장합니다. |
| `newsroom revise` | 발행 입력, `--article-id`, `--expected-revision`, `--reason` | 원 작성자의 기사 개정 번호를 확인한 뒤 이전 본문을 남기고 새 개정을 추가합니다. |
| `newsroom comment` | `--peer-id`, `--article-id`, `--revision-number`, `--body` | 실제 읽은 개정에 댓글을 연결합니다. 옛 개정의 댓글을 새 개정으로 옮기지 않습니다. |

`--body -`는 표준입력 전체를 읽습니다. 제목은 200자, 본문과 댓글은 각각 UTF-8 1 MiB까지 받으며 초과분을 자르지 않고 거절합니다. 근거 참조와 정정 이유는 비어 있을 수 없습니다. 도움말은 DB를 열지 않습니다.

`--expected-revision`은 기사 본문의 개정 번호입니다. 저장소의 정수 `revision`은 댓글·열람·알림 소비를 포함한 모든 변경의 낙관적 잠금 버전이며 둘을 혼동하지 않습니다. 오래된 기대 개정, 다른 작성자 또는 다른 프로젝트의 요청은 전체 트랜잭션을 롤백합니다.

본문 조회 유스케이스는 읽기 전용입니다. CLI는 JSON 직렬화와 전체 stdout 출력이 반환된 뒤 내부 `RecordArticleReadUseCase`를 호출합니다. stdin·직렬화·stdout 실패에는 열람을 기록하지 않으며 수동 seen 명령을 제공하지 않습니다. 출력 뒤 DB 기록이 실패하면 CLI는 실패하고 열람을 성공으로 추정하지 않습니다. 이 receipt는 CLI 출력 경계의 사건이며 모델의 이해·동의·태스크 수락을 입증하지 않습니다.

## 활성 구독자와 훅 제목 알림

#144의 `SubscribePeerUseCase`에서 `topics`에 `newsroom`을 포함한 피어가 제목 알림을 구독합니다. 이 입력은 전체 주제 목록의 교체 계약이므로 유지할 다른 주제도 함께 전달합니다. 구독 해제는 아직 제출하지 않은 기사 알림도 같은 트랜잭션에서 폐기합니다. 재구독으로 옛 알림이 살아나지 않습니다. 일반 구독·협업 업무 CLI는 후속 티켓 범위입니다.

발행·정정 시 같은 프로젝트의 현재 활성 구독자를 수신자로 확정합니다. 비활성 피어에는 알림을 쌓지 않고 외부 메시지 전송이나 provider 실행을 시작하지 않습니다. 수신 가능한 다음 실제 훅에서 기사 ID·현재 개정·제목만 한 번 제출합니다. 그 전에 추가 정정이 있었다면 옛 제목을 재생하지 않습니다. 한 훅은 최대 10개 제목을 제출하며 나머지는 활성 상태가 이어지는 다음 훅에서 처리합니다.

대기·종료·취소가 관찰되거나 직전 피어가 비활성이었다면 남은 알림을 폐기합니다. compact를 제외한 새 SessionStart 연결에서는 종료 관찰이 누락됐더라도 과거 알림을 폐기하며, 연결만으로 실행의 정지를 해제하지 않습니다. 활성 상태는 #142/#144가 저장한 실제 호스트 관찰에 따르며 관찰하지 못한 프로세스 종료를 추정하지 않습니다. 훅 응답 생성은 호스트의 실제 수신·다음 모델 입력 전달과 구분합니다.

## 정정과 실제 사용 작업

단순 본문 열람과 실제 사용은 구분합니다. `newsroom read --task-id`는 출력 전에 같은 프로젝트의 작업 요구 개정을 확인하고, 출력 뒤 그 작업·요구 개정·기사 개정·사용 피어를 연결합니다. 출력 중 작업 요구가 바뀌면 잘못된 사용 연결과 열람 기록을 롤백합니다.

기사가 정정되면 옛 개정을 실제 사용한 작업이 `ArticleSummary.affected_tasks`, `ReadArticleResult.affected_tasks`, `GetTaskResult.article_impacts`에 나타납니다. 작업 상세는 사용 당시 요구 개정과 사용 기사 개정·현재 기사 개정을 반환하므로 관련 없는 작업이나 새로 바뀐 요구에 영향을 임의 전가하지 않습니다. 최신 기사 개정을 같은 작업에 다시 사용하면 그 연결의 미확인 정정 영향이 해소됩니다. 과거 개정을 다시 읽어도 확인한 최신 사용을 되돌리지 않습니다. 단순 열람·댓글·다수 동의는 요구·시도 결과·작업 성공을 바꾸지 않습니다.

## 저장과 검증 경계

`core_0010`은 기존 행을 수정하지 않고 기사와 소유 이력 테이블을 추가합니다. 기사 이력이 있는 downgrade는 삭제를 거부하며 빈 후보 스키마만 되돌릴 수 있습니다. 프레임워크의 기본 CRUD, 선언형 selectin 관계, UUID7, 낙관적 잠금과 `@transactional`을 사용합니다.

`tests/test_newsroom.py`는 실제 스캔·DI·SQLite·CLI로 A20/A21/A56의 Newsroom 범위와 B17을 검증하며 공통 pre-commit·CI 품질 검사에 포함됩니다. stdout·stdin·커밋 실패, 개정 충돌, 교차 프로젝트, 실제 사용 작업 영향, 구독 해제·비활성 중 발행·재접속, 개정별 seen·댓글과 보존형 이전을 확인합니다. A56의 enclave와 학습 항목은 각각의 담당 티켓 범위입니다. fixture·로컬 console 실행은 실제 사용자 설치나 실행 중인 호스트의 활성화를 뜻하지 않습니다. 이 후보를 실설치하지 않습니다.

# Neurath 요구사항과 수용 명세

[문서 안내](index.md) · [English](../en/specification.md)

이 명세는 새 Neurath 설계가 충족해야 할 계약을 정의합니다. 여기에 적힌 요구사항만으로 구현이나 실제 호스트 검증이 통과했다고 판단하지 않습니다. 로컬 후보 버전은 **0.3.0**이며, 이 문서는 공개 릴리스 공지가 아닙니다.

## 목적과 범위

Neurath는 누가 요청하고 소유하는 일인지, 어느 단계에 도달했는지, 무엇을 관찰했는지, 왜 완료할 수 있는지를 기록합니다. MCP 서버 이름은 `neurath` 하나입니다. 프로토콜 응답, 데이터베이스 기록, 호스트 관찰은 각각 실제로 담고 있는 사실만 입증합니다.

새 설계를 적용할 때 기존 저장 데이터와 미완료 작업을 보존해야 합니다. 가져온 작업을 완료된 것처럼 만들기 위해 누락된 권한, 근거, 소유권, 실행 성공을 만들어 내면 안 됩니다.

## 개념

| 개념 | 책임 |
| --- | --- |
| Session | 네이티브 호스트와 행위자를 명시적으로 식별하는 실행 맥락입니다. |
| Source | 요청의 출처와 권한 경계입니다. 출처를 계속 추적할 수 있어야 합니다. |
| Task | 소유자, 리비전, 생명주기 단계, 결과를 갖는 작업 단위입니다. |
| Evidence | 특정 주장을 뒷받침하는 관찰이나 산출물입니다. |
| Delegation | 소유 작업을 위해 다른 행위자에게 맡기는 범위가 정해진 요청입니다. |
| Message | 발신자와 수신자가 기록된 통신입니다. |
| Checkpoint | 특정 작업 리비전에 연결된 영속적인 상태 스냅샷과 메모입니다. |
| Lease | 오래된 보유자를 차단하는 세대 값으로 보호되는 배타적인 작성 권한입니다. |
| Receipt | 식별된 출처에서 특정 사건이나 결정을 수신했다는 기록입니다. |
| Invocation | 요청한 네이티브 동작과 그 실행 결과의 기록입니다. |

도메인은 데이터베이스 어댑터와 독립적으로 표현합니다. 저장소와 작업 단위 경계가 영속화를 제공합니다. SQLAlchemy가 저장을 구현하고 Alembic이 버전별 스키마 마이그레이션을 관리합니다.

## 소유권과 권한

1. 모든 활성 작업에는 식별 가능한 소유자가 있습니다. 위임받은 행위자는 자신의 작업을 보고할 수 있지만, 그로 인해 원래 작업이나 출처의 소유권을 얻지 않습니다.
2. 사람의 결정에는 사람에게 귀속되는 권한 근거가 필요합니다. 에이전트 문장, 다른 작업의 메시지, 성공한 도구 호출, 가져온 상태로 동의를 만들어 내면 안 됩니다.
3. 네이티브 호스트 신원은 호스트 연동에서 검증한 맥락으로 확인해야 합니다. 호출자가 전달한 이름만으로 네이티브 출처를 확정할 수 없습니다.
4. 보고와 수락은 별개의 사건입니다. 권한이 있는 소유자가 작업 요구사항에 따라 수락하거나 거절하기 전까지 위임 결과는 보고 상태로 남습니다.
5. 소유권 변경이나 작업 수락은 명시적으로 감사할 수 있는 전이여야 합니다. 결과를 읽은 부수 효과로 발생하면 안 됩니다.

**수용 기준:** 관계없는 행위자나 오래된 임대 보유자의 변경을 작업 상태 변화 없이 거절합니다. 위임 결과 보고만으로 상위 작업을 완료할 수 없습니다. 사람의 출처 근거가 없으면 사람의 결정이 필요한 조건을 충족하지 못합니다.

## 순서가 있는 실행과 완료

생명주기는 요청 이해, 실행 가능한 계획 수립, 작업 수행, 결과 검사, 완료 결정을 구분해야 합니다. 단계는 호출자가 식별자와 이름을 지정한 순서 목록이며 상태는 대기, 진행, 완료입니다. 작업 상태는 대기, 진행, 입력·결과 대기, 완료, 철회입니다. 구현이 사용하는 용어와 허용 전이를 호출자에게 일관되게 제공해야 합니다. 필수 단계를 통과하려면 선행 조건을 충족해야 하며, 다시 열거나 재시도해도 이전 이력이 보존되어야 합니다.

완료 결정은 현재 작업 리비전과 그 작업에 적용되는 필수 관찰을 참조해야 합니다. 최종 실패, 취소, 성공한 완료는 서로 다른 결과입니다. 프로세스 종료, 빈 대기열, 전체가 종료됐다는 집계 값만으로 작업 성공을 판단할 수 없습니다.

**수용 기준:** 순서를 어긴 전이는 해결 가능한 이유와 함께 실패합니다. 필수 검사 실패는 성공한 완료를 막습니다. 이전 리비전의 체크포인트가 변경된 작업을 자동으로 검증하지 않습니다. 실패한 시도는 기록에 남으며 사용자 목표를 취소하지 않습니다. 재시도는 실패한 이전 시도와 새로운 시도를 모두 보존합니다.

호스트 턴의 중단과 작업 종료는 별개입니다. 첫 Stop 훅은 미완료 작업의 계속 진행을 요청합니다. 호스트의 `stop_hook_active` 표시가 있는 반복 중단에서는 해당 작업을 버리지 않고 제어를 넘겨 장애 보고의 무한 반복을 막습니다.

## 근거의 종류와 한계

근거에는 뒷받침하는 주장, 출처, 해당 작업과 동작을 연결할 수 있는 맥락이 있어야 합니다. 특히 다음을 구분합니다.

- 요청 수신증은 요청을 받았음을 나타내며 실행을 입증하지 않습니다.
- 호출 기록은 동작의 실행 상태를 나타내며 의도한 결과를 자동으로 입증하지 않습니다.
- 검증 관찰은 실제로 측정한 검사를 뒷받침하며 관련 없는 테스트로 대신할 수 없습니다.
- 위임 보고는 결과를 전달하며 소유자의 수락은 별도 결정입니다.
- 네이티브 호스트 관찰은 해당 호스트가 관찰한 사실을 입증하며 도구 발견은 네이티브 실행이 아닙니다.

**수용 기준:** 요구사항이 특정 종류나 출처를 요구하면 다른 종류의 근거로 대체할 수 없습니다. 네이티브 동작을 실행하지 않은 검사는 미검증 상태로 남습니다. 재시작이나 마이그레이션 후에도 저장된 근거의 출처를 추적할 수 있습니다.

설정한 검사에서는 네이티브 실행 전 관찰이 준비한 실행과 실행기를 연결합니다. 실행기는 저장된 인자 목록을 실행하고 실제 하위 프로세스 반환 코드를 근거로 저장합니다. 표시된 도구 출력이나 출력한 성공 문구로 대신할 수 없습니다. 실행 시작만으로 조건을 충족할 수 없으며, 중단된 경우 계속하기 전에 저장된 상태를 확인해야 합니다.

## 동시성과 영속적인 전이

작업 변경은 예상 리비전을 비교한 뒤 갱신하는 방식으로 처리합니다. 전이와 그 전이를 설명하는 필수 기록은 하나의 작업 단위 안에서 원자적으로 커밋합니다. 트랜잭션 실패 후에 근거 기록 없이 완료된 전이가 남으면 안 됩니다.

멱등성 키는 하나의 연산과 입력을 식별합니다. 같은 연산을 반복하면 효과를 중복 생성하지 않고 원래의 영속적인 결과를 반환합니다. 다른 입력으로 같은 키를 재사용하면 명시적으로 실패합니다. 멱등성은 실제로 새로운 동작을 생략하는 허가가 아닙니다.

임대 획득과 해제에는 명시적인 규칙이 적용됩니다. 더 새로운 세대가 발급되면 이전 토큰을 가지고 있어도 이전 보유자의 권한은 무효가 됩니다. 해제하려면 현재 소유자, 세대, 리비전이 일치해야 합니다. 임대는 원장 작성자를 조정하며 호스트 권한을 부여하지 않습니다.

**수용 기준:** 같은 예상 리비전에 대한 경합 변경 두 개가 모두 성공할 수 없습니다. 중복 요청에는 하나의 영속적인 효과만 생깁니다. 멱등성 입력 충돌은 거절합니다. 롤백 후에 부분 전이가 남지 않습니다. 해제되거나 이전 세대인 임대는 보호된 쓰기를 허용하지 않습니다.

## 마이그레이션과 복구

기존 데이터베이스를 적용하기 전에 복구 가능한 복사본과 보존 내역을 남겨야 합니다. 새 운영 스키마로 대응되지 않는 기록을 포함하여 원래 데이터를 보존해야 합니다. 미완료 작업을 식별하고 명시적으로 대응해야 하며, 불확실성을 성공으로 꾸며 해소하지 말고 드러내야 합니다.

SQLAlchemy는 런타임 영속화 계층이며 Alembic이 스키마를 관리합니다. 더 새롭거나 알 수 없는 스키마의 데이터베이스는 다운그레이드하거나 수정하지 않고 명확히 거절해야 합니다. 복구 안내는 보관본과 활성 데이터베이스를 분명하게 식별해야 합니다.

긴급 우회는 운영 데이터베이스가 없거나, 손상됐거나, 잠겼거나, 너무 새로운 경우에도 사용할 수 있어야 합니다. 강제 적용을 끄거나 복구 방법을 설명하는 데 데이터베이스 연결 성공을 요구하면 안 됩니다. 우회는 복구 상태이며 작업 완료나 검증 성공이 아닙니다.

워크트리를 제거하기 전에 변경 사항을 복구 가능한 형태로 보존하고 목록을 남겨야 합니다. 보관본에는 추적 파일, 미추적 파일, 필요한 무시 파일을 포함해야 합니다. 백업을 확인하기 전에는 정리 후 복구가 가능하다고 주장할 수 없습니다.

**수용 기준:** 대표적인 마이그레이션이 원본 데이터를 모두 보존하고 미완료 작업을 명시적으로 집계하며 복구 가능해야 합니다. 마이그레이션을 반복해도 작업이 중복되지 않습니다. 미래 버전 데이터베이스는 거절 후에도 변경되지 않습니다. 의도적으로 사용할 수 없게 만든 데이터베이스에서도 우회가 작동합니다. 검증한 복구 자료로 제거한 워크트리를 재구성할 수 있습니다.

## 설치와 호스트 활성화

다음은 서로 다른 관찰입니다.

| 관찰 | 확인하는 사실 |
| --- | --- |
| 소스 버전 | 체크아웃에 현재 존재하는 코드입니다. |
| 설치 배포본 | 설치 환경에서 사용할 수 있는 패키지나 실행 파일입니다. |
| 프로토콜 가용성 | 특정 프로토콜 기능을 제공하는 서버에 접근할 수 있다는 사실입니다. |
| 네이티브 호스트 활성화 | 실제 호스트가 의도한 연동을 불러와 사용했다는 사실입니다. |

어느 행도 자동으로 다음 행을 입증하지 않습니다. 로컬 테스트 통과는 실제 활성화를 입증하지 않으며 로컬 후보가 공개 배포를 의미하지도 않습니다. 릴리스, 푸시, 배포, 설치, 호스트 재시작에는 각각 기록된 범위와 권한이 필요합니다.

**수용 기준:** 상태 출력은 소스, 설치, 프로토콜, 호스트 관찰을 구분하고 알 수 없는 값을 표시합니다. 실제 활성화 근거에는 호스트와 관찰한 연동이 명시됩니다. 검증 보고는 실제 실행한 테스트와 남은 검사를 구분합니다.

## 문서 수용 기준

영문과 국문 문서는 대응되는 경로와 동등한 범위를 갖습니다. 명시적인 번역 링크 외에 언어 내부 링크는 같은 언어를 유지합니다. 사용자 안내는 자연어 흐름을 사용하고 에이전트·개발자 명령은 기여 안내에 둡니다. 공개 문서에 개인 파일 경로나 관계없는 저장소 식별자를 넣지 않습니다.

기능 안내는 새 구현에 실제로 있는 프로토콜 기능만 나열합니다. 제공하지 않는 기능과 수행하지 않은 검증은 명시합니다. 구현이 미완성이라도 이 명세는 수용 목표로 유지하며, 목표가 이미 충족됐다는 근거로 사용하지 않습니다.

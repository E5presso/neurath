# 작업 목록과 세션 완료

**한국어** · [English](../../en/contributing/task-todo-contract.md)

**등록한 일이 남아 있으면 계속하고, 끝낸 일의 결과는 한 번 기록합니다.**

## 작업 목록

에이전트는 사용자 프롬프트, 티켓, 스펙을 완료 여부를 판단할 수 있는 작업으로 나눕니다.
각 작업은 고유 ID, 목표, 완료 조건, 출처와 상태를 가집니다.
목록은 프로젝트의 SQLite에 저장합니다. 실행 도중 작업을 추가할 수 있으며,
기존 ID, 결과와 의존 관계는 유지합니다.

작업 도구는 네 개입니다.

| 도구 | 역할 |
| --- | --- |
| `task_define` | 목표, 출처와 완료 조건을 가진 작업을 추가합니다. |
| `task_list` | 현재 목록, revision과 TODO 표시 내용을 읽습니다. |
| `task_start` | 작업을 진행 중으로 바꿉니다. |
| `task_resolve` | 결과 설명과 근거 참조를 받아 성공·실패·무효를 기록합니다. |

종결은 인증된 작업 소유자의 결과 보고입니다. 별도 워크플로 종결, 완료 조건별 중복 보고,
추가 태스크 검토자는 요구하지 않습니다. 검사 결과, 소스 위치, PR 또는 사용자 취소 지시를
직접 참조할 수 있습니다. 에이전트는 실제 수행 결과를 설명해야 하며, 하네스는 이를
기록합니다. 기록 자체를 독립 검증이라고 주장하지 않습니다.

상태는 `pending`, `in_progress`, `succeeded`, `failed`, `invalidated`입니다.
마지막 세 상태가 종결입니다. 실패·무효는 실제 결과이며 미완료 작업을 감추는 수단이 아닙니다.
이전 결과 기록은 원래의 보증 수준을 유지합니다.

## 종료와 가시성

작업 목록이 있으면 그 목록이 완료 판단의 기준입니다. Stop은 턴을 닫는 SQLite 트랜잭션에서
최신 목록을 읽고 미완료 작업이 있으면 거부합니다. 따라서 확인과 종료 사이에 추가된 작업을
놓치지 않습니다.

워크플로, 검토, 체크포인트, 학습, TODO 표시 기록은 별도의 완료 심사가 아닙니다.
작업 목록이 없는 기존 세션은 이전 워크플로 규칙을 유지합니다.
옛 워크플로 기록으로 성공한 작업 목록을 만들어내지는 않습니다.

네이티브 TODO 도구는 목록을 보여줍니다. 표시 실패나 지연이 작업의 실제 상태를 바꾸거나
완료를 거부하지 않습니다. 사용 가능한 화면은 최신 상태로 유지합니다.
표시 기록은 실제 제출 결과만 설명하며, 사용할 수 없는 화면을 갱신했다고 하지 않습니다.

## 검사와 파일 수정

호스트의 일반 편집·명령 도구를 사용합니다. 작업 공간 소유권과 네이티브 권한은 유지합니다.
일반 파일 수정에 material 배치 준비·종결은 필요하지 않습니다.
material 및 verification 장부 도구는 공개 MCP 목록에서 제외합니다.
기록된 통합을 위한 기존 호출 호환성은 남깁니다.

등록된 검사는 실행 전에 허용된 정책을 확인하고 소스 fingerprint를 포함한 실제 결과를
반환합니다. 나중에 들어온 질문 때문에 완료된 검사를 권한 오류로 바꾸지 않습니다.
검사는 별도 완료 장부나 Stop 재시도 루프를 자동으로 만들지 않습니다.
변경한 소스에는 저장소가 요구하는 검사를 실행하고, 실패는 그대로 설명합니다.

## 바이패스 전환

`harness_bypass(enabled=true)`로 현재 worktree의 모든 Neurath 훅 제약을 중지하고,
`enabled=false`로 복원합니다. 값을 생략하면 현재 모드를 읽습니다.
이 도구는 일반 훅 결속 없이 동작하므로 바이패스를 다시 끄는 작업이 막히지 않습니다.
호스트 자체 권한과 작업 이력은 바꾸지 않습니다. 다른 Neurath MCP 작업은 여전히
네이티브 결속이 필요하므로 훅을 중지한 동안 사용할 수 없습니다.

도구 결과는 짧은 텍스트 상태와 한 번의 JSON 본문으로 전달합니다.
작업 변경 응답에는 ID·상태·TODO 표시를 담고, 전체 정의는 `task_list`로 조회합니다.
과거 기록 자동 주입은 세션 시작 시 3 KB로 제한하며 이후 질문마다 반복하지 않습니다.

## 저장과 설치

변경되는 작업·런타임 상태는 SQLite에 저장합니다. JSON은 직렬화와 Git으로 관리하는
프로젝트 설정, manifest, 외부 산출물의 형식으로 사용합니다.

이전 상태를 옮길 때 ID, revision과 참조를 트랜잭션으로 보존합니다.
실제 설치를 SQLite로 전환하기 전에 이전 기록 프로세스를 멈춥니다.
이전 파일의 변경 감지는 그 프로세스를 멈추는 일을 대신하지 않습니다.
전환을 확인할 때까지 복구 자료를 보존합니다.

모델 목록은 같은 네이티브 발행자·provider 세션에서 재사용합니다.
명시적 요청이나 오래된 목록이라는 구체적인 근거가 있을 때 갱신합니다.
일괄 메시지는 원자적으로 저장한 뒤 지정 수신자에게 전달합니다.
전달 상태와 작업 완료는 구분합니다.

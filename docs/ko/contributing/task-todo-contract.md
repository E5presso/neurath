# 태스크 결과 기록과 진행 상황 표시

[English](../../en/contributing/task-todo-contract.md)

Neurath의 태스크 원장은 사용자가 요구한 작업을 기록합니다. 호스트 TODO는 그 원장을 표시합니다. 이 계약에 따라 에이전트는 완료 기준을 따로 만들지 않고 진행 상황을 갱신할 수 있습니다.

**목표**는 필요한 결과입니다. **태스크**는 범위가 정해진 목표를 지시 출처와 **완료 조건**에 연결합니다. 완료 조건은 결과를 평가하는 데 필요한 관찰입니다. 호스트 세션의 **루트 에이전트**가 원장을 소유합니다. **receipt**는 특정 이벤트나 보고의 기록이며 태스크 결과 receipt와 TODO 제출 receipt는 의미가 다릅니다. 워크플로의 **phase**는 절차를 구성하고 **리뷰**는 정해진 범위를 평가합니다. 둘 다 태스크 결과를 대신하지 않습니다.

## 구현 단계보다 필요한 동작을 먼저 정의

공통 예시는 사용자 웹앱의 저장 필터가 새로고침 후 사라지는 문제입니다. 태스크는 다시 불러온 뒤 선택값이 유지되고, 화면에 올바르게 표시되며, 결과에도 적용되고, 기존 기본 동작을 검증할 것을 요구할 수 있습니다. 저장·새로고침 재현, 저장 코드 수정, API 계약 리뷰는 이 관찰을 얻기 위한 작업입니다.

태스크 정의는 다음 필드를 가집니다.

| 필드 | 의미 |
| --- | --- |
| `key` | 세션 안에서 이 정의를 식별하는 고정 키 |
| `title` | 진행 상황 표시에 쓰는 짧은 이름 |
| `goal` | 사용자 요구에 기여하는 범위가 정해진 결과 |
| `sources` | `prompt`, `ticket`, `spec`의 출처. 각각 참조와 리비전 포함 |
| `acceptance` | 관찰 가능한 조건 1~32개 |
| `dependencies` | 시작 전에 종료되어야 하는 기존 태스크 ID |

런타임은 기준 생산자와 결과 근거 계약을 추가합니다. 정의의 식별에는 출처 리비전과 완료 조건이 포함됩니다. 같은 정의 키에 다른 내용을 넣으면 거부합니다. 새로 필요한 작업은 새 정의로 추가하며 종료된 기록은 변경하지 않습니다.

## 실제 지시를 기준으로 태스크 등록

태스크 변경에는 검증된 루트, 활성 전경 턴, 현재 호스트의 호출 허용 근거가 필요합니다. 최초 등록에는 현재 사용자 지시 receipt 또는 같은 세션에 남아 있는 명시적인 지시 출처가 필요합니다. 티켓·명세 참조는 호스트 지시 출처를 보충할 수 있습니다.

태스크가 이미 있는 상태에서 새 입력이 오면 추가 작업의 출처로 원래 요구 또는 명시적인 새 요청을 선택해야 합니다. 상태 질문을 암묵적으로 새 범위의 출처로 삼는 경우는 거부합니다. 동료 메시지로 재개한 턴은 새 사용자 receipt를 만들지 않고 검증된 같은 세션의 기존 지시 출처를 사용할 수 있습니다.

`task_list`는 `current_prompt_source`와 각 태스크의 저장된 출처를 반환합니다. 명시적 출처가 필요한 호출에는 관찰한 참조와 리비전을 사용합니다. 지시 식별자를 만들어 넣지 않습니다.

## 상태 전이와 리비전

| 상태 | 의미 | 종료 상태인가? |
| --- | --- | --- |
| `pending` | 정의했으나 시작하지 않음 | 아니요 |
| `in_progress` | 실행할 작업으로 선택함 | 아니요 |
| `succeeded` | 소유자가 완료 조건 충족을 보고함 | 예 |
| `failed` | 소유자가 실제 실패 결과를 보고함 | 예 |
| `invalidated` | 더 이상 적용되지 않는 이유를 소유자가 보고함 | 예 |

`task_start`는 대기 중 태스크만 시작합니다. 모든 의존 태스크가 종료 상태여야 합니다. 성공 결과를 기록할 때도 의존 태스크 종료가 필요하지만 실패·무효 결과는 그 전에도 남길 수 있습니다. 런타임은 종료 여부를 검사하므로 모든 의존 태스크가 성공했다고 가정하지 않고 실패 결과의 의미를 평가해야 합니다.

종료 전 태스크에는 결과를 기록할 수 있으므로 대기 → 진행 → 성공 경로만 허용하는 모델은 아닙니다. 변경마다 정확한 목록 리비전을 비교하고 start/resolve에서는 태스크 리비전도 비교합니다. 오래된 리비전은 최신 상태를 조용히 바꾸는 대신 충돌을 반환합니다.

성공한 변경의 반환값 또는 새 `task_list`에서 리비전을 가져옵니다. 고정 작업 키는 동일한 재시도를 지원합니다. 같은 키로 내용을 바꾸면 계약 오류입니다.

## 결과 보고와 보장 수준

`task_resolve`에는 ID·리비전과 함께 `status`, `references`, `summary`가 필요합니다. 서비스는 태스크 정의 다이제스트, 소유자, 상태, 요약, 참조를 담은 내용 주소 기반 `neurath.task-result.v1` 보고를 만듭니다. 목록을 읽을 때 artifact의 존재·무결성과 동일 태스크 연결을 검사합니다.

보고의 보장 수준은 `agent-report`입니다. 런타임은 출처와 무결성을 보존하며 앱이 이제 필터를 유지하는지를 독립적으로 증명하지 않습니다. 소유자는 관찰을 완료 조건에 연결하고 근거의 한계를 설명해야 합니다.

결과를 기록하기 전에 아직 다른 태스크에서 다루지 않는 필요한 후속 작업을 등록합니다. 실패 보고에는 충족하지 못한 조건, 실제 장애 요인, 다음 행동이 필요합니다. 경과 시간, 곁가지 질문, Stop 거부는 실패나 취소를 입증하지 않습니다. 실패 기록을 유지하면서 새 태스크로 필요한 작업을 이어갈 수 있습니다.

목록은 세 가지 요약을 제공합니다.

| 필드 | 해석 |
| --- | --- |
| `all_terminal` | 목록이 비어 있지 않고 모든 태스크가 종료 상태임 |
| `all_succeeded` | 목록이 비어 있지 않고 모든 태스크가 성공을 보고함 |
| `unsuccessful_task_ids` | `failed` 또는 `invalidated`인 태스크 목록 |

나중에 성공한 후속 작업이 이전 실패를 지우지는 않습니다. 전체 결과를 보고할 때 이후 근거가 남아 있던 요구를 어떻게 충족했는지 설명합니다.

## 전체 목록을 호스트에 표시

`task_list`와 변경 결과는 `todo_projection`, `native_todo`를 반환합니다. `native_todo`에는 호스트 도구와 정확한 인자가 들어 있습니다. Codex는 `update_plan`, Claude Code는 `TodoWrite`를 사용합니다. 현재 행 전체를 포함한 반환값을 그대로 사용합니다.

`native_todo.display_status`는 실제 호스트 제출 기록에 따라 `pending`, `current`, `empty`를 표시합니다. 변경된 원장이 화면에 반영되지 않았다면 다음 일반 네이티브 도구 호출에서 해당 리비전의 정확한 표시 인자를 한 번 안내합니다. 별도 완료 조건을 추가하지는 않습니다. 독립적으로 확인되는 작업은 결과를 얻는 즉시 원장과 TODO에 반영하고, 진행률은 그 목록에서 계산합니다. 복구 바이패스 중에도 호스트 TODO를 유지하고 복구 뒤 원장과 맞춥니다.

Codex 0.152.0부터 `update_plan`은 명시적으로 켜야 합니다. 프로젝트와 사용자 설정에 기존 선택이 없으면 설치기가 `tools.update_plan.enabled = true`를 추가합니다. 현재 Claude Code는 Task 도구군을 기본으로 사용하며, 일부 버전의 새 모델에서는 작업 도구 자체의 활성화도 필요합니다. Neurath는 자신의 태스크 원장을 표시하기 위해 공식 지원되는 전체 목록 방식의 `TodoWrite`를 사용합니다. 미설정 항목에만 프로젝트 설정으로 `CLAUDE_CODE_ENABLE_TODO_TOOLS=1`, `CLAUDE_CODE_ENABLE_TASKS=0`을 넣습니다. 프로젝트·사용자 설정·환경변수의 명시적 선택은 보존합니다. 기존 선택이 다른 작업 인터페이스나 비활성화를 가리키면 `TodoWrite`를 사용할 수 있다고 주장하지 않습니다. 도구 노출 설정을 바꾼 뒤 호스트를 다시 불러오고 실제 네이티브 호출을 확인합니다.

두 호스트의 화면 상태는 원장보다 적습니다. 모든 종료 태스크를 호스트의 `completed`로 매핑하고 실제 결과를 본문에 표시합니다. 진행 중 태스크 중 첫 번째만 호스트의 `in_progress`를 사용하며 다른 진행 태스크도 본문에서 상태를 확인할 수 있습니다. 각 행에는 태스크 ID와 목록 리비전이 들어갑니다.

따라서 완료 표시가 `Failed`나 `Invalidated`를 나타낼 수도 있습니다. 성공으로 설명하기 전에 행의 문구나 원장의 실제 결과를 읽습니다.

반환값에 목록이 있다고 화면에 자동으로 표시되는 것은 아닙니다. MCP의 텍스트 응답과 `native_todo.display_instruction`은 바뀐 목록을 정확한 인자로 네이티브 도구에 전달해 즉시 표시하도록 안내합니다. 현재 도구 목록에 해당 도구가 없으면 빠진 호스트 기능을 명시하고 표시 요구를 유지합니다. 인라인 체크리스트, 파일 패널, 합성 이벤트는 네이티브 TODO 표시를 대신하지 않으며 제출 성공으로 기록하지 않습니다. 같은 표시를 반복하거나 별도 태스크 원장을 만들지 않습니다.

## 제출 관찰과 완료 기준을 구분

호스트 `PreToolUse`는 제출하려는 모든 행을 현재 원장의 표시값과 비교한 뒤 준비된 호출을 기록합니다. 짝이 되는 결과도 그 요청과 일치해야 합니다. Codex는 정확한 기준 행 외에 텍스트 `explanation`을 함께 넣을 수 있습니다.

제출 receipt 상태는 `submitted`, `current`, `stale`, `failed`입니다. `current`에는 성공한 호스트 결과와 변경되지 않은 표시 다이제스트가 필요합니다. 성공했더라도 결과를 기록하기 전에 태스크 목록이 바뀌면 stale이 됩니다. 기능 관찰 상태는 `unobserved`, `observed-supported`, `unsupported-runtime`입니다.

receipt 범위는 `native-tool-submission`입니다. 태스크 성공이나 앱의 화면 표시를 입증하지 않습니다. 표시가 오래됐거나 실패해도 원장을 다시 쓰거나 중복된 일반 태스크 완료 게이트가 될 수 없습니다. 해당 호스트 기능을 사용할 수 있다면 현재 태스크 상태에서 표시를 갱신합니다.

## 종료와 이전 과정에서 작업 보존

최신 원장 검사와 루트 턴 종료는 하나의 트랜잭션을 사용합니다. 따라서 앞선 조회 이후 새로 추가된 태스크를 놓치고 종료할 수 없습니다. 미완료 태스크는 커널의 루트 턴 종료를 거부합니다. 호스트 Stop 어댑터는 모델 재호출을 요청하지 않고 그 거부를 진단으로 전달합니다. 답변 반환은 태스크 완료 처리가 아닙니다. 등록된 원장이 태스크 완료의 기준이며 체크포인트·학습·TODO·독립 리뷰가 일반 작업의 추가 완료 투표가 되지 않습니다. 명시적으로 선택한 phase나 리뷰 계약에는 자체 요구가 남습니다.

메모리 adopt가 반영되면 원본 결과를 보존하고 `superseded_by`를 기록합니다. 이전된 원본에는 태스크 변경을 허용하지 않고 받는 세션이 자신의 호스트 신원으로 미완료 작업을 이어갑니다. 이전은 원본의 미완료 기록을 성공으로 바꾸지 않습니다.

인자 예시는 [태스크 도구](task-tools.md), 목표 알림과 정상 Stop은 [실행 생명주기](runtime-lifecycle.md)를 참고하세요. 소스는 `src/neurath/_assets/scripts/agent_harness/`의 `task_ledger.py`, `task_service.py`, `task_todo.py`와 `src/neurath/runtime/`의 호스트 어댑터에 있습니다.

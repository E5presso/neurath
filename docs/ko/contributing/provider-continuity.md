# 새 세션이 미완료 작업을 받아 이어가기

[English](../../en/contributing/provider-continuity.md) · [기여자 시작 안내](index.md)

사용자가 원하는 결과를 얻기 전에 코딩 세션이 끝날 수 있습니다. 가상의 웹앱에서 저장 API가 필터를 보존한다는 사실까지 확인했지만, 불러오기 경로의 수정과 검증은 남아 있을 수 있습니다. 다음 에이전트에는 조사 내용뿐 아니라 계속 수정할 유효한 소유권도 필요합니다. Neurath의 `memory_pull`은 수신 세션이 보존된 작업을 가져와 살펴보고, 조건이 맞으면 미완료 작업을 인수하게 합니다.

## 무엇을 이어받는가

**컨텍스트(context)**는 현재 판단을 위해 에이전트에게 제공되는 정보입니다. **기억(memory)**은 세션을 넘어 보존된 출처 있는 프로젝트 정보입니다. **세션(session)**은 그 기록을 만든 네이티브 호스트의 대화 실행입니다. **체크포인트(checkpoint)**는 에이전트가 결정과 다음 행동을 적은 인계 요약입니다. **트랜스크립트(transcript)**는 메시지와 도구 이벤트를 담은 호스트의 JSONL 기록입니다. **pull**은 수신자가 다른 세션의 보존된 작업을 명시적으로 조회하는 동작이며, 소유권을 바꾸는 인수(adopt)는 그 뒤의 별도 단계입니다.

수신자는 공유 SQLite의 원본 작업·프로세스 상태, 저장된 기억, 통신 기록, 정확히 등록된 네이티브 JSONL을 읽습니다. 원본이 최종 체크포인트를 만들거나 인계 내용을 밀어 보낼 필요는 없습니다. 정상적으로 마무리하지 못했어도 이미 저장된 결정은 남아 있습니다. 트랜스크립트에서 추가로 보이는 작업을 복구할 수 있지만, 한 번도 저장되지 않은 provider 내용까지 복구한다고 보장할 수는 없습니다.

공유 범위는 로컬 Git common directory입니다. 연결된 워크트리와 같은 프로젝트의 Codex·Claude 세션은 기록을 공유할 수 있지만 독립 복제본과 다른 컴퓨터는 자동 동기화되지 않습니다. 인수하려는 수신자는 원본 워크트리의 확인된 네이티브 루트여야 합니다. 자신의 네이티브 설정과 신원은 그대로 유지합니다.

앱 소속은 별도 진단입니다. `session_status.app_project`는 앱이 소유한 로컬 기록에서 `thread-project-assignments`로 현재 세션의 배정을 찾고, `local-projects`로 일치하는 로컬 프로젝트를 확인하며, `projectless-thread-ids`로 명시적으로 프로젝트가 없는 세션을 구분합니다. 읽기는 최대 16 MiB로 제한하고 관련 소속 필드만 반환합니다. 앱 상태 변경, 원격 UI 관측, 권한 부여, 작업 인수는 수행하지 않습니다. [소스의 조회 구현](../../../src/neurath/hosts/app_projects.py)을 참고하세요.

## 소유권을 바꾸기 전에 정확한 원본 살펴보기

1. `memory_pull(action="list")`로 후보를 찾습니다. 기본 20개, 최대 50개입니다.
2. 관측된 `source_host`, `source_session`을 선택하고 안정적인 키로 `preview`를 호출합니다. 익숙한 제목만 보고 세션을 추정하지 않습니다.
3. 반환된 원본 정보, 작업 상태, 네이티브 관측, 스냅샷 `reference`를 확인합니다. 미리보기가 제한되었다면 나머지를 읽습니다.
4. 원래 사용자 수락 조건, 미완료 작업, 결과가 불명확한 실행, 원본의 제한을 대조한 뒤 인수 여부를 판단합니다.

이 동작의 권한 표시는 `authority="reference-only"`입니다. 미리보기는 수신자 소유의 불변 스냅샷을 만들지만 리스를 옮기거나 과거 작업을 현재 소유자의 작업으로 바꾸지 않습니다. 트랜스크립트는 등록된 원본 JSONL 또는 Codex가 그 파일을 정확히 옮긴 보관 위치에서만 읽습니다. 비공개 추론과 알려진 자격 증명은 제외하고 위치, digest, 출처, 생략 안내를 유지합니다. 여러 대화를 폭넓게 훑는 검색은 아닙니다.

## 큰 스냅샷을 읽을 때의 범위

미리보기와 읽기 응답은 모두 8,000 UTF-8 바이트 이내입니다. `read` 조각은 최대 3,000자이며 바이트 제한을 맞추기 위해 더 짧아질 수 있습니다. `offset`과 `next_offset`의 단위는 문자입니다. `before_offset`이 사용하는 트랜스크립트의 바이트 위치와 다릅니다.

```json
{
  "action": "read",
  "reference": "<preview가 반환한 reference>",
  "offset": 0
}
```

반환된 `next_offset`을 따라가 `null`이 될 때까지 읽습니다. `json_fragment`는 저장된 스냅샷 문서의 일부라서 한 페이지가 독립적인 유효 JSON일 필요는 없습니다. 제한된 미리보기에는 올바른 참조를 담은 `read_remaining`이 있습니다. 이를 모두 읽으면 저장된 스냅샷 전체를 얻는 것이며 생략된 원본 자료가 새로 복구되는 것은 아닙니다.

미리보기의 기억 페이지는 최대 64개 항목을 담습니다. 항목 내용은 4,096자로 제한되며 잘렸다면 표시됩니다. 더 이른 기억과 트랜스크립트 부분은 `memory_before`, `before_offset`을 사용한 새 미리보기 요청으로 선택합니다. `scan_transcript=false`는 트랜스크립트 본문 포함을 끌 뿐 네이티브 신원, 원본 상태, 미결 실행 검사를 끄지 않습니다.

## 원본 실행이 멈추고 정리된 뒤 인수하기

인수하려면 원본이 정지 상태여야 합니다. 등록된 트랜스크립트가 완결되어 있고, 결과 대기 중인 도구·프로세스가 없으며, 네이티브 턴이 닫혔거나 저널에 연결 종료가 기록되어야 합니다. 네이티브 자식, provider 실행, 동료 과업도 정리되어야 합니다. 셸 프로세스가 실행 핸들만 반환하고 이후 종료가 관측되지 않았다면, 원본이 더 이상 말하지 않아도 미결 실행입니다.

수신자의 `task_list`를 읽고 반환된 revision으로 다음을 호출합니다.

```json
{
  "action": "adopt",
  "reference": "<검토한 불변 미리보기 reference>",
  "expected_revision": 0,
  "key": "saved-filter-adopt-1"
}
```

여기서 `0`은 설명용이며 실제 수신자 revision으로 바꿔야 합니다. 미리보기와 다른 키를 사용합니다. 인수는 원본 작업·프로세스 상태, 트랜스크립트 관측, 통신, 리스가 여전히 미리보기와 같은지 확인하고 현재 수신자 작업 revision도 검사합니다. 기반이 달라졌다면 새 미리보기로 다시 대조해야 하며 강제 인수는 없습니다.

하나의 트랜잭션에서 미완료 작업에 수신자 소유 ID를 만들고, 의존성을 다시 연결하고, 원본 소유 워크트리 리스를 이전하고, 원본에 인계된 세션이라는 표시를 남깁니다. 미완료 작업은 최대 64개까지 인수할 수 있습니다. 원본의 완료 이력은 원본 출처로 보존됩니다. 일부만 가져오다 실패하면 모든 영역이 롤백되어야 합니다. 반환된 claim이 현재 claim이며 오래된 fencing token은 더 이상 쓰기를 허용하지 않습니다.

인계된 원본은 수신자가 나중에 리스를 해제해도 작업을 다시 변경하거나 워크트리를 재취득할 수 없습니다. 이어갈 책임을 이전하는 것이지 활성 소유자를 둘로 복제하는 것이 아닙니다. 권한을 복사하지 않으며 이전 시도의 실패를 사용자의 요구 취소로 바꾸지도 않습니다.

## 도구가 알려 준 실제 장애 해결하기

| 조건 | 영향과 복구 |
| --- | --- |
| 원본이 활성 상태이거나 실행이 미결 | 미리보기는 참고할 수 있지만 실제 실행이 정리되기 전에는 인수할 수 없습니다. |
| 원본 상태·트랜스크립트·리스 변경 | 새 스냅샷을 만들고 다시 검토합니다. |
| 수신자 revision 변경 | 수신자 원장을 다시 읽고 대조한 뒤 새 인수 호출을 합니다. |
| 다른 워크트리 또는 다른 소유자의 claim | 원본 워크트리에서 유효한 소유권 절차를 따릅니다. claim을 임의로 만들지 않습니다. |
| 다른 수신자의 스냅샷 | 현재 수신자의 참조로 읽거나 인수할 수 없습니다. |
| 이전 워크플로에 작업 인수 계약이 없음 | 참고 조회는 가능하지만 작업 인수는 성립하지 않습니다. |
| 이전 프로세스 결과 불명 | 미확인 상태를 유지하고 승인된 실행 소유자를 통해 실제 결과를 정리합니다. |

인수 후에는 현재 작업 revision으로 반환된 미완료 작업을 선택하고, 불러오기 수정과 검증을 마친 뒤 원래 수락 조건에 따라 결과를 기록합니다. 인수한 리스는 승인된 시점에 실제 반환값으로 해제합니다. 기억을 읽거나 가져오거나 요약했다는 사실은 필터가 새로고침 뒤 유지된다는 증거가 아닙니다.

## 구현의 근거 범위

[src/neurath/memory/migration.py](../../../src/neurath/memory/migration.py)는 스냅샷, 응답 제한, 원자적 인수를 구현하고 `migration_transcript.py`는 네이티브 트랜스크립트 복구 범위를 제한합니다. 원본 변경과 claim 차단은 [src/neurath/_assets/scripts/agent_harness/task_service.py](../../../src/neurath/_assets/scripts/agent_harness/task_service.py), `worktree_registry.py`에도 있습니다.

[tests/test_memory_pull.py](../../../tests/test_memory_pull.py)는 원본 불변 조건, 작업·리스 이전, 롤백, 의존성 재연결, 계속 유지되는 원본 차단을 검사합니다. [tests/test_memory_pull_mcp.py](../../../tests/test_memory_pull_mcp.py)는 원본 체크포인트 없이 이루어지는 개별 네이티브 바인딩 pull 사례를, [tests/test_migration_transcript.py](../../../tests/test_migration_transcript.py)는 트랜스크립트 경계를 다룹니다. 양방향 네이티브 개별 사례와 과금 한도 소진을 모사한 사례는 각각의 제한된 증거입니다. 모든 운영 환경을 입증하거나 모든 provider 중단에서 완전한 의미 연속성을 보장하지는 않습니다.
## 명명 도구 입력 참조

아래는 현재 명명 도구의 입력 계약입니다. 중첩 필드의 필수 조건은 상위 객체나 배열 항목을 제공했을 때 적용됩니다. 스키마 통과는 첫 검사일 뿐이며 네이티브 신원, 소유권, 출처, revision, 각 동작의 전제 조건도 적용됩니다. `_neurath_binding`은 호스트가 제공하므로 임의로 만들지 않습니다.

모든 응답에는 `ok`, `operation`이 있습니다. 성공 호출에는 표준 `result`, 실패에는 `error.code`, `error.message`, `error.state`, `error.retryable`, `error.next_action`이 포함됩니다. `ok`는 해당 동작의 성공만 뜻하며 사용자 목표 달성을 뜻하지 않습니다. 후속 호출에는 반환된 ID와 revision을 유지합니다.

### `memory_pull`

| 필드 | 필수 여부·기본값 | 형식·제한 |
| --- | --- | --- |
| `action` | 선택; 기본 `"list"` | 문자열: `"list"`, `"preview"`, `"read"`, `"adopt"` |
| `source_host` | 선택; 기본 `"codex"` | 문자열: `"codex"`, `"claude-code"` |
| `source_session` | 선택; 기본 `""` | 문자열; 0–256 자 |
| `reference` | 선택; 기본 `""` | 문자열; 0–71 자 |
| `key` | 선택; 기본 `""` | 문자열; 0–512 자 |
| `expected_revision` | 선택; 기본 `0` | 정수; 0–9007199254740991 |
| `scan_transcript` | 선택; 기본 `true` | 불리언 |
| `limit` | 선택; 기본 `20` | 정수; 1–50 |
| `before_offset` | 선택; 기본 `0` | 정수; 0–9007199254740991 |
| `offset` | 선택; 기본 `0` | 정수; 0–9007199254740991 |
| `memory_before` | 선택; 기본 `0` | 정수; 0–9007199254740991 |

# 다른 제공자에게 중단된 작업 넘기기

[English](../../en/contributing/provider-continuity.md)

작업을 끝내기 전에 한 제공자가 멈추면, 일을 받는 세션이 저장된 맥락을 가져와 남은 작업을 이어받을 수 있습니다. `memory_pull`은 공유 SQLite의 기록을 읽고, 필요한 경우 정확히 등록된 네이티브 대화 기록을 함께 확인합니다. 원본의 마지막 인계 기록이나 맥락 전송은 필요하지 않습니다.

수신자는 원래 작업이 진행되던 worktree에서 자신의 네이티브 루트로 실행합니다. 먼저 내용을 미리 읽고, 원본 실행이 정리된 뒤에만 작업을 승계합니다. 일반 사용 요청은 [기록된 결정에서 작업 이어가기](../usage/memory.md)를 참고하세요.

## 실행 설정과 작업 소유권 구분하기

독립 `provider_run`의 기본값은 `inherit`입니다. 일을 받는 제공자의 기존 기본값·훅·도구 규칙을 유지하려면 `target-native`를 명시적으로 승인하고 계획과 실행에 같은 mode를 사용합니다. 모델 선택은 계획의 별도 필드입니다. 생성된 세션의 실제 모델·정책·활성화·소유권도 확인해야 합니다.

`memory_pull`은 수신자의 설정을 바꾸거나 원본의 자격 증명을 복사하지 않습니다. 미완료 작업과 worktree 소유권은 승계 단계에서 넘깁니다. `target-native`를 선택하는 것만으로는 어느 것도 이전되지 않습니다. 세션 생성과 정책 확인은 [모델 계획](model-planning-mcp.md)과 [제공자 실행](provider-transports.md)에 설명합니다.

## 원본을 찾아 미리 확인하기

같은 Git 프로젝트에서 원본 세션 후보를 조회합니다.

```json
{"tool":"memory_pull","arguments":{"action":"list","limit":20}}
```

결과에서 정확한 원본 호스트와 세션을 선택합니다. `source_host`는 `codex` 또는 `claude-code`이며, `limit` 기본값은 20, 최대값은 50입니다. 아래 식별자는 실제 반환값을 넣을 자리이며 임의로 만들 신원이 아닙니다.

```json
{"tool":"memory_pull","arguments":{"action":"preview","source_host":"codex","source_session":"SOURCE_SESSION_FROM_LIST","key":"continuity-preview-1"}}
```

미리보기는 `reference`와 원본의 작업·기억·통신·대화 기록 관찰을 반환합니다. 원본 원장, 프로세스, 기억, 통신 상태, 등록된 대화 기록의 관찰값, worktree 소유권 기준을 수신자에게 속한 변경 불가능한 스냅샷에 연결합니다. 내용을 읽어도 소유권은 이전되지 않습니다. 아직 승계할 수 없는 원본을 진단하는 데도 미리보기를 사용할 수 있습니다.

## 저장된 맥락을 나누어 읽기

미리보기 응답은 8,000 UTF-8 바이트 이내로 제한합니다. 수신자는 소유권을 받기 전에도 셸로 호스트의 도구 출력 파일을 열지 않고 승계에 필요한 reference를 얻을 수 있습니다. 전체 스냅샷은 그대로 보존하며 `read`로 나누어 읽습니다.

```json
{"tool":"memory_pull","arguments":{"action":"read","reference":"RETURNED_PREVIEW_REFERENCE","offset":0}}
```

`json_fragment`, `next_offset`, `total_characters`가 반환됩니다. offset은 바이트가 아닌 문자 위치입니다. 한 조각은 최대 3,000문자이며 전체 응답이 8,000 UTF-8 바이트를 넘으면 더 짧아집니다. 반환된 `next_offset`으로 저장된 스냅샷을 끝까지 읽습니다.

| 입력 | 목적 |
| --- | --- |
| `before_offset` | 등록된 JSONL의 이전 페이지를 요청하며, 반환된 `earlier_offset`을 다음 미리보기에 사용 |
| `memory_before` | 반환된 커서로 SQLite 기억의 이전 페이지 요청 |
| `scan_transcript:false` | 대화 내용만 제외하며, 네이티브 신원과 미종결 실행 검사는 유지 |

기억 페이지는 최대 64건이며, 개별 기억 내용은 4,096문자로 제한하고 잘리면 표시합니다. 큰 대화 레코드는 내용 생략 표시와 원본 위치·해시로 나타낼 수 있습니다. 저장된 스냅샷 전체를 읽어도 저장 전에 생략된 내용까지 재구성되지는 않습니다.

대화 복구는 등록된 JSONL 또는 정확한 Codex 보관 위치 이동만 확인합니다. 무관한 대화를 전수 탐색하지 않습니다. 비공개 추론과 인식된 자격 증명을 제외하고 원본 위치·해시를 유지하며, 가져온 글은 참고 자료로 다룹니다. 저장된 성공 주장만으로 관찰하지 못한 도구 결과를 증명할 수는 없습니다. 제공자가 저장하지 않은 내용은 복구를 보장할 수 없습니다.

## 원본 실행이 정리된 뒤 승계하기

실제로 반환된 미리보기 `reference`와 수신자 작업 목록의 현재 리비전을 사용합니다. 예제의 리비전 `0`은 관찰한 수신자 목록 리비전이 0인 경우에만 해당합니다.

```json
{"tool":"memory_pull","arguments":{"action":"adopt","reference":"RETURNED_PREVIEW_REFERENCE","expected_revision":0,"key":"continuity-adopt-1"}}
```

미리보기와 승계에는 서로 다른 안정된 key를 사용합니다. 같은 key는 동일한 작업과 변경 없는 입력을 다시 조회할 때만 재사용합니다. 승계는 원본 실행의 정지, 태스크·프로세스 상태, 대화 기록 관찰, 소유권을 다시 확인합니다. 원본이 달라졌으면 새 미리보기를 만들며 강제로 소유권을 가져오지 않습니다.

도구나 프로세스의 결과가 확인되지 않았거나, 활성 자식·미종결 provider 실행·동료 배정이 남아 있으면 승계를 막습니다. 이 조건이 해결되지 않았을 때는 미리보기와 사유를 보존합니다. 강제 인수 입력은 제공하지 않습니다.

성공하면 `status:"adopted"`와 `task_mapping`, 가져온 `tasks`, 새 `claim`, `source_terminal_tasks`를 반환합니다. 최대 64개의 미완료 작업에 수신자 소유의 새 ID를 부여하고 의존 관계를 다시 연결합니다. 종결 이력과 근거의 출처는 원본으로 남습니다.

작업 가져오기, 소유권 이전, 원본 세션의 승계 표시는 원자적으로 저장합니다. 승계된 원본은 수신자가 자신의 소유권을 해제한 뒤에도 다시 쓰거나 worktree를 되찾을 수 없습니다. 두 세션이 같은 쓰기를 이어가는 일을 막기 위한 처리입니다. 수신자는 원래 목표와 완료 조건을 유지합니다. 제공자가 바뀌어도 조건을 낮추거나 과거 시도의 실패를 사용자 취소로 바꾸지 않습니다.

## 아직 충족되지 않은 조건 확인하기

| 관찰한 상태 | 다음 행동 |
| --- | --- |
| 원본에 미종결 실행이 남음 | 실제 도구·자식·provider·동료 작업의 결과를 확인한 뒤 승계 |
| 미리보기 후 원본 상태나 대화 기록이 바뀜 | 새 미리보기에서 변경된 기준 확인 |
| 미리보기 응답이 축약됨 | 반환된 참조와 커서로 저장된 스냅샷 읽기 |
| 원래 데이터가 저장되지 않음 | 빠진 맥락을 밝히고 완전한 재구성을 주장하지 않음 |
| 네이티브 프로젝트 메타데이터가 바뀜 | 앱 프로젝트 소속을 별도로 확인; CLI 생성 Codex 세션의 실제 앱 연결은 미해결 |
| 파일을 업데이트했지만 오래된 MCP 연결이 실행 중임 | 해당 연결에 재접속해 활성 도구와 동작 확인 |

`provider_recover`는 발행자가 기록한 provider 실행을 복원합니다. `memory_pull`은 다른 네이티브 수신자가 저장된 맥락과 작업을 승계하는 기능이며 원본을 가장하거나 재개하지 않습니다. 기존 [프로젝트 기억과 학습](memory-reference.md)은 계속 사용하며, 가져온 복구 경험도 활성 지침이 되려면 기존 검증 절차를 거쳐야 합니다.

## 구현과 검증 범위

[승계 구현](../../../src/neurath/memory/migration.py)은 스냅샷과 원자적 이전을, [대화 복구](../../../src/neurath/memory/migration_transcript.py)는 등록된 기록의 조회와 제한된 추출을 담당합니다. 입력은 [도구 스키마](../../../src/neurath/runtime/task_schema.py), target-native 설정은 [provider 정책](../../../src/neurath/runtime/provider_policy.py)에 있습니다.

[승계 테스트](../../../tests/test_memory_pull.py), [MCP 테스트](../../../tests/test_memory_pull_mcp.py), [대화 테스트](../../../tests/test_migration_transcript.py), [대상 정책 테스트](../../../tests/test_target_native_policy.py)는 결정적으로 확인할 수 있는 동작을 다룹니다. 네이티브 검증은 양방향 pull의 승계·작업 종결·소유권 해제·기존 파일 보존까지 확인합니다. 사용량 한도 소진을 모사한 검증은 실제 결제 한도 소진이나 보편적인 production 준비를 입증하지는 않습니다. 위임·목표 환기·원본 재개 차단 근거는 각각 실제 확인한 후보에 연결해 유지합니다. 이 근거의 범위는 [검증 가이드](validation.md)를 참고하세요. 의미의 완전한 복원이나 제공자가 저장하지 않은 데이터의 복구를 보장하는 검사는 아닙니다.

상태: 확정된 제품 계약. 구현 전환과 실제 호스트 수용 검증은 아직 남아 있습니다.
이 문서는 구현해야 할 동작을 정의합니다. 기존 코드와 이전 테스트 통과만으로 이 요구가
구현됐다고 판단하지 않습니다. 모델 선택과 에이전트용 MCP 표면은
[모델 계획과 MCP 운용](model-planning-mcp.md)에서 별도로 정의합니다.

## 목표와 결정

세션, 네이티브 서브에이전트, 프로바이더 런타임이 사용자의 메시지 중계나 명령 실행 없이
협업합니다. 이미 부여된 작업 권한을 반복해서 승인받지 않습니다. 최초 루트는 Codex와
Claude 모두 가능합니다. 실행 프로세스가 살아 있으면 사용자가 보고 있지 않아도 승인된
작업을 수행합니다.

| ID | 확정 결정 | 구현에 적용할 결과 |
| --- | --- | --- |
| D01 | 최초 루트를 특정 프로바이더로 고정하지 않음 | Codex→Codex, Codex→Claude, Claude→Codex, Claude→Claude 모두 검증 |
| D02 | 새 실행은 생성자의 실제 권한 정책을 승계 | 실제 설정 확인, 의미 대응, 적용 확인 후 작업 전달 |
| D03 | 사용자 관측은 하네스 수명 관리의 범위 밖 | 앱 소속, 대시보드, 원격 화면 연결, 사용자 접속 여부를 실행 게이트로 사용하지 않음 |
| D04 | 각 프로바이더 인스턴스가 내부 세션·서브에이전트를 소유 | 내부 통신은 해당 프로바이더, 인스턴스 간 통신은 Neurath가 담당 |
| D05 | 전달 계약은 at-least-once이며 중복보다 누락 방지가 중요 | ACK 없는 수락 메시지를 보존하고 같은 키로 재전달 |
| D06 | 수신 LLM이 키로 중복을 식별할 수 있음 | 안정적인 식별자와 동일 내용을 제공하되 작업 효과의 exactly-once는 주장하지 않음 |
| D07 | 협업은 이벤트로 구동 | 완료 감시 폴링, heartbeat 자동화, 별도 LLM 수신 세션 금지 |
| D08 | 작업 수명과 RPC 제한 시간을 구분 | 개별 통신은 제한하되 경과 시간만으로 일반 작업을 종료하지 않음 |

이 결정은 이전의 Desktop 저장 프로젝트 소속·원격 열기 필수 조건과 불확실한 전달의
재전송 금지 정책을 대체합니다. 네이티브 신원, 명시적 deny, 호스트 훅, worktree 소유권,
공개 권한은 유지합니다. 작업 난이도에 따른 모델 선택이 권한 범위를 바꾸어서는 안 됩니다.

## 용어와 소유권

| 용어 | 의미 |
| --- | --- |
| 프로바이더 종류 | Codex 또는 Claude라는 제품 구분. 프로세스 신원이 아님 |
| 프로바이더 인스턴스 | 복구 시 런타임 연결과 네이티브 프로세스 세대를 교체할 수 있는 영속적인 소유 실행 신원 |
| 논리적 수신자 | 프로젝트와 소유된 프로바이더 실행 안에서 지속적으로 주소를 갖는 참여자 |
| 네이티브 세션 | 프로바이더가 부여한 세션 식별자. 결속을 검증하며 호출자 권한 입력으로 쓰지 않음 |
| 네이티브 서브에이전트 | 프로바이더가 부모 관계를 확인하고 지원하는 위임 구조로 관리하는 자식 |
| 발행자 | 위임한 작업의 보고를 받고 후속 조치를 책임지는 참여자 |
| 메시지 | 안정적인 키와 영속 식별자를 가진 변경 불가 수신자 지정 본문 |
| 전달 시도 | 메시지 한 건을 전송하는 한 번의 시도. 중복될 수 있음 |
| 수신 ACK | 지정된 수신자가 메시지 수신을 확인한 기록. 작업 완료가 아님 |
| DLQ | 전달을 계속하려면 구체적인 복구가 필요한 수락 메시지를 영속적으로 격리하는 영역 |

같은 프로바이더 종류를 쓰는 두 프로세스가 자동으로 같은 인스턴스가 되지는 않습니다.
네이티브 자식마다 독립된 오프라인 노드 모델을 만들지 않습니다. 프로바이더 내부 작업
실패는 여전히 보고하며, 프로세스가 살아 있어도 네이티브 호출은 실패할 수 있습니다.

발행자는 작업 수락, 명시적 취소 또는 검증된 인계까지 후속 처리를 소유합니다. 현재 모델
턴의 종료를 인계로 해석하지 않습니다. 프로세스 종료나 연결 EOF를 관측했다고 다른
에이전트의 worktree claim을 가져오거나 세션 신원을 대신 사용할 수는 없습니다.

## 권한 승계

**FR-P01.** 허용된 네이티브 도구 호출에서 생성자의 현재 실제 권한을 읽습니다. 오래된
전역 기본값, 프롬프트 문구, 확인되지 않은 모델 보고를 권한으로 쓰지 않습니다. 승계 대상은
승인 동작, 도구 제한, 파일·네트워크 격리와 관련 프로바이더 설정입니다. 각 필드에 관측
출처를 연결하고, 확인할 수 없는 값은 미관측으로 남깁니다.

**FR-P02.** 같은 프로바이더에서는 실제 네이티브 설정을 보존합니다. 다른 프로바이더에서는
기능과 제한을 각각 대응시킵니다. 모드 이름만으로 동등성을 판단하지 않습니다. 작업 공간
상대 권한은 할당된 작업 공간과 필요한 공유 하네스 상태에만 적용하며, 다른 소유자의
소스 저장소에 대한 쓰기 권한을 부수적으로 넘기지 않습니다.

| 원래 동작 | 대응 요구 |
| --- | --- |
| 일반 도구 사용을 묻지 않고 폭넓게 승인 | Claude `bypassPermissions`는 지원 후보이며, Codex의 승인 정책과 샌드박스 설정은 별도 입력으로 처리 |
| 새 승인이 필요한 작업은 거부 | 이 동작을 보존. Claude `dontAsk`를 묵시적으로 `bypassPermissions`로 바꾸지 않음 |
| 읽기 전용 또는 계획 | 허용된 읽기와 실제 쓰기 제한을 보존. `plan`만으로 OS 격리를 증명하지 않음 |
| 대화형 승인, 편집 자동 승인, 분류기 승인 | 지원되는 네이티브 설정으로 판단 경계를 보존하며 모든 모드를 단일 별칭으로 추정하지 않음 |
| 명시적 도구 deny 또는 파일·네트워크 제한 | 승인 모드와 별도로 보존 |

어댑터가 버전별 대응 규칙과 테스트를 소유합니다. 대상이 원래 권한을 표현하거나 검증할 수
없으면 지원하지 못하는 항목을 정확히 보고하고 작업 전달을 보류합니다. 권한을 몰래
넓히거나 줄인 상태를 승계 성공으로 표시하지 않습니다.

**FR-P03.** 바로 위 생성자를 기준으로 계속 승계합니다. 중간 세션이 제한됐다면 그 자식도
제한을 이어받으며, 최초 루트의 더 넓은 권한을 자동 복원하지 않습니다. 명시적으로 승인된
정책 변경만 승계를 덮어씁니다. 폭넓은 승인 모드가 프로바이더 승인 콜백을 건너뛰더라도
명시적 deny와 하네스 훅은 유지합니다.

**FR-P04.** 설치, 네이티브 활성화, 실제 권한 readback, 정상 소유권, 명명된 도구 사용
가능성을 확인한 뒤 본 구현을 전달합니다. 준비와 작업 전달은 별도 상태입니다. 새 작업
공간에 Git에서 제외된 설치 파일이 있다고 가정하지 않습니다. 발행자가 지원되는 설치·수명
관리 경로로 빠진 준비를 수행합니다. 사용자에게 명령을 맡기거나 전역 권한을 다시 쓰거나
다른 연결이 소유한 실행 중 세션을 resume하는 방식으로 복구하지 않습니다.

## 실행 수명과 보고 책임

**FR-L01.** 실행 호스트의 프로세스·네이티브 연결 이벤트를 관측합니다. 사용자 접속,
앱 화면 상태, 원격 관측 연결은 실행이나 전달에 영향을 주지 않습니다. 모델의 idle,
입력·승인 대기, 프로세스 실패, 명시적 취소는 구분합니다.

**FR-L02.** 영속 접수는 모델 실행이 끝나기 전에 반환합니다. 접수, 실제 시작, 대기,
오류, 연결 종료, 취소, 완료를 따로 보고합니다. 네이티브 턴 성공만으로 실제 작업 효과를
주장하지 않습니다. 발행자가 보고 본문을 읽고 후속 응답을 책임집니다.

**FR-L03.** 위임한 작업이나 ACK 없는 필수 보고가 남으면 한 턴이 끝나도 소유 연결을
유지합니다. 수신 이벤트는 정상 소유 연결을 통해 같은 논리적 발행자의 후속 처리를
진행시킵니다. 보고 수신만을 위해 다른 LLM 세션을 만들거나 경쟁 연결에서 살아 있는
세션을 resume하지 않습니다.

**FR-L04.** 발행자 인스턴스가 죽어도 다른 인스턴스에서 승인된 작업이 실행 중이면
발행자 부재만으로 취소하지 않습니다. 보고는 나중에 받을 수 있도록 보존합니다. 전원이
꺼진 호스트에서 실행을 계속하거나 손실된 디스크를 복구한다고 보장하지 않습니다.
중단된 작업 실행과 메시지 전달 복구를 별도로 보존합니다.

## 메시지 식별과 전달

**FR-M01.** 접수 전에 발신자, 수신자, 본문을 검증합니다. 영속 접수 반환이나 전송 알림에
앞서 변경 불가 메시지를 원자적으로 저장합니다. 공개 결과는 저장·접수, 전송 제출,
수신자 ACK를 구분합니다.

**FR-M02.** 메시지에는 `message_id`, 발신자, 논리적 수신자, 종류, 대화, 본문 참조·내용
지문, 생성 시간과 선택적인 작업·답장 연결을 포함합니다. 발행 멱등 키는 정확한 요청에
결속하며 같은 키로 다른 내용을 보내면 충돌입니다. 모든 재시도는 같은 메시지 식별자와
내용을 사용합니다. 전달 시도 식별자는 달라도 논리적 메시지 키를 새로 만들지 않습니다.

**FR-M03.** 수신 LLM에 안정적인 키를 제공합니다. 알림에는 전체 본문 대신 키와 명명된
본문 조회 도구를 담을 수 있습니다. 반복 알림도 같은 메시지로 식별돼야 합니다. LLM은
중복 작업을 무시하고 ACK를 다시 보낼 수 있으며, 하네스가 외부 작업 효과의 exactly-once를
보장한다고 주장하지 않습니다.

**FR-M04.** 유효하게 수락된 메시지는 수신자 ACK 또는 명시적으로 기록된 취소까지 전달
대상으로 남습니다. 전달이나 ACK가 불확실하면 재시도하며 `sending`, `uncertain`, `failed`,
ACK 없는 `submitted`도 복구합니다. 어느 상태도 영구 재시도 금지 표지가 아닙니다.
전송 성공이나 프로세스 재시작으로 ACK를 만들어 내지 않습니다.

**FR-M05.** 현재 소유 전송 경로로 재시도하며 개별 통신 제한 시간과 재시도 간격을 둡니다.
재시도 예약은 이미 알고 있는 미확인 메시지에 대한 것이며, 보관함·작업·프로세스 상태를
주기적으로 조회하는 폴링이 아닙니다. 재연결, 네이티브 준비 상태 변경, 메시지별 전달·ACK
기한이 재시도를 유발할 수 있습니다. 승인 대기 중 반복 실행하거나 죽은 프로세스를 붙들지
않고, 다음 정상 연결에서 전달하도록 보존합니다. backoff는 빈도를 제한하며 작업 수명이나
영속 복구 기회의 횟수를 제한하지 않습니다.

**FR-M06.** ACK는 지정된 수신자 신원으로 인증하고 영속 저장합니다. ACK 전에 전체 본문을
직접 전달받거나 본문 조회에 성공해야 합니다. ID만 있는 알림은 충분하지 않으며, 본문 조회가
실패하면 전달 대기를 유지합니다. 이미 같은 불변 메시지의 본문을 받은 수신자는 중복 메시지에
다시 ACK할 수 있습니다. 중복 ACK는 같은
결과를 냅니다. ACK는 전달 재시도를 끝낼 뿐이며 작업 수락·거부·완료·후속 처리는 별도
메시지입니다. 늦게 도착한 시도 결과가 ACK나 더 새로운 소유 연결 세대의 결과를 덮어쓰지
못해야 합니다.

**FR-M07.** 일반 대화의 TTL과 메시지 예산은 새 활동을 제한할 수 있지만, 이미 수락된
미확인 메시지를 복구 대상에서 없애서는 안 됩니다. 대기 메시지가 있는 대화를 닫으려면
대기 상태를 명시적으로 반환하거나 승인된 취소를 기록해야 합니다. 만료·닫기·재시작·정리
과정에서 몰래 버리지 않습니다. 이 요구는 협업 메시지에 적용하며 의도적으로 일시적인
Newsroom 피드에는 적용하지 않습니다.

전달 보장은 영속 저장소가 유지되고 정당한 수신자가 결국 사용 가능해지는 것을 전제로
합니다. 그 전제가 없으면 대기 또는 복구 필요를 보고하며 전달 성공을 주장하지 않습니다.
명시적 취소는 눈에 보이는 종료 예외이지 수신 성공이 아닙니다.

## 복구와 DLQ

**FR-R01.** 논리적 수신자 신원은 PID, 소켓 경로, 네이티브 연결 세대와 분리해 보존합니다.
복구 시 소유된 실행과 기존 수신자 결속을 입증하고, 지원되는 네이티브 세션을 복원한 뒤
현재 권한·활성화를 확인합니다. 새 네이티브 UUID를 이전 보관함의 자동 후계자로 취급하지
않습니다. 살아 있는 소유자의 lease를 빼앗거나 임의 호출자 신원을 받아 복구하지 않습니다.

**FR-R02.** 정상 소유자가 재연결되면 원래 키로 미확인 메시지를 재전달합니다. 종료 직전
제출된 메시지는 두 번 전달될 수 있습니다. 두 시도와 최종 ACK를 보존합니다. 프로바이더가
해당 실행을 복원할 수 없으면 보관함을 유지하고 기능 제약을 보고합니다. 대체 대화를
임의로 만들거나 대신 작업을 수락하지 않습니다.

**FR-R03.** 일시적 프로세스 부재, 응답 유실, ACK 유실은 재시도 대상입니다. DLQ는
메시지 버전 불일치나 무효화된 수신자 결속처럼 복구 선행 조건이 확인된 수락 메시지에
사용합니다. 메시지, 실패 분류, 시도 이력과 필요한 복구를 보존합니다. 삭제 큐나 시간에
따른 만료가 아닙니다. 미해결 DLQ 항목이 있으면 모든 메시지가 전달됐다고 주장할 수 없습니다.

**FR-R04.** 복구 후 재처리는 정당한 소유자가 명명된 도구로 수행하고 메시지 식별자·내용과
전이 기록을 유지합니다. 권한을 넓혀 거부를 재실행하거나 취소된 작업을 되살리거나 DB를
직접 편집해 불확실성을 지우지 않습니다. 발행 멱등성과 전달 재시도는 별도 계약입니다.

| AC09 | 일반 TTL 경과·대화 예산 소진·대기 중 닫기 이후에도 메시지가 복구 가능하거나 명시적으로 취소됨 | FR-M07 |

결정적 큐·전송 테스트는 상태 전이를 입증합니다. 실제 설치된 Codex와 Claude에서는 정상
명명된 진입점과 프로바이더 소유 연결로 AC01–AC06 및 AC11을 추가 검증합니다. 내부 worker
함수 직접 호출, 신원 합성, 앱 metadata만의 확인, 과거 테스트 수치 합산으로 대체하지 않습니다.
검증 원문은 비공개 로컬에 보존하고 각 실행이 실제로 다룬 시나리오를 구분합니다.

## 구현 소유권과 전환 순서

| 작업 묶음 | 소스 담당 영역 / 집중 검사 | 선행 조건 |
| --- | --- | --- |
| W1 권한 표현과 대응 | `providers/contracts.py`, 프로바이더 어댑터, `readiness.py`; 권한 테스트 | 확정 계약, 모델·MCP 공통 입력 합의 |
| W2 영속 재시도와 보존 | `agents/store.py`, `agents/delivery.py`; 전달·수명 테스트 | FR-M 메시지·ACK 계약 |
| W3 소유 연결 복구와 전달 | `providers/jobs.py`, `supervision.py`, `codex_delivery.py`, `execution_claude.py`; 복구 테스트 | W1, W2 |
| W4 명명된 준비·복구 작업 | `runtime/task_schema.py`, `runtime/tasks.py`, 호스트 결속, 설치 투영 | W1, W2, 모델·MCP 계약 |
| W5 통합 실호스트 검증과 문서 | 한영 사용 안내, 최종 fixture, 패키지·설치 검증 | W1–W4 |

W1과 W2는 수정 영역을 분리해 병행할 수 있습니다. W3과 W4는 공통 스키마에 먼저 합의해야
합니다. runtime 스키마, CLI 호환, 설치 정책과 문서 진입점은 단일 통합 담당자가 수정합니다.
병행 모델·MCP 담당은 검토된 계약이나 격리된 패치를 제공합니다. 중복 claim이나 상태 파일
직접 편집으로 이 합의를 대신하지 않습니다.

전환은 바뀐 의미를 검증하는 실패 테스트부터 시작합니다. 일반 프로바이더 실행의 앱 접근
필수 조건과 불확실 메시지 재시도 금지 검사를 누락·복구 검사로 교체합니다. 소유권·권한·취소
검사는 유지하며 통과 수치를 만들기 위해 제거하지 않습니다. 이 계약 문서 자체가 설치된
하네스를 바꾸거나 모델을 선택하거나 이슈·커밋·푸시·릴리스를 발행하지는 않습니다.

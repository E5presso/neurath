Neurath는 배포본 무결성, 설치 동작, 런타임 계약, 실제 Codex·Claude Code 호스트에서 발생한
이벤트를 구분해 검사합니다. `doctor`가 통과했다는 것은 로컬 파일 배치와 프로토콜 검사를
통과했다는 뜻이며, 호스트의 신뢰 권한을 부여하지는 않습니다.

| 자기 설치 재실행 | 변경 없음. 프로젝트 연결 설정 보존 |

자기 설치 검사는 개발용 `.venv`와 분리된 패키지 도구 환경을 사용합니다.
Linux 검사는 빌드한 소스 배포본을 임시 컨테이너에서 실행합니다. 실제 호스트 검사는
프로젝트 신뢰를 명시적으로 설정한 임시 프로젝트에서 수행합니다. 이 결과가 다른 설치에
신뢰 권한을 부여하지는 않습니다. 위 Codex의 거부 결과는 실행 디렉터리 누락 시의 차단을
증명합니다. 해당 바깥쪽 도구 호출 정보에서 보호 경로 패턴을 정확히 판별했다는 근거는 아닙니다.
디렉터리와 셸 접두어의 정규화는 별도의 보호 기능 회귀 테스트로 검사합니다.

위 표의 전체 실제 호스트 수명주기·메시징·학습 검증에는 SHA-256이
`e4347d3d836313b7d61edce04a847f8731f5c7c52c0b436269542580a3e43609`인 wheel을 사용했습니다.

중간 wheel인
`a6aea761286a3806b9ebc02beae54366a21e24696b7fd8dae14bf85acc7043f0`에서는 실제 도구 실행 결과를
보존하도록 리뷰 지침과 생성된 점검 목록·무결성 검사 메타데이터를 수정했습니다.
실행 모듈은 전체 실제 호스트 검증에 사용한 wheel과 동일합니다.

리뷰 이력 처리를 수정한 wheel은
`1c24238e2271f8d4fb04b8ee8471467aac86525684748e79b3fd17b261b26552`입니다.
이 버전에서는 전체 리뷰 시 사용하지 않는 과거 보고서를 해석하지 않으며, 이전 리뷰에서
이어받을 근거에서 무관한 일반 작업 위임을 제외합니다. 같은 커밋에 대한 리뷰가 서로
충돌하면 기록 순서에 관계없이 새 전체 리뷰를 요구합니다. 관련 집중 검사에서 테스트 19개와
하위 테스트 5개가 통과했습니다. 여기에는 형식이 잘못된 관련 근거의 거부와, 동등한 과거
통과 리뷰의 수용이 포함됩니다. 갱신된 macOS·Linux 전체 검사, 외부 패키지 검사, 실제 uv
설치, 자기 설치, 두 호스트의 새 활성화 검사는 이 wheel을 대상으로 했습니다.
앞서 수행한 전체 실제 호스트 수명주기·메시징·학습 결과는 위에 명시한 원래 wheel에 한정됩니다.

최종 공개 배포 wheel은
`aa91a4ae93759e5380ca866a8b5fb57821a8f70839e1b9877674f6612a194b8f`입니다.
이 버전에서는 리뷰 의견 분류 지침과 생성된 점검 목록·무결성 검사 목록만 보완했습니다.
기존의 세 번째 수집 경로에서 리뷰 본문을 수집하고, 답변은 PR의 일반 토론에 남기며,
수신 확인에는 별도 에이전트 표식을 사용합니다. 처리 완료 표식은 최종 답변에만 붙입니다.
로컬 API 테스트 환경에서 수집, 원래 항목을 닫지 않고 수신 확인만 수집 대상에서 제외하는
동작, 최종 처리 완료 표식 필터링을 검증했습니다. 실행 모듈은 리뷰 이력 수정 wheel과
동일하며, 앞선 실제 호스트 수명주기 결과의 적용 대상도 그대로입니다.
기존 항목 크기 제한을 지키기 위해 중복 문구를 제거했으며, 프롬프트 로딩 검사는 제한값이나
테스트를 바꾸지 않고 통과했습니다.

Linux에서는 빌드한 소스 아카이브를 Python 3.14로 실행했습니다. 개발 환경의 Python
버전 지정은 3.14 계열을 허용하므로, uv의 인터프리터 목록에 특정 패치 버전이 아직 없어도
동작합니다.

## 기억과 학습의 회귀 검증 범위

테스트는 worktree 간 공유 저장소, 동시 쓰기, 저장소 격리, 같은 출처 이벤트의 기록 충돌,
크기가 제한된 기억 조회, 자격 증명 가림 처리, 비공개 추론 제외를 검사합니다.
학습 테스트는 무관한 테스트의 통과, 알 수 없는 결과, 불완전한 검사 결과, 같은 세션 안에서의
정식 지침 전환, 전달하지 않은 전략의 성공을 근거로 인정하지 않는지 확인합니다.
자동 검증 테스트는 인계 기록이 이미 저장된 경우, 실패한 검사의 반복 억제, 범위를 한정한
검증 보류, 새 실패 복구 근거, 연결되지 않은 검증 명령을 다룹니다. 검증 계약 변경,
시험 전략 사용 후 실패, 실행 기록의 반복 동기화, 실제 전달한 지침에 한정한 전달 기록도 검사합니다.

실제 호스트 테스트는 프로세스와 도구 실행 결과의 메타데이터를 사용합니다. 프로세스 종료
결과처럼 위장한 JSON 표준 출력과 Claude의 별도 실패 응답 형식도 검사 대상입니다.
일반적인 인계 기록 작성을 요구하는 Stop 요청은 같은 세션에서 인계를 실제로 저장하고,
그다음 Stop이 성공한 경우에만 실제 호스트 검증기가 수용합니다. 그 밖의 실행 허용 조건
실패는 그대로 실패로 남습니다.

호스트 간 기억 조회는 도구 출력과 추론 블록을 제외하고, 사용자에게 보이는 에이전트의
답변을 기준으로 확인했습니다. 중단 테스트에서는 원래 세션에 인계 기록이 없었음을
확인했습니다. 명령 학습 테스트는 모델의 학습 주장뿐 아니라 저장된 상태 전환 이력도
확인했습니다. 지원하는 학습 범위는 [기억과 학습](../usage/memory.md)에 설명합니다.

## 패키지 검사 재현하기

```sh
uv sync --locked
uv run --locked python tools/check.py
uv build
uv run --locked python tools/validate_distribution.py dist/neurath-0.1.0-py3-none-any.whl --output .validation/wheel.json
uv run --locked python tools/validate_setup.py --output .validation/setup.json
```

검사 명령은 전체 실행 자산 목록, Python 진단, 패키지·설치기 테스트, 분리된 환경의
런타임 계약 테스트를 검증합니다. wheel 검사는 외부 실행 환경을 이용해 빈 저장소,
Python 저장소, JavaScript 저장소에 설치합니다. 설치, 재설치, 로컬 프로토콜, 실행,
기존 파일 보존, 제거를 확인합니다.

## 자기 설치를 이용한 개발

```sh
./setup --self
.neurath/run doctor --protocol
.neurath/run verify check
```

개발 저장소는 `.neurath/project.json`에서 `check`를 동일한 전체 검사 명령에 연결합니다.
설치된 하네스는 별도의 영구적인 도구 환경을 사용하며, 개발 환경은 `uv.lock`으로
재현할 수 있습니다.

공개 지침과 프로젝트 연결 설정은 Git에 포함합니다. 생성된 스킬, 호스트 설정,
인터프리터 절대 경로가 들어간 실행기, 설치 이력, 실행 결과, 검증 기록, 검토 결과,
호스트 실행 기록 원문, 런타임 상태는 포함하지 않습니다. 새로 복제한 저장소에서는
`./setup --self`로 해당 파일을 다시 만듭니다. 기존 Neurath 지침 블록이 원문과 정확히
일치하면 중복 없이 보존하며, 편집됐거나 알 수 없는 블록은 충돌로 처리합니다.

## 과거의 기억·호스트 검증 근거

이전의 실제 Codex·Claude Code 실행에서는 파일 쓰기, 중단, 재개, 컨텍스트 압축,
별도 검토자, 완료, 소유권 해제, 보호 작업 거부를 검사했습니다.
이 검사는 독립적으로 패키징한 런타임에서 통과했습니다. 새 Claude 세션이 Codex의
정상 종료 후 결정을 복원하는 경우와, 인계 기록 없이 중단된 턴의 결정을 복원하는 경우도
확인했습니다. 일반 작업 요청으로 자동 인계 요청, 명령 실패 복구, 시험 지침,
세션 간 활성화, 실제 명령 실패 후 철회를 검사했습니다.
위 최근 결과에 명시된 경우를 제외하면 과거 검증 결과이며, 모든 배포본에서 이전의 모든
시나리오를 다시 검사했다는 의미는 아닙니다.

배포본이 바뀌면 해당 검사를 다시 실행하고 패키지 지문을 기록합니다. 호스트 활성화에는
정확히 그 설치에서 발생한 새 호스트 이벤트와 실제 상태 재조회가 필요합니다.
신뢰는 프로젝트와 실제 훅에 한정됩니다. 테스트 프로젝트의 신뢰 설정으로 다른 저장소가
활성화되지는 않습니다. 하위 프로세스가 중단되거나 완료됐다는 사실만으로도 충분하지 않습니다.

상세 근거는 Git에서 제외한 로컬 검증 저장소에 보관합니다. 공개 배포본에는 개인 경로,
세션 식별자, 프로세스 기록, 원본 파일 백업, 오래된 아카이브를 포함하지 않습니다.

# 런타임 경계별 검증 근거

[English](../../en/contributing/validation.md)

Neurath 검증은 소스 자산의 무결성, 빌드된 배포본의 독립 실행, 설치 시 대상 보존, 실제 호스트의 런타임 계약 집행을 각각 확인한다. 바꾼 경계에 맞는 근거를 선택한다. 과거의 통과 개수나 다른 세션에서 확인한 wheel로 현재 체크아웃의 상태를 확정하지 않는다.

## 소스 검사 실행

Neurath 소스 체크아웃에서 실행한다.

```sh
uv sync --locked
uv run --locked python tools/check.py
```

[검사 실행기](../../../tools/check.py)는 첫 실패 단계에서 중단하고 해당 종료 코드를 반환한다. 실행 순서는 다음과 같다.

1. `python -m neurath integrity`로 배포 자산 무결성 확인.
2. `src/neurath`에 Ruff `E4,E7,E9,F` 규칙 적용.
3. `python -m pytest -q`로 패키지·설치 테스트 수행.
4. `tools/run_core_regressions.py`로 독립 런타임 계약 검사.

모든 단계가 성공한 뒤에만 `NEURATH_CHECK_OK`를 출력한다. 다른 실행에서 복사한 문자열은 현재 프로세스 결과의 근거가 아니다. 새 동작은 적절한 실패 테스트로 시작하고 수정 중에는 관련 검사를 사용한다. 최종 소스에서 필수 전체 검사를 완료한다. 같은 상태에서 실패 명령을 반복하기보다 관련 수정이나 새로운 근거가 있을 때 다시 실행한다.

공개 문서 규칙의 집중 검사:

```sh
uv run --locked pytest -q tests/test_publication.py
```

런타임·배포 자산을 수정했으면 전체 검사 전에 무결성 데이터를 갱신한다.

```sh
uv run --locked python tools/build_manifest.py
uv run --locked python tools/check.py
uv build
```

## 개발 체크아웃과 분리한 런타임 검사

런타임 실행기는 Neurath 소유 자산과 런타임 테스트를 새 Git 검증 환경에 복사하고, 검사용 연결 설정·훅을 제공한 뒤 번들 엔진을 가져와 pytest를 실행한다. 다른 프로젝트를 소스 자산으로 사용하지 않는다. 기본 임시 환경은 실행 후 삭제된다. 조사할 환경을 유지하려면 새로운 비공개 대상을 지정한다.

```sh
uv run --locked python tools/run_core_regressions.py --target /private/path/to/fixture
```

새 트리를 복사하므로 대상은 아직 존재하지 않아야 한다. 뒤에 테스트 선택자를 추가하면 해당 환경의 pytest 범위를 좁힐 수 있다. 실패 진단은 `.neurath/local/verification` 아래 비공개로 보관하며 공개 배포에 넣지 않는다. 구현은 [실행기](../../../tools/run_core_regressions.py)를 참고한다.

## 소스 밖에서 실제 wheel 검증

빌드 후 실제 전달할 wheel을 선택하여 검사한다.

```sh
uv build
mkdir -p .validation
uv run --locked python tools/validate_distribution.py dist/neurath-0.1.0-py3-none-any.whl --output .validation/wheel.json
```

예시 파일명은 현재 패키지 버전 `0.1.0` 기준이다. 버전이 바뀌면 실제 빌드 결과를 지정한다. [배포본 검증](../../../tools/validate_distribution.py)은 외부 Python 3.14 환경에 wheel을 설치하고 빈 저장소·Python·JavaScript 저장소에서 동작을 확인한다. 프로젝트 지침, 권한, 대상 환경을 보존하면서 설치, 변경 없는 재설치, 호스트 선택 업데이트, 로컬 진단, 제거를 수행한다. 경로에는 공백과 따옴표도 포함한다. 모듈 가져오기 단계에서는 소스 체크아웃 접근을 차단하여 번들 모듈의 독립성을 확인한다. 결과에는 wheel 해시, import 관측, 저장소별 결과, 실제 활성화 미확인을 기록한다.

`.whl`을 만들었다는 사실만으로 이 계약을 실행한 것은 아니다. 소스 배포본 검사는 두 언어 문서 포함과 비공개 자산 제외를 별도로 확인한다. [공개 문서 테스트](../../../tests/test_publication.py)는 같은 언어 링크, 경로 대응, 메타데이터, 독립 import도 확인한다.

## 개발 환경을 사용하지 않는 실제 초기 설치

```sh
uv run --locked python tools/validate_setup.py --output .validation/setup.json
```

[초기 설치 검증](../../../tools/validate_setup.py)은 소스를 격리된 임시 위치에 복사하고 최소 시스템 PATH와 별도의 `uv`·Python·도구·실행 파일 디렉터리를 사용한다. 해당 최소 PATH에서 Git과 curl을 사용할 수 있어야 한다. 공식 `uv` 다운로드와 Python 준비를 실제 수행하고 빈 저장소·Python·JavaScript 대상을 검사한다. 경로에는 공백, 따옴표, 한글을 포함한다.

권한, 기존 훅 그룹, 모델 선택, 지침, 의존성 선언, 수정한 연결 설정이 보존되는지 확인한다. 대상 `.venv`·잠금 파일이 생기지 않는지, 재설치 변경이 없는지, 제거 후 원래 내용으로 돌아오는지도 본다. 설치 소스를 옮긴 뒤 설치 실행기를 호출하고, 새 체크아웃에서 자기 설치를 두 번 수행하여 공개 지침 보존과 변경 수 0의 재사용을 확인한다. 실제 네트워크를 사용하는 검사이므로 실패 시 준비 조건이나 네트워크 오류를 그대로 남긴다.

설치기 회귀 검사는 내용 기반 런타임 재사용, 불변 런타임 업데이트, 캐시가 있는 상태의 빌드, dry-run 범위, 오래되거나 변조된 계획, 다른 대상, 경로 이탈, 소유 파일 충돌, 정상 블록 주변 편집, 블록 자체 수정 거부, 정확한 모드·링크 복원, 트랜잭션 되돌리기, 실제 프로세스 강제 종료 후 복구도 다룬다. [설치기 테스트](../../../tests/test_installer.py)와 `tests`의 setup 검사를 참고한다.

## 실제 호스트 수명주기 확인

배치 진단은 바이트·링크와 설치 이력을 비교한다. 프로토콜 검사는 독립 subprocess에서 정상 시작 JSON과 잘못된 입력을 다룬다. 실제 활성화는 Claude Code나 Codex 세션이 설치 연동을 로드하고 호출자가 확인된 상태 작업을 수행하는 것을 관측해야 한다. 원시 transcript, 지문, 관측 자산은 비공개로 보관하고 검사한 정확한 런타임·호스트와 연결한다.

| 시나리오 | 필요한 관측 |
| --- | --- |
| 새 시작 | 실제 호스트 이벤트, 명령 실행, 호출자 결속 상태, 런타임 신원 |
| 방향 수정·중단 | 이전의 확인된 턴만 종료되고 새 사용자 의도와 남은 작업은 유지 |
| 재개 | 네이티브 복구 근거로 재개 가능한 세션을 연결; 영구 종료한 커널 세션은 부활하지 않음 |
| 직접 자식 | 실제 생성·transcript 계보, 필요한 검토가 남았을 때 조기 완료 거부 |
| 독립 검토자 | 정확한 후보 읽기, 인증된 보고, 부모의 보고 소비 |
| 소유권 | 현재 임대·소유권 확인 키 집행, 오래된 쓰기 거부, 승인된 해제 관측 |
| Stop | 작업 목록 확인과 종료를 원자적으로 수행하여 동시 추가가 사라지지 않음 |

`UNATTESTED` 세션·턴·자식 식별자는 실행 상태를 바꿀 수 없다. 복사한 참조도 네이티브 계보가 아니다. Codex는 실제 직접 자식 결과 경로와 transcript 메타데이터를 확인하고, Claude는 자식 transcript에서 확인한 일회용 부모 Agent 호출 참조를 결속한다. 등록이 늦으면 첫 상태 작업에서 재시도할 수 있지만, 확인되지 않은 자식의 셸·쓰기는 `child-identity-unverified`로 막힌다. 중첩 생성은 지원하는 직접 자식 계약 밖이다.

호스트 프로세스 종료 후에도 재개 가능한 작업, 소유권, 세션 상태는 남는다. fork는 자체 소유권이 필요한 새 루트다. 사용자 프롬프트 훅 없이 들어온 앱 동료 전달은 실제 전달·완료와 네이티브 턴 근거를 사용해야 하며 새로운 사용자 승인을 만들 수 없다. 늦은 Stop은 더 최신의 확인된 턴을 닫지 않는다. 짝이 없는 Stop은 상태를 바꾸지 않는 비차단 진단을 남긴다. 루트의 계속 실행 횟수는 확인된 사용자 턴마다 제한되어 미완료 작업이 무제한 Stop 반복을 만들지 않는다.

## 의미 있는 경계 사례 유지

| 영역 | 정상 동작을 구분하는 사례 |
| --- | --- |
| Provider 실행 | 두 provider 방향, 직전 생성자의 실제 정책 승계, 실제 모델 재확인, 편집 전 준비·소유권, 장시간 작업 중 메시지·취소 수용 |
| 메시지 전달 | 전체 본문 읽기·ACK·답변·종료, 전송 전후 발행자·수신자 종료, ACK·응답 유실, 오래된 시도, TTL·종료 후 미확인 메시지 보존, 원래 식별자로 복구 재전달 |
| 기억 | 연결 worktree 동시성·격리, 충돌하는 출처 재생, 문맥 크기 제한, 인증 정보 가림, 비공개 추론 제외, 인계 기록 없이도 결정 회상 |
| 학습 | 같은 작업·선택자의 실패와 복구, 실제 프로세스 결과, 대응하는 프로젝트 검사, 다른 노출 세션의 사용 후 승격, 미노출·같은 세션·위조 stdout·미확인·불완전 근거 거부 |
| 학습 복구 | 검증 유예와 재시도 억제, 새 근거, 검사 계약 변경, 노출 상한, 복구 명령·검사 실패에 따른 지침 철회 |
| 보호 작업 | 정확한 경로·glob 처리와 디렉터리 부재에 따른 보수적 거부 구분 |
| PR 검토 | 전체 검토에서 쓰지 않은 옛 보고 제외, 무관한 위임 근거 승계 제외, 같은 커밋의 충돌 판단은 새 전체 검토 필요, 잘못된 관련 근거 거부, 동등한 기존 통과 인정 가능 |
| 댓글 처리 | 리뷰 본문 별도 수집, PR 일반 논의에 답변, ACK와 최종 처리 마커 구분, ACK만으로 원본 항목을 닫지 않음 |

학습 검사는 네이티브 프로세스 메타데이터와 출력 문자열을 구분하고 Claude 실패 응답 형식을 다뤄야 한다. 인계 기록 기반 Stop 관측은 같은 세션에서 인계 기록을 수용한 뒤 성공한 Stop까지 확인했을 때만 해당한다. 다른 기록·세션에서 결과를 가져와 일반화하지 않는다.

[호스트 테스트](../../../tests/test_host_lifecycle.py), [전달 복구 테스트](../../../tests/test_delivery_recovery.py), [학습 테스트](../../../tests/test_learning.py), [프로젝트 기억 테스트](../../../tests/test_project_memory.py)가 소스 기반 회귀 검사의 출발점이다. 실제 네이티브 자산은 각각의 관측 범위를 유지한다. 모의 회귀 검사 성공만으로 모든 provider나 데스크톱 연결을 실행했다고 설명하지 않는다.

## 목표 환기와 제공자 간 승계 확인

목표 환기는 유효한 루트 이벤트, 새 프롬프트 출처, 서로 다른 완료 ID 12건, 5분 뒤의 다음 유효 이벤트, 중복 콜백, UTF-8 크기 한도, 태스크·권한 상태 보존을 검사한다. 실제 호스트별 전달도 따로 관찰한다. 이 검사는 전달 동작을 확인하며 의미상 판단이나 목표 수렴의 완벽함을 보장하지 않는다.

`target-native`는 대상의 기존 설정과 생성된 세션에 적용된 모델·정책을 확인한다. `memory_pull`은 미리보기·전체 읽기의 페이지 처리, 정리되지 않은 원본, 스냅샷 기준 변경, 의존 관계 매핑, 원자적 소유권 이전, 중복 쓰기, 승계 후와 수신자 소유권 해제 후의 원본 재개를 다룬다. 저장된 대화도 참고 자료이며 제공자가 남기지 않은 내용은 복구 보장 범위 밖이다. 관련 fixture는 [환기](../../../tests/test_goal_reminders.py), [대상 정책](../../../tests/test_target_native_policy.py), [승계](../../../tests/test_memory_pull.py), [MCP 입력](../../../tests/test_memory_pull_mcp.py), [대화 복구](../../../tests/test_migration_transcript.py)에 있다.

비공개 네이티브 결과마다 검증한 빌드의 식별과 실행 방향을 유지한다. 한 후보의 검사 성공을 근거로 다른 후보의 위임·pull·목표 환기·원본 재개 차단 검증을 새 실행 결과로 바꾸어 적지 않는다. 배포본 검사, 외부 설치, 자기 설치, 실제 호스트 실행은 각각의 범위를 유지한다. 네이티브 프로젝트 메타데이터 변경은 Codex 앱 소속의 증거가 아니다. 앱 소속이 필요한 작업은 앱 생성 경로를 사용하고, 지원되는 경우 검증된 루트의 `session_status.app_project`를 포함해 앱 소속 기록을 별도로 관찰한다. 이 기록은 원격 화면이나 실행 권한의 증거가 아니다. 새로 설치한 도구를 확인할 때 오래된 MCP 프로세스는 재접속이 필요할 수 있다.

## 근거가 뒷받침하는 결과 보고

변경 동작, 실제 실행한 명령, 관측 결과, 자산 식별자, 중요한 미확인 범위를 설명한다. 소스 검사, wheel 빌드, 자기 설치, 대상 검사, 독립 검토, 실제 활성화, 공개 배포는 각각의 결과다. 실행 자산 개발 후 현재 체크아웃의 하네스 갱신이 범위에 있다면 `./setup --self`를 수행하고 설치 결과와 필요한 실제 호스트 동작을 확인한다. 문서 수정만으로 런타임 활성화가 입증되거나 요구되지는 않는다.

## 명명된 작업의 전체 경로 확인

Provider 수용 검사는 Codex·Claude 생성자와 수신자의 네 가지 조합, 더 제한적인 정책을 가진 중간 생성자를 모두 포함한다. Claude bypass 모드에서도 명시적 deny와 훅을 유지하고 지원할 수 없는 격리는 차단해야 한다. 설치·활성화·소유권·도구가 없으면 위임을 전달하지 않는다. 유휴 발행자는 같은 소유 연결로 전체 본문을 받고 ACK·답변을 수행해야 한다. 전송 전 종료된 수신자는 원래 key로 복구하고, 전송 후 ACK 전 종료는 식별자를 바꾸지 않는 중복 재전달로 처리한다. 전송·ACK 응답 유실도 복구할 수 있어야 한다. 오래된 generation의 시도는 새 소유자나 ACK를 되돌릴 수 없다. TTL·예산·종료 후에도 명시적 취소가 없다면 미확인 메시지를 보존한다. 전송 실패 보관함의 복구는 같은 ID를 재전달하고 임의 수신자 재결속·취소 후 부활은 거부한다. 본문 조회 실패는 ACK할 수 없으며 이미 읽은 중복 본문은 다시 ACK할 수 있다.

모델 검사는 근거 있는 단순·복잡 작업 선택, 고정·사용 불가 모델, 미확인 목록, 미지원 추론 설정, 오래된 계획, 모델 불일치, 별칭 결속을 다룬다. 접수 결과가 불확실한 뒤 할당량·범위가 바뀌면 상태를 대조해야 한다. 회상, 동료 메시지, 뉴스, 상태, 단계, 소유권, 학습 되돌리기, 업데이트, 보고의 명명 경로를 확인한다. MCP 미제공, 제한 모드, 불확실한 접수는 명시적인 미충족 항목으로 남기며 제약을 피하는 다른 호출을 유발하면 안 된다.

수용 범위에는 도구 목록뿐 아니라 설치된 정책·스킬·알림·오류의 `next_action` 안내도 포함한다. 실패하는 schema·plan·binding 테스트, adapter·설치 지침·설치 환경 검사를 거쳐 실제 Codex·Claude의 정책·시작·유휴·프로세스 종료·장시간 작업·모델·도구 선택 시나리오를 수행한다. 기존 저장 호출과 새 설치의 명명 호출은 함께 동작해야 한다. 이는 필요한 시나리오이며 네이티브 검증이 모두 끝났다는 선언이 아니다. 일반 명명 경로와 소유 연결을 사용하고 신원을 만들거나 비공개 작업자를 직접 호출하지 않는다. 네이티브 소스 편집과 검사는 일반 호스트 도구의 책임으로 유지한다.

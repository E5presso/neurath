# 코어 교체 구현 계획

[English](../../en/contributing/core-v2-plan.md) · [코어 명세](core-v2-spec.md)

새 코어 소스 구현과 이전 코어 소스 제거를 수행했다. 릴리스 후보는 0.2.1이다. 기존 호스트의 설치와 실제 활성화는 별개 작업이다. 소스 commit은 실행 중인 불변 설치본을 바꾸지 않는다.

## 구현한 경계

- Task가 사용자 인수 조건·순서가 있는 SkillRun·시도·배정을 소유한다. 실패한 시도는 원래 목표를 보존한다. phase를 건너뛸 수 없고 소유한 책임을 정리해야 정상 Stop이 가능하다.
- 네이티브 실행자 신원은 checkout 위치와 별개다. 쓰기 소유권은 변경을 조정하며 읽기·실패 보고에는 쓰기 소유권이 필요 없다.
- 서브에이전트·독립 세션·교차 provider는 명시적인 실행 선택이다. worker·reviewer·executor는 역할이다. 네이티브 handback은 부모 수락을 기다리지 않고 수신자의 보고 책임이 끝났는지 확인한다.
- 원문 입력 구간·실제 도구 결과·출처가 표시된 보고를 구분한다. 리뷰 준비에는 명시적인 checkout이 필요하며 실제 소스 스냅샷을 저장한다. 소스가 바뀌면 이전 리뷰를 재사용할 수 없다.
- 하나의 SQLite 저장소에 작업 상태를 둔다. 설치기는 오프라인 파일 전환 중 v1의 목표·의존성·소유권을 가져오며 원본 DB를 보존하고 중단된 파일 설치를 복구한다.
- 배포 스킬 33개 모두에 순서가 있는 정의가 있다. 편집·검사·provider 실행은 네이티브 도구가 수행한다. 이전 runtime·host/agent 제어 패키지·스크립트 엔진·불필요해진 provider 조정 계층은 제거했다.

## 검증 상태

필수 전체 소스 검사에서 패키지·설치 테스트 512개와 격리된 코어 계약 테스트 198개가 통과했다. 독립 리뷰가 발견한 터미널 입력·리뷰 freshness·필수 독립 리뷰·요청 오류 격리·네이티브 handback 결함을 수정하고 재검증했다. 빌드한 wheel은 소스 checkout 접근을 막은 독립 import 검사와 세 종류 저장소의 설치·재설치·제거 검사를 통과했다. 실제 setup bootstrap의 사용자 파일 보존과 자기 설치 검사도 통과했다.

이전 고정 후보의 실제 Claude 관측에서 phase 순서 위반 거부와 미완료 Task의 Stop 거부 뒤 계속 실행을 확인했다. 현재 후보에서는 네이티브 서브에이전트 생성·원문 읽기·출처가 표시된 리뷰·네이티브 handback·상위 수락·phase 순차 완료까지 확인했다. 실패한 handback 시도와 성공한 재시도는 같은 Task ID 아래 별도 시도로 보존했다.

실제 Codex 검증은 격리된 후보의 프로젝트·훅 신뢰 승인이 남아 있다. 프로토콜 fixture로 이 결과를 대신하지 않는다. 기존 운영 호스트의 활성화·병합·공개 릴리스는 실제 수행한 뒤 각각 보고해야 한다.

## 테스트 교체

삭제된 내부 구조에 결속된 테스트는 구현과 함께 폐기한다. 필요한 동작은 `tests/core`에서 검사한다. Task·phase·Stop·재작업, 트랜잭션 revision, 원문·승인 출처, 쓰기 소유권, 세 위임 선택, 실제 검사 결과, 리뷰 freshness, 네이티브 반환, 기존 데이터 보존이 대상이다. 설치·업데이트·보고·전송·학습 테스트는 유지한다. 전체 테스트와 소스 무결성 검사가 릴리스 기준이며 일부 검사 통과는 부분 근거다.

# 코어 교체 구현 계획

[English](../../en/contributing/core-v2-plan.md) · [코어 명세](core-v2-spec.md)

새 코어 소스 구현과 이전 코어 소스 제거를 수행했다. 소스 후보는 0.2.3이다. 기존 호스트의 설치와 실제 활성화는 별개 작업이다. 소스 commit은 실행 중인 불변 설치본을 바꾸지 않는다.

## 구현한 경계

- Task가 사용자 인수 조건·순서가 있는 SkillRun·시도·배정을 소유한다. 실패한 시도는 원래 목표를 보존한다. phase를 건너뛸 수 없고 소유한 책임을 정리해야 정상 Stop이 가능하다.
- 네이티브 실행자 신원은 checkout 위치와 별개다. 쓰기 소유권은 변경을 조정하며 읽기·실패 보고에는 쓰기 소유권이 필요 없다.
- 서브에이전트·독립 세션·교차 provider는 명시적인 실행 선택이다. worker·reviewer·executor는 역할이다. 네이티브 handback은 부모 수락을 기다리지 않고 수신자의 보고 책임이 끝났는지 확인한다.
- 원문 입력 구간·실제 도구 결과·출처가 표시된 보고를 구분한다. 리뷰 준비에는 명시적인 checkout이 필요하며 실제 소스 스냅샷을 저장한다. 소스가 바뀌면 이전 리뷰를 재사용할 수 없다.
- 하나의 SQLite 저장소에 작업 상태를 둔다. 설치기는 오프라인 파일 전환 중 v1의 목표·의존성·소유권을 가져오며 원본 DB를 보존하고 중단된 파일 설치를 복구한다.
- 배포 스킬 33개 모두에 순서가 있는 정의가 있다. 편집·검사·provider 실행은 네이티브 도구가 수행한다. 이전 runtime·host/agent 제어 패키지·스크립트 엔진·불필요해진 provider 조정 계층은 제거했다.

## 객체 책임

`Task`는 제어 주체·역할 호환성·배정 참여·순차적인 skill 진행·최종 인수를 소유한다. `Assignment`는 수신자 결속·결과 보고·수락·종료 전이를 소유한다. 두 불변 도메인 객체는 저장소나 호스트 입력 형식에 의존하지 않는다.

`Core`는 구체적인 협력 객체를 구성하고 명령 검증·호출자 확인·중복 실행 방지·트랜잭션 경계를 책임진다. `TaskCommands`와 `AssignmentCommands`는 명명 요청을 도메인 동작으로 변환한다. `Provenance`는 원문을 보관하고 증거가 속한 Task·시도·checkout·원문 종류를 확인한다. 리뷰 독립성은 프로젝트의 다른 Task에서 구현에 참여한 이력까지 고려한다.

`SessionLifecycle`은 실행자의 활성화·중단을 관측하고 미완료 작업을 보존하며 네이티브 TODO·Stop 결과를 만든다. `WorkspaceOwnership`은 checkout의 쓰기 주체를 조정한다. `NativeInvocations`는 네이티브 호출과 정확한 요청을 결속하고 호출의 수명을 닫는다. `CheckObservations`는 직접 실행한 등록 검사의 관측을 보관한다. `HookAdapter`는 호스트 이벤트를 변환해 이 객체들에 위임하며 도메인 전이를 직접 조립하지 않는다.

한 명령을 처리하는 객체는 같은 `Transaction`을 공유한다. 배정 보고의 원문·증거·Task revision은 함께 저장되며 도중에 실패하면 모두 되돌린다. 외부 게시 상태 조회는 쓰기 트랜잭션 전에 수행하고 기록 시 호출자를 다시 확인한다. 성공한 명령의 재시도는 원래 결과를 반환한다. 구체적인 메서드와 명시적인 라우팅으로 이 흐름을 드러내며 범용 명령 버스나 상속 계층은 두지 않는다.

## 검증 상태

0.2.2 기준본은 패키지·설치 테스트 472개와 격리된 코어 계약 테스트 158개가 통과했다. 객체 책임을 재구성한 0.2.3은 별도의 전체 검사에서 패키지·설치 테스트 477개와 격리 코어 계약 테스트 163개를 통과했다. 해당 wheel은 코어 모듈 33개의 독립 import와 세 종류 저장소의 설치·재설치·제거 검사를 통과했으며 실제 setup·자기 설치 검사도 통과했다. 독립 객체 설계 리뷰에 미해결 actionable finding이 없었다. 실제 Claude 세션에서 미완료 Task의 Stop 거부가 한 번 발생한 뒤 같은 Task가 완료됐다. 실제 Codex 후보에서도 phase 순서 위반 거부 1회, 미완료 Task의 네이티브 Stop 거부 1회, 같은 Task 계속 실행, scope/inspect/explain 순차 완료와 최종 정상 Stop이 통과했다. 코어 강제를 순서 전이·완료 근거·배정 정리·writer 조정으로 한정했다. 셸 분류·터미널 입력 차단·phase별 도구 권한·bypass 스위치를 제거했다. 독립 리뷰에서 중단된 세션/executor 복구·편집기의 literal 경로·리뷰 freshness·필수 독립 리뷰·결과 출처를 재검증했다. 빌드한 wheel은 소스 checkout 접근을 막은 독립 import 검사와 세 종류 저장소의 설치·재설치·제거 검사를 통과했다. 실제 setup bootstrap의 사용자 파일 보존과 자기 설치 검사도 통과했다.

이전 고정 후보의 실제 Claude 관측에서 phase 순서 위반 거부와 미완료 Task의 Stop 거부 뒤 계속 실행을 확인했다. 이전 고정 후보에서는 네이티브 서브에이전트 생성·원문 읽기·출처가 표시된 리뷰·네이티브 handback·상위 수락·phase 순차 완료까지 확인했다. 실패한 handback 시도와 성공한 재시도는 같은 Task ID 아래 별도 시도로 보존했다.

실제 Codex 검증은 격리된 0.2.3 후보에 대해 명시적으로 승인받은 프로젝트·훅 신뢰 설정으로 수행했다. 네이티브 훅 이벤트와 저장된 Task 상태를 각각 읽어 결과를 확인했다. 운영 환경의 설치·활성화는 이 후보 검증 및 공개 릴리스와 별개다.

## 테스트 교체

삭제된 내부 구조에 결속된 테스트는 구현과 함께 폐기한다. 필요한 동작은 `tests/core`에서 검사한다. Task·phase·Stop·재작업, 트랜잭션 revision, 원문·승인 출처, 쓰기 소유권, 세 위임 선택, 실제 검사 결과, 리뷰 freshness, 네이티브 반환, 기존 데이터 보존이 대상이다. 설치·업데이트·보고·전송·학습 테스트는 유지한다. 전체 테스트와 소스 무결성 검사가 릴리스 기준이며 일부 검사 통과는 부분 근거다.

0.2.2 wheel은 독립 import, 세 저장소의 설치·재설치·제거, 실제 setup·자기 설치 검증을 통과했다. 실제 Claude root 세션은 미완료 Task 상태에서 정상 Stop을 한 번 시도해 네이티브 거부를 받았고, 요청한 원문을 읽은 뒤 같은 Task를 완료했다. 셸 권한 분류 없이 완료 책임이 유지됨을 확인한 결과다. 후속 0.2.3 Codex 관측은 위에서 설명한 승인된 후보를 검증하며 이미 실행 중인 운영 앱의 활성화를 뜻하지 않는다.

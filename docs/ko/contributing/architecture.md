# 프로젝트와 에이전트를 연결하는 구조

Neurath는 기존 Git 프로젝트에 공통 작업 규칙과 지속적인 협업 상태를 더한다. 대상 프로젝트의 애플리케이션, 의존성, 빌드 방식은 그대로 사용한다. Claude Code와 Codex가 실제 세션과 도구를 제공하고, Neurath는 그 세션을 프로젝트 지침, 작업 공간 소유권, 명시적인 작업 기록에 연결한다.

구조를 이해할 때는 프로젝트에 파일을 설치하는 과정, 실제 호스트 호출자를 확인하는 과정, 확인된 작업 상태를 저장하는 과정을 나누어 본다. 이 구분이 있어야 설치 파일은 정상인데 호스트가 아직 로드하지 않은 경우와, 세션은 정상인데 다른 세션이 작업 공간을 소유한 경우를 각각 진단할 수 있다.

## 구성 요소의 책임

| 책임 | 구현 | 지켜야 할 계약 |
| --- | --- | --- |
| 독립 실행 자산 제공 | `src/neurath/_assets`, `resources.py`, `manifest.json` | 배포 자산을 Neurath가 직접 소유하며 다른 저장소를 빌드 입력으로 사용하지 않는다. |
| 기존 프로젝트 설정 보존 | `install/projection.py`, `install/transaction.py` | 정확한 변경을 계획하고 원본을 다시 확인한 뒤 교체 이력과 복원 자료를 남긴다. |
| 실제 호출자 확인 | `hosts/identity.py`, `hosts/hooks.py` | 호스트 세션, 현재 턴, 부모 관계, 해당 도구 호출을 검증한다. 호출자가 적은 문자열로 권한을 만들 수 없다. |
| 범위가 정해진 작업 제공 | `runtime/task_schema.py`, `runtime/*_tasks.py`, `agents/mcp.py` | 이름이 있는 도구마다 허용 입력과 구조화된 결과를 정의한다. |
| 실행 상태 관리 | `SessionKernel`, `StateHandle` | 세션, 참여자, 턴, 워크플로, 위임의 식별자를 구분하고 오래된 접근을 거부한다. |
| 이전 소유자의 쓰기 차단 | `WorktreeRegistry` | 해당 워크트리의 현재 소유권, 세대 번호, fencing token으로 변경 권한을 확인한다. |
| 사용자 요청 보존 | `TaskLedger`, `TaskService` | 측정 가능한 작업을 추가하고 소유자의 결과를 기록하며 Stop에서 목록을 원자적으로 확인한다. |
| 명시적인 스킬 계약 실행 | `phase_runner.py`, `AdaptiveControlAuthority`, `EvaluationLoop` | 단계 근거와 독립 검토를 정확한 후보 및 리비전에 묶는다. |
| 독립 세션 간 협업 | `agents/store.py`, 전달 및 제공자 모듈 | 할당, 실행, 전달, 수신 확인, 결과 소비를 각각 추적한다. |
| 프로젝트 맥락 유지 | 프로젝트 메모리, enclave, 학습 모듈 | 출처가 있는 사실을 제한된 양으로 회상하며 현재 사용자 지시를 대체하지 않는다. |

클래스 이름을 제외한 표의 상대 경로는 `src/neurath/` 아래를 가리킨다. 실행 클래스는 독립 배포되는 `src/neurath/_assets/scripts/` 트리에 있다.

## 일반 요청이 처리되는 과정

1. 호스트가 세션을 시작하거나 재개한다. 훅 어댑터가 실제 세션을 검증해 현재 참여자를 등록한다. 새 사용자 요청은 프롬프트 수신 근거로 남는다.
2. 에이전트가 프로젝트 연결 설정과 소유권을 확인한다. 공통 저장소는 연결된 워크트리를 식별하고, 변경할 워크트리에는 별도의 소유권을 적용한다.
3. `task_define`으로 측정 가능한 작업을 등록한다. 정의에는 요청 출처, 완료 조건, 의존 관계가 남으며 반환된 ID와 리비전이 실제 기록을 식별한다.
4. 일반 네이티브 도구로 편집과 검사를 수행한다. 요청된 스킬이나 검토 계약이 요구할 때 단계 워크플로를 사용한다.
5. 소유자가 구체적인 참조와 요약을 담아 `task_resolve`로 각 결과를 기록한다. 이 기록의 보증 수준은 인증된 소유자 보고인 `assurance=agent-report`다.
6. Stop은 루트 턴을 닫는 SQLite 트랜잭션 안에서 최신 작업 목록을 확인한다. 동시에 추가된 작업이 완료 판단에서 사라지지 않는다.

호스트의 TODO 화면은 이 목록을 표시한다. 화면을 갱신하는 것으로 작업 결과를 확정할 수는 없다. 정확한 표시 규칙과 복구 방식은 [작업과 TODO 계약](task-todo-contract.md)에 설명한다.

작업 기록은 [주기적 목표 환기](runtime-lifecycle.md)의 맥락으로도 쓰인다. 루트 에이전트가 원래 목적과 완료 조건을 기준으로 접근을 돌아보도록 돕되 별도의 판정 주체를 만들지는 않는다. 다른 제공자가 중단된 일을 이어갈 때는 [수신자 주도 승계](provider-continuity.md)가 같은 공유 데이터베이스에서 미완료 작업과 worktree 소유권을 원자적으로 넘기고 승계된 원본의 재실행을 차단한다.

## 저장 공간 공유와 책임 구분

변경 가능한 실행 상태는 Git 공통 디렉터리에서 구한 제어 루트 아래 `.neurath/local/runtime.sqlite3`에 저장한다. 같은 저장소의 연결된 워크트리는 이 저장소를 공유한다. 별도로 복제한 저장소나 다른 컴퓨터까지 자동으로 공유하는 것은 아니다.

작업 결과와 세션 종료 판단처럼 서로 일치해야 하는 변경은 SQLite 트랜잭션으로 묶는다. 네임스페이스, 도메인별 직렬화 규칙, 기록 리비전, 해시를 통해 작업, 세션, 메시지, 소유권, 메모리의 의미를 구분한다. 같은 데이터베이스에 있다는 이유로 메모리가 실행 근거가 되거나 동료 메시지가 사용자 지시가 되지는 않는다.

설치 계획, 트랜잭션 복구 기록, 복원용 원본, 일부 비공개 프로세스 자료는 각 기능의 파일 저장 방식을 유지한다. 실행 도메인 상태가 SQLite에 모였다는 이유로 모든 비공개 파일을 데이터베이스로 옮기지 않는다. 이전 상태 경로는 마이그레이션 입력이며 현재 저장 구조가 아니다.

데이터베이스는 비공개 파일 권한을 제한하고 저장 경로의 심볼릭 링크를 거부한다. 이전 자료를 가져올 때는 원본 해시도 고정한다. 이전 런타임이 가져온 자료를 다시 변경하면 어느 쪽이 맞는지 임의로 선택하지 않고 불일치를 차단한다. 이전 쓰기 주체의 종료와 복구 절차는 [실행 수명주기](runtime-lifecycle.md)에 있다.

## 배포와 호스트 활성화

빌드는 manifest에 해시가 선언된 독립 자산을 포함한다. 설치는 대상 프로젝트의 관리 지침, 스킬 연결, 훅, 실행기를 만든다. 실행 코드는 배포 내용으로 선택한 지속적인 전용 환경에서 동작하며 개발용 `.venv` 및 대상 프로젝트 환경과 분리된다. 한 프로젝트를 업데이트해도 다른 프로젝트의 런타임까지 자동으로 바뀌지 않는다.

설치 계획은 대상 경로, 변경 전후 바이트, 권한, 링크를 정확히 고정한다. 적용 시 잠금을 잡고 이 입력을 다시 확인한 뒤 교체 기록을 남긴다. 충돌한 사용자 변경은 보존해 해결할 수 있게 한다. 복원은 현재 기본값으로 재구성하는 대신 기록된 원본과 보존된 런타임을 사용한다.

설치 위치 검사는 파일과 링크를 확인하고, 프로토콜 검사는 격리된 훅 프로세스를 실행하며, 실제 활성화 검증은 호스트가 설치된 훅과 도구를 호출하는 것을 관찰한다. 각 근거의 범위는 [호스트 통합](hosts.md)과 [검증](validation.md)에서 다룬다.

## 맥락과 협업의 경계

프로젝트 메모리는 세션 간 이력을 보관하고 enclave는 제한된 최신 세션 사실을 보관한다. Graphify는 현재 소스로 확인할 관계 정보를 제공한다. 학습 전략과 명시적으로 승인된 프로젝트 규칙은 각각의 반영 조건을 가진다. 세션 시작 시 메모리 주입은 최대 3,000바이트이며 명시적 맥락 조회의 기본값은 12,000바이트다. 학습 지침은 별도로 최대 12개 규칙, 6,000바이트까지다.

직접 자식은 실제 호스트의 부모 관계가 확인되어야 위임된 평가 역할을 가질 수 있다. 다른 제공자의 동료 세션은 유용한 검토를 반환해도 동료 역할을 유지한다. 제공자 경로는 지원되는 실행 선택을 설명하고, 실행과 전달은 이후 실제로 관찰해야 한다. 자세한 권한 상속, 모델 계획, 전달 복구 계약은 [모델 계획](model-planning-mcp.md)과 [협업](collaboration-contract.md)에 있다.

## 변경 위치 선택

배포 동작은 설치 결과인 `.agents/skills`나 `.neurath/rules`가 아니라 `src/neurath/_assets`에서 바꾼다. 호출 허용 판단과 실행 연결은 해당 호스트·런타임 모듈에서 수정하고 스키마를 실제 작업과 일치시킨다. 새 설치 동작은 먼저 실패하는 설치 테스트로 정의한다. 실행 자산을 수정했다면 manifest 갱신, 필수 검사, 빌드, 자기 설치 업데이트를 각각 수행하고 확인한다.

구조 변경은 [설계 원칙](design-principles.md)으로 판단하고, 담당 스킬과 도구는 [기능 지도](capability-map.md)에서 찾는다. 개발 절차는 [개발 안내](index.md)를 따른다.

# 기억 실행 참조

**대상 독자: 코딩 에이전트와 기여자.** 아래 명령은 승인된 작업을 수행하는 에이전트의 실행 참조입니다. 사용자는 [사용 안내](../usage/index.md)에 따라 목표를 요청하며, 이 명령을 직접 실행할 필요가 없습니다.

Neurath는 Claude Code와 Codex의 대화가 바뀌어도 프로젝트의 작업 기록을 이어줍니다.
작업에서 얻은 교훈과 검증한 실행 방법은 다음 세션의 작업 지침에 반영합니다.
설치된 훅이 활성화되어 있어야 동작합니다.

[English](../../en/contributing/memory-reference.md)

## 별도 지시 없이 동작합니다

처음에 훅을 활성화하고 프로젝트 검사 명령을 연결해 두면, 평소처럼 작업을 요청하면 됩니다.
매번 기억·회고·학습·후보 검증을 지시하거나 다음 세션에서 학습을 켤 필요가 없습니다.
현재 에이전트가 일반 도구로 작업하고, 훅과 실제 실행 기록이 학습 과정을 이어갑니다.

종료할 때 검증하지 않은 개선 후보나 실제로 사용한 시험 전략이 있으면, 인계가 이미 저장되어
있어도 훅이 프로젝트 검사를 요청합니다. 실제 검사 결과가 기록되어야 이 요청이 처리됩니다.
같은 근거에 대한 실패한 검사를 자동으로 반복하지는 않습니다. 새 실패·복구 근거가 생기면
철회했던 전략도 다시 후보로 삼아 검증할 수 있습니다.

현재 사용자가 검사를 금지했거나 기존 권한·도구로 실행할 수 없다면 에이전트가
`learning defer --reason "구체적 사유"`로 미검증 상태와 사유를 남깁니다. 검사를 통과한 것으로
처리하지 않습니다. 검사 명령이 연결되지 않은 경우에도 후보로 남습니다. 학습을 시작하기 위해
매번 허락을 구하거나, 검사를 느슨하게 바꾸거나, 권한을 넓히지는 않습니다.

자율 동작은 작업 중인 세션 안에서 수행합니다. 에이전트가 실행 중이지 않을 때 새 세션이나
백그라운드 작업을 만들거나, Neurath 소스 코드를 저절로 수정하는 기능은 아닙니다.

## 무엇을 기억하나요?

새 세션을 시작하거나 요청을 보내면 같은 Git 저장소의 목표, 결정, 인계, 실행 기록을
찾아 에이전트에게 전달합니다. 연결된 worktree는 저장소를 공유하지만, 별도로 복제한
저장소나 다른 컴퓨터의 기록까지 동기화하지는 않습니다.

요청은 작업을 시작할 때 저장합니다. 명령 실행 결과는 현재 호스트가 등록한 해당 세션의
기록에서 수집합니다. 에이전트는 작업 결과, 결정, 남은 일, 실패나 피드백에서 얻은 교훈을
인계 기록으로 남깁니다. 명령을 사용한 턴이 끝날 때 현재 요청의 인계가 없으면 종료 훅이
작성을 요청합니다. 컨텍스트 압축 전과 세션 종료 때에도 마지막으로 확인할 수 있는
사용자에게 보여 준 답변과 작업 상태를 보관합니다.

```sh
.neurath/run memory recall --query "작업 기록 내보내기"
.neurath/run memory checkpoint --summary "CSV 완료, PDF 미구현" \
  --decision "파일명은 UTF-8 유지" --next-step "PDF 내보내기 구현" \
  --lesson "프로젝트 도구 환경에서 검사를 실행할 것" --status paused
```

강제로 중단해도 이미 저장한 기록은 남습니다. 다만 관측하거나 저장하기 전에 사라진 내용은
복구할 수 없습니다. 과거 대화 전체를 매번 읽히는 대신, 현재 요청과의 관련성·미완료 인계·
최근 기록을 기준으로 최대 12개, 12,000바이트 안에서 고릅니다. 더 필요한 내용은 조회 명령으로
찾습니다. 입력과 답변, 수집할 호스트 기록에도 크기 제한이 있어 모든 대화를 그대로 보존하는
기능은 아닙니다. 프롬프트 길이를 줄이기 위해 저장된 이력을 삭제하지는 않습니다.

인계는 출처를 표시한 에이전트의 보고입니다. 과거 지시가 현재 사용자 지시보다 우선하지
않으며, 다른 세션의 기록을 읽었다고 작업 소유권까지 넘어오지 않습니다. 인계에
`completed`라고 적어도 실제 workflow 완료 검증을 대신할 수 없습니다.

## 사용할수록 무엇이 달라지나요?

**회고와 교훈**은 다음 세션의 참고 자료가 됩니다. 에이전트가 현재 작업과 파일을 확인해
적용합니다. 보고에 적힌 교훈을 검증된 사실이나 전역 정책으로 자동 취급하지는 않습니다.

**명령 실행 방법**은 실제 관측과 검증을 거쳐 학습합니다. 예를 들어
`pytest tests/test_export.py`가 실패하고 `uv run pytest tests/test_export.py`가 성공했다면
같은 작업을 수행하는 실행 방법의 개선 후보가 됩니다. 다른 테스트가 통과한 것은 근거가 아닙니다.

1. 실패와 성공한 대안을 같은 세션에서 관측해 후보를 만듭니다.
2. 해당 세션의 프로젝트 검사가 통과하면 다음 세션에 시험 적용할 전략으로 제공합니다.
3. 다른 세션이 그 전략을 전달받고, 동일한 명령을 성공적으로 실행하고, 같은 검증 계약의
   프로젝트 검사까지 통과하면 유지할 전략으로 전환합니다.
4. 이후 해당 명령이 실패하거나, 그 전략을 사용한 뒤 프로젝트 검사가 실패하면 자동 철회합니다.

전환마다 근거와 이력이 남습니다. 실제로 전달하지 않은 전략에는 시험 적용 근거를 부여하지
않으며, 전달할 전략도 최대 12개, 6,000바이트로 제한합니다. 철회한 전략은 더 이상 학습 지침으로
제공하지 않습니다. 과거 보고는 과거 이력으로 남습니다.

```sh
.neurath/run verify check
.neurath/run learning status
.neurath/run learning history <lesson-id>
```

검증은 실제 실행 결과, 검사 설정, 변경 전후 저장소의 일치 여부를 확인합니다. 명령의
표준 출력에 적힌 “성공”이나 `exit_code` 값을 종료 결과로 믿지 않습니다. 시험할 명령은
그대로 단독 실행해야 합니다. 뒤에 `echo`를 붙이거나 여러 명령을 연결하면 실패가 가려질 수
있어 원래 명령의 성공 근거로 인정하지 않습니다.

프로젝트의 `check`가 연결되지 않았다면 후보로 남습니다. 기존 검증 계약이 바뀌면 해당
실행 지침을 무효화합니다. 다른 worktree가 별도의 검사 설정을 쓴다는 이유만으로 원래
worktree의 전략까지 폐기하지는 않습니다.

## 저장 위치와 범위

Git 공통 저장소의 `.neurath/local/memory/project.sqlite3`에 저장합니다. Git과 배포본에는
포함하지 않습니다. 동시 쓰기는 트랜잭션으로 처리하고, 같은 출처의 재전달은 중복 저장하지
않습니다. 같은 출처를 다른 내용으로 바꾸는 재전달은 거부합니다.

알려진 자격 증명 패턴은 저장 전에 가립니다. 모든 비밀을 자동 판별할 수 있는 것은 아니므로
인계에 비밀 값을 넣지 마세요. 비공개 추론과 thinking 내용은 저장 대상에서 제외합니다.

학습으로 달라지는 것은 프로젝트의 작업 기억과 지원하는 실행 전략입니다. Neurath의 소스나
프로젝트 정책 파일을 자동 수정하거나, 세션이 없을 때 백그라운드에서 작업하거나, 임의 조언을
검증된 정책으로 바꾸는 기능은 아닙니다. 더 넓은 코드·하네스 개선은 기존 구현·검토·검증
절차로 진행합니다. 학습 지침이 명령 실행, 보호 해제, 공개 배포 권한을 부여하지도 않습니다.

공유 기억은 활성 훅을 사용하는 루트 세션에 전달합니다. 자식 에이전트는 기존 위임 규칙을
따릅니다. 중단된 세션의 작업을 새 대화에서 읽을 수 있어도, 수정하기 전에 유효한 소유권을
확인해야 합니다.

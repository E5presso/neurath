# 다음 세션으로 이어지는 작업 문맥

프로젝트 메모리는 이전 결정, 관찰 결과, 남은 일을 다시 찾는 데 쓰입니다. 기록에는 출처와 작성 주체가 남지만 실행 권한이 생기지는 않습니다. 현재 요청과 소스, 현재 작업 공간 소유권을 기준으로 행동해야 하며, 과거 승인이나 완료된 인계 기록을 새 호출자의 권한으로 사용할 수 없습니다.

## 보존하려는 정보에 맞는 수단

| 목적 | 인터페이스 | 기록의 의미 |
| --- | --- | --- |
| 과거 결정과 작업 찾기 | `memory_recall` | 출처를 포함한 프로젝트의 세션 간 이력 |
| 다음 작업자에게 인계하기 | `memory_checkpoint` | 요약·결정·다음 단계·교훈을 담은 에이전트 보고 |
| 현재 세션의 최신 사실 유지 | `enclave_read`, `enclave_set`, `enclave_delete` | 크기가 제한되고 digest로 동시 변경을 확인하는 작업 상태 |
| 명령 복구 지침 확인 | `learning_status`, `learning_pending`, `learning_history` | 관찰된 전략과 검증 이력 |
| 반복 지식을 프로젝트 규칙으로 반영 | `memory-to-rules` 스킬 | 별도의 검토와 승인을 거치는 규칙 변경 |
| 소스 관계 탐색 | `graphify` 스킬 | 현재 소스로 결론을 확인해야 하는 탐색 그래프 |

변경 가능한 상태는 Git 공통 관리 경로에서 정한 제어 루트 아래의 `.neurath/local/runtime.sqlite3`를 사용합니다. 연결된 worktree는 프로젝트 메모리를 공유하지만 별도 clone이나 컴퓨터까지 자동 동기화하지는 않습니다. 메모리와 세션 상태 등은 각 도메인 namespace로 구분합니다. 설치 계획, 원본 백업, 복구 journal에는 별도의 비공개 파일 저장소가 유지됩니다.

## 자동 수집과 회상 범위

확인된 루트 호스트 이벤트가 사용자 요청과 실제 관찰된 명령을 저장합니다. `UserPromptSubmit`은 같은 턴에 추가된 지시도 기록합니다. 도구 이벤트에는 관찰된 명령과 호스트가 제공한 실행 결과가 남습니다. `PreCompact`, `Stop`, `SessionEnd`에서는 저장 대상인 최근 에이전트 발화를 `agent-report`로 남길 수 있고, workflow 상태는 `reference-only`로 기록합니다. 비공개 추론 채널은 수집하지 않습니다.

| 문맥 제공 경로 | 제한 | 시점 |
| --- | --- | --- |
| 자동 프로젝트 메모리 주입 | 3,000바이트 | `SessionStart`에서만 |
| 명시적 `ProjectMemory.context` 렌더링 | 기본 12,000바이트 | 내부에서 명시적으로 문맥을 요청할 때 |
| 학습한 실행 지침 | 최대 12개 규칙, 6,000바이트 | 세션 시작 시 별도로 추가 |
| 이름 있는 회상 도구 | `limit` 기본 12, 범위 1–100 | `memory_recall` 호출 시 |

`UserPromptSubmit`은 메모리 블록을 다시 주입하지 않습니다. 명시적 회상의 기본값 12,000바이트를 시작 시 자동 주입량으로 설명하면 안 됩니다. 관찰하거나 저장하지 못한 대화와 작업은 중단 후 복원할 수 없습니다. 이미 저장된 기록은 마지막 checkpoint가 없어도 남습니다.

다음 입력으로 `memory_recall`을 호출할 수 있습니다.

```json
{"query":"내보내기 검증에서 남은 작업","limit":8}
```

관련 결과의 출처와 세션을 읽고, 현재 코드와 검사를 확인한 뒤 과거 결정을 적용합니다. 흔한 자격 증명 패턴은 값 단위로 가려지지만, 메모리에서 가져온 내용을 외부에 공개하려면 의미를 검토해 사적인 정보가 없는지 확인해야 합니다.

## 맥락을 가져와 미완료 작업을 승계하기

`memory_pull`은 일반 기억 조회와 함께 사용하는 수신자 주도의 작업 승계 도구입니다. `list`로 원본 세션을 찾고, `preview`로 정확한 원본의 변경 불가능한 스냅샷을 만들며, `read`로 저장된 내용을 나누어 읽습니다. 미완료 작업과 worktree 소유권은 원본 실행이 정리된 뒤 `adopt`에서만 넘깁니다. 원본의 마지막 인계 기록이나 맥락 전송은 필요하지 않습니다.

스냅샷은 SQLite의 작업·기억·동료 결과에, 등록된 네이티브 transcript JSONL의 사용자에게 보이는 내용을 보충합니다. 출처와 원본 위치를 유지하고 비공개 추론과 인식된 자격 증명은 제외합니다. 저장된 글은 참고 자료이며 관측하지 못한 도구 결과의 증명이 아닙니다. 제공자가 저장하지 않은 데이터까지 완전히 복구할 수는 없습니다.

입력, 페이지 읽기, 실행 정지 확인, 원자적 승계, 원본 재개 차단은 [제공자 간 작업 승계](provider-continuity.md)에 설명합니다. 복구 경험을 가져왔다고 활성 학습 지침이 되는 것은 아닙니다. 아래의 원본 세션 및 독립 세션 검사 조건을 그대로 적용합니다.

## 다음 행동이 분명한 인계 기록

아래는 `memory_checkpoint` 입력입니다. 예시의 내보내기 검증은 가상의 대상 프로젝트 작업이며 Neurath의 내보내기 기능을 뜻하지 않습니다.

```json
{
  "summary":"빈 컬렉션의 내보내기 검증을 수정했으며 통합 사례 확인이 남았습니다.",
  "key":"export-validation-handoff-1",
  "decisions":["기존 공개 응답 형식을 유지합니다."],
  "next_steps":["수정된 직렬화기로 승인된 통합 사례를 실행합니다."],
  "lessons":["빈 컬렉션은 실제 실행 결과를 따로 확인해야 합니다."],
  "status":"paused"
}
```

`summary`와 `key`는 필수입니다. 세 목록은 기본값이 빈 배열이고 각각 최대 32개 항목을 받습니다. `status`는 `active`, `paused`, `completed`, `blocked` 중 하나이며 기본값은 `paused`입니다. 같은 작업을 재시도할 때는 안정적인 키를 유지합니다. `completed` 인계도 소유자의 보고입니다. 작업 원장 해결, 소유권 해제, 검사 인증, 명시적 검토 종료를 대신하지 않습니다.

현재 세션의 최신 사실은 먼저 `{}`로 `enclave_read`를 호출해 읽습니다. 변경·삭제 시 반환된 digest를 `expected_digest`로 전달합니다. `enclave_set`에는 `fact_key`, `value`, `expected_digest`, `key`가 필요합니다. digest 충돌이 나면 다시 읽고 동시 변경을 조정해야 하며 예상 값을 추측해서 덮어쓰면 안 됩니다.

## 명령 복구 경험의 검증

학습은 같은 작업과 선택 대상을 유지한 실패·복구 실행을 연결합니다. `pytest tests/test_export.py`를 `uv run pytest tests/test_export.py`로 바꾸는 것은 실행 환경을 바로잡은 같은 검사일 수 있습니다. 다른 테스트를 골라 통과시키는 것은 원래 실패의 복구 증거가 아닙니다.

1. 관찰된 실패와 같은 작업의 성공한 대안으로 후보를 만듭니다.
2. 원본 세션에서 설정된 프로젝트 검사가 통과하면 시험 지침으로 사용할 수 있습니다.
3. 다른 세션이 해당 지침을 실제로 전달받고 정확한 복구를 수행한 뒤 같은 검사를 통과해야 활성 지침으로 승격합니다.
4. 복구 명령이나 이후 프로젝트 검사가 실패하면 시험·활성 지침을 철회합니다. 복구를 처음 관찰한 worktree의 검증 계약이 바뀌면 지침을 `stale`로 처리하지만, 다른 연결 worktree가 다른 검사를 쓴다는 이유만으로 폐기하지는 않습니다.

같은 실패와 성공한 복구가 새로 관찰되면 이전 지침 노출 기록을 지우고 `reverted` 또는 `stale` 전략을 다시 `candidate`로 돌려 검증합니다.

성공 판단에는 네이티브 호스트가 제공한 프로세스 결과를 사용합니다. 명령이 출력한 `exit_code: 0` JSON, 복사한 성공 보고, 알 수 없는 결과, 다른 테스트의 통과는 성공 근거가 아닙니다. 독립 명령의 원래 종료 코드는 보존합니다.

검사가 없거나 실행할 수 없거나 금지되어 있다면 미검증 상태와 사유를 남깁니다. `learning_pending`으로 대기 중인 검증을 확인하고 `learning_defer`에 `reason`과 안정적인 `key`를 전달해 보류할 수 있습니다. 새 근거 없이 실패한 검사를 반복해도 검증이 추가되지 않습니다. `learning_history`에는 반환받은 `strategy_id`를 넣어 진행 이력을 확인합니다.

학습은 활성 세션에서 동작합니다. 정책·권한을 수정하거나 무인 모델 세션을 실행하지 않습니다. 프로젝트 규칙 변경은 별도 `memory-to-rules` 작업으로 진행합니다.

## 구현과 검사 근거

수집과 권한 경계는 [메모리 훅](../../../src/neurath/memory/hooks.py), [프로젝트 메모리](../../../src/neurath/memory/store.py), [대화 기록 동기화](../../../src/neurath/memory/transcript.py), [학습](../../../src/neurath/memory/learning.py)에 있습니다. 세션 내 최신 상태의 동시 변경은 [EnclaveStore](../../../src/neurath/_assets/scripts/agent_harness/enclave_store.py)가 처리합니다.

[메모리 테스트](../../../tests/test_project_memory.py)는 연결된 worktree, 출처 재처리 충돌, 크기 제한, 비밀 가리기, checkpoint 없는 복원을 다룹니다. [학습 테스트](../../../tests/test_learning.py)는 지침 노출, 다른 세션의 승격, 잘못되거나 위조된 결과, 보류, 계약 변경, 철회를 검사합니다. 이 검사의 범위와 실제 호스트 활성화 관찰은 [검증 안내](validation.md)에서 구분합니다.

규칙 반영은 [스킬 참조](skills-reference.md), 세션·소유권 복구는 [에이전트 참조](agents-reference.md)를 참고합니다.

# 조사 내용을 기억하고 유용한 교훈 검증하기

[English](../../en/contributing/memory-reference.md) · [기여자 시작 안내](index.md)

저장 필터 조사를 다시 시작하는 에이전트는 저장 API에서 확인한 내용, 아직 설명하지 못한 불러오기 동작, 남은 검증을 찾아볼 수 있어야 합니다. Neurath는 출처가 있는 작업 기록을 보존하고 필요한 일부를 다음 세션에 제공합니다. 일부 명령 복구 사례는 이후에도 믿고 참고할 수 있는지 검증해 안내로 제공합니다.

이 문서는 일반 기억과 학습을 설명합니다. 미완료 작업과 쓰기 소유권을 다른 루트에 넘기려면 [별도의 pull·인수 절차](provider-continuity.md)를 사용합니다.

## 저장되는 정보와 지금 보이는 정보

**세션(session)**은 네이티브 호스트의 대화 실행입니다. **기억(memory)**은 프로젝트가 그 대화들에서 보존한 정보이고, **컨텍스트(context)**는 지금 에이전트에게 보여 주는 선택된 정보입니다. **체크포인트(checkpoint)**는 에이전트가 명시적으로 작성한 인계 보고입니다. **트랜스크립트(transcript)**는 일반 조회보다 더 자세한 가시적 기록을 담을 수 있는 호스트의 JSONL 이력입니다.

프로젝트 기억은 Git common directory로 선택한 SQLite 런타임 데이터베이스에 저장됩니다. 같은 로컬 프로젝트의 연결된 워크트리와 Claude·Codex 세션이 공유하며, 독립 복제본이나 다른 컴퓨터에는 자동으로 전파되지 않습니다. 각 기록에는 호스트, 세션, 이벤트 식별자, 순서, 종류, 관련 메타데이터가 붙습니다. 기억과 현재 정보가 다르면 현재 사용자 지시, 현재 소스, 현재 소유권이 우선합니다.

확인된 훅은 `UserPromptSubmit`에서 사용자 요청을, 도구 이벤트에서 명령과 실제 프로세스 결과를, `PreCompact`·`Stop`·`SessionEnd`에서 적절한 에이전트·워크플로 보고를 기록합니다. 보고는 에이전트 보고로 남습니다. 명령이 `exit_code`를 주장하는 JSON을 출력해도 네이티브 실행 메타데이터가 되지는 않습니다. 비공개 추론은 제외하고 알려진 자격 증명 형태는 저장 전에 가립니다. 패턴에 따른 처리이므로 비공개 프로젝트 내용은 여전히 공개 보고가 아닌 로컬 기록에 두어야 합니다.

`SessionStart`에서는 선택된 기억 컨텍스트가 최대 3,000바이트 주입됩니다. 학습된 안내는 별도로 최대 6,000바이트, 규칙 12개까지 제공됩니다. 일반 기억 조회는 Newsroom 기사 본문을 가져오지 않습니다. 관련 기사는 에이전트가 명시적으로 읽고 출처를 유지합니다.

## 필요한 기억을 찾거나 인계 내용 남기기

`memory_recall(query, limit)`는 관련 프로젝트 이력을 찾습니다. 기본 12개, 최대 100개입니다. 명시적 컨텍스트 렌더러의 기본 한도는 12,000바이트로, 자동 SessionStart 주입의 작은 한도와 다릅니다. 반환된 관측의 출처와 시점을 읽고 바뀔 수 있는 사실은 다시 확인합니다.

`memory_checkpoint(summary, key, decisions, next_steps, lessons, status)`는 인계 내용을 저장합니다. 요약과 키는 필수이고 목록 기본값은 빈 배열입니다. 각 목록은 비어 있지 않은 문자열을 최대 32개 받습니다. `status`는 `active`, `paused`, `completed`, `blocked`이며 기본값은 `paused`입니다. 재시도 결과가 불확실하면 같은 키와 동일한 내용을 사용합니다.

필터 문제에서는 API가 선택값을 저장한다는 사실, 불러오기 경로 조사가 남았다는 사실, 다음 검증에서 새 페이지 로드를 확인해야 한다는 내용을 담으면 유용합니다. 실제 근거 참조가 있으면 함께 남깁니다. `completed` 체크포인트는 에이전트가 완료라고 보고했다는 뜻입니다. 작업 해결, claim 해제, 검토 확정, 일반 완료 판정에 추가되는 별도 표가 아닙니다.

의미 있는 작업 뒤 인계가 필요하면 런타임이 체크포인트 작성을 요청할 수 있습니다. 실제 요약은 에이전트가 제공해야 하며 요청 자체로 남은 일이 완료되지는 않습니다. 마지막 요약을 쓰지 못했어도 pull은 이미 저장된 SQLite와 등록된 트랜스크립트를 사용할 수 있습니다.

## 회고가 바로 검증된 안내가 되지는 않음

“프로젝트 환경을 통해 테스트를 실행하자”는 에이전트가 `lessons`에 남길 수 있는 회고입니다. 명령 복구를 학습하려면 더 강한 근거가 필요합니다. 필터 조사 중 동일한 테스트 선택자를 실행했지만 실행기가 없어 실패했고, 프로젝트 환경을 통해 같은 작업을 실행해 성공했다고 가정해 봅시다. 구현 테스트의 예는 `pytest -q` 다음 `uv run pytest -q`입니다. 실제 프로젝트에서는 그곳에서 관측한 명령과 선택자를 그대로 사용해야 합니다.

학습 엔진은 같은 세션·워크트리·작업 계열·검증 계약 안에서 실패와 수정된 성공 명령을 연결합니다. 다른 테스트 실행, 성공 문구 출력, 관계없는 명령의 성공, 알 수 없는 프로세스 결과는 그 연결을 만들지 못합니다.

| 상태 | 도달 조건 | 이후 에이전트에게 제공되는 내용 |
| --- | --- | --- |
| `candidate` | 해당하는 명령 실패 후 대안 명령의 성공을 관측. | 아직 승격된 안내는 제공하지 않음. |
| `trial` | 원본 세션에서 설정된 프로젝트 검사가 완전하고 일치하는 근거로 통과. | 다른 세션의 독립 사용을 기다리는 시험 안내. |
| `active` | 다른 세션에 실제 안내가 전달되고, 정확히 같은 복구가 성공하며, 일치하는 프로젝트 검사도 통과. | 검증 계약이 유효한 동안 범위를 한정한 검증 안내. |
| `reverted` | 복구가 다시 실패하거나 관련 trial·active 사용 뒤 검사가 실패. | 해당 안내를 더 이상 제공하지 않음. |
| `stale` | 원래 워크트리의 검증 계약이 변경됨. | 새 근거가 생기기 전까지 기존 안내를 보류. |

**노출(exposure)**은 특정 교훈이 세션에 실제 전달된 안내에 포함되었다는 뜻입니다. 저장되어 있거나 목록에 표시된 것만으로 시험 사용 근거가 되지는 않습니다. 네이티브 종료 결과를 관측할 수 있도록 복구 명령을 바꾸지 않고 독립된 명령으로 실행해야 합니다. 원래 세션에서 다시 성공하거나 안내를 받은 적 없는 다른 세션에서 성공해도 trial을 승격할 수 없습니다.

완전한 검사 receipt에는 설정된 검증기의 digest, 워크트리 fingerprint, 출력 digest, 실제 종료 코드, 시간 초과 여부, 통과 결과가 연결됩니다. 근거가 누락되거나 맞지 않으면 candidate를 trial로 올릴 수 없습니다. 다른 연결 워크트리에서 한 검사가 원래 워크트리의 안내를 임의로 무효화하지도 않습니다.

## 자동 유지 관리는 실제로 나온 근거를 따라감

Stop에서 검증할 학습이 있으면 승인된 프로젝트 등록 검사와 사실에 근거한 인계를 요청할 수 있습니다. 관계없는 실험이나 무인 모델 세션을 시작하지 않습니다. 검사를 사용할 수 없거나, 금지되었거나, 실패했거나, 보류했다면 미검증 상태를 유지하고 자동 중복 재시도 루프를 만들지 않습니다.

현재 전략은 `learning_status`, 필요한 검사는 `learning_pending`, 전환 이력은 `learning_history(strategy_id)`로 읽습니다. `learning_defer(reason, key)`는 해당 미검증 관측을 지금 검사할 수 없는 이유를 기록합니다. 새로운 적격 근거가 생기면 검사가 다시 필요해질 수 있습니다. 새로 유효한 실패·복구 쌍이 생기면 candidate·reverted·stale 전략을 초기화하고 이전 노출 기록을 지울 수 있습니다. 이후 승격 조건을 다시 만족해야 합니다.

학습이 바꾸는 것은 저장된 안내이며 모델 가중치, 권한, 저장소 규칙은 아닙니다. 회고는 유용한 생각을 기록하고, 실행 학습은 범위가 분명한 복구를 검증하며, `memory-to-rules`는 승인과 개인정보 검토를 거쳐 프로젝트 규칙으로 만들 내용을 제안합니다. 이 스킬의 소스 식별자는 `promote-memory`입니다. 제안만으로 저장소를 수정하지 않습니다.

## 구현과 확인할 회귀 사례

기억 저장·선택은 [src/neurath/memory/store.py](../../../src/neurath/memory/store.py), 훅은 `hooks.py`, 복구 학습은 `learning.py`에 있습니다. 명명된 기억·학습 도구는 [src/neurath/runtime/task_schema.py](../../../src/neurath/runtime/task_schema.py), `maintenance_tasks.py`에 정의됩니다.

[tests/test_project_memory.py](../../../tests/test_project_memory.py), [tests/test_memory_hooks.py](../../../tests/test_memory_hooks.py)는 보존, 공유, 컨텍스트 제한, 훅 관측을 다룹니다. [tests/test_learning.py](../../../tests/test_learning.py)는 candidate → trial → active → reverted, 검증기 변경, 관계없는 명령, 선택자 불일치, 불완전한 receipt, 실제 노출, 검사 보류를 다룹니다. 확인 가능한 구현 사례이며 저장된 교훈을 필터 수정에 적용할 때도 그 교훈의 유효 범위를 먼저 읽어야 합니다.
## 명명 도구 입력 참조

아래는 현재 명명 도구의 입력 계약입니다. 중첩 필드의 필수 조건은 상위 객체나 배열 항목을 제공했을 때 적용됩니다. 스키마 통과는 첫 검사일 뿐이며 네이티브 신원, 소유권, 출처, revision, 각 동작의 전제 조건도 적용됩니다. `_neurath_binding`은 호스트가 제공하므로 임의로 만들지 않습니다.

모든 응답에는 `ok`, `operation`이 있습니다. 성공 호출에는 표준 `result`, 실패에는 `error.code`, `error.message`, `error.state`, `error.retryable`, `error.next_action`이 포함됩니다. `ok`는 해당 동작의 성공만 뜻하며 사용자 목표 달성을 뜻하지 않습니다. 후속 호출에는 반환된 ID와 revision을 유지합니다.

### `memory_recall`

| 필드 | 필수 여부·기본값 | 형식·제한 |
| --- | --- | --- |
| `query` | 선택; 기본 `""` | 문자열; 0–16000 자 |
| `limit` | 선택; 기본 `12` | 정수; 1–100 |

### `memory_checkpoint`

| 필드 | 필수 여부·기본값 | 형식·제한 |
| --- | --- | --- |
| `summary` | 필수 | 문자열; 1–16000 자 |
| `key` | 필수 | 문자열; 1–512 자 |
| `decisions` | 선택; 기본 `[]` | 배열; 0–32 항목; 문자열; 1–16000 자 |
| `next_steps` | 선택; 기본 `[]` | 배열; 0–32 항목; 문자열; 1–16000 자 |
| `lessons` | 선택; 기본 `[]` | 배열; 0–32 항목; 문자열; 1–16000 자 |
| `status` | 선택; 기본 `"paused"` | 문자열: `"active"`, `"paused"`, `"completed"`, `"blocked"` |

### `learning_status`

에이전트가 제공할 입력 필드가 없습니다.

### `learning_pending`

에이전트가 제공할 입력 필드가 없습니다.

### `learning_history`

| 필드 | 필수 여부·기본값 | 형식·제한 |
| --- | --- | --- |
| `strategy_id` | 필수 | 문자열; 1–128 자 |

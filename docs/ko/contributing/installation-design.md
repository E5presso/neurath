# 프로젝트의 작업을 보존하는 설치 구조

[English](../../en/contributing/installation-design.md) · [설치 따라 하기](installation.md)

설치기는 기존 프로젝트의 지침, 훅, 의존성, 후속 편집을 보존하면서 에이전트 하네스를 추가해야 합니다. 이를 위해 정확한 변경 계획을 만들고, 적용 직전에도 대상이 같은지 확인하며, 변경을 되돌리는 데 필요한 정보를 보관합니다. 설치·업데이트·제거·복원은 모두 이 구조를 사용합니다.

## 패키지에서 여러 설치 위치로

실행 코드와 번들 자산의 원본은 `src/neurath` 아래에 있으며, `src/neurath/_assets`는 독립적인 자산 원본입니다. 설치된 스킬과 규칙은 공개 이름, 호스트 설정, 프로젝트 연결에 맞춰 생성한 **투영본**입니다. 개발할 때 수정할 원본은 아닙니다.

| 위치 | 설치 동작 |
| --- | --- |
| `AGENTS.md` | 주변 지침을 보존하고 표시된 Neurath 블록을 추가합니다. |
| `CLAUDE.md` | 새 파일은 `AGENTS.md`를 연결할 수 있고, 기존 일반 파일에는 관리 대상 import를 추가합니다. |
| `.agents/skills`, `.claude/skills` | 공개 스킬 이름으로 설치하고 관리 링크를 통해 Claude와 공유합니다. |
| `.neurath/policy.md`, `.neurath/rules`, `.neurath/reference` | 이식 가능한 정책, 규칙, 계약, 참조를 생성합니다. |
| `.neurath/project.json` | 없는 연결 설정을 초기화하고 이후 사용자 편집을 유지합니다. |
| 호스트 훅과 MCP 설정 | 기존 그룹과 무관한 설정을 유지하며 Neurath 항목을 추가합니다. |
| `.neurath/run` | 절대 경로의 인터프리터에서 Python import를 격리해 실행합니다. |

Codex는 `.codex/hooks.json`과 `.codex/config.toml`을, Claude는 `.claude/settings.json`과 `.mcp.json`을 사용합니다. Codex의 기존 인라인 훅도 남으며, 진단은 호스트가 두 형식을 함께 불러오는 상황을 알려 줄 수 있습니다. 설치기가 사용자의 모델, 샌드박스, 승인 방식을 선택하지는 않습니다.

훅은 세션 시작·종료, 하위 에이전트 시작·종료, 사용자 프롬프트 제출, 도구 실행 전후, 컨텍스트 압축, Stop을 다룹니다. Claude에는 도구 실패와 권한 거부 이벤트도 연결합니다. 설치된 명령의 제한 시간은 기본 30초이고 Codex SessionEnd만 3초입니다. 하나의 명령 안에서 Neurath 핸들러는 순차 실행합니다. 훅 등록은 설치 근거이며, 활성화 확인에는 실제 호스트 이벤트가 필요합니다.

## 호스트의 시작 지침에 도구 사용 계기 담기

`AGENTS.md`의 `<!-- neurath:managed -->` 블록에는 호스트가 처음 읽는 짧은 상시 지침이 들어 있습니다. 새로운 요구는 태스크 정의로, 작업 중첩이나 다른 담당자의 도움이 필요한 막힘은 메시징으로, 재사용할 발견은 뉴스룸으로 연결합니다. 중단된 작업에는 기억 가져오기를, 관찰된 실패에는 복구 학습과 승인 범위 안의 하네스 개선을 안내합니다. 태스크 변경 뒤에는 TODO 표시도 갱신하도록 지시합니다. 세부 계약은 정책과 도구 스키마에서 읽습니다.

설치기는 이 블록 하나를 갱신하고 주변 프로젝트 지침과 Context7 등 다른 연동은 보존합니다. 알려진 구버전 블록의 원문이 정확히 일치하면 비공개 설치 기록이 없는 복제본에서도 업데이트합니다. 수정되었거나 모호한 블록은 충돌로 남깁니다. 이 지침은 필요한 행동을 선택하게 하며, 모든 도구 호출·반복 조회·거부된 선행 조건 우회를 허용하지 않습니다. 바뀐 지침은 호스트가 다시 읽어야 하며 이미 캡처한 프롬프트가 설치만으로 소급 변경되지는 않습니다.

## 계획을 검토한 다음 트랜잭션으로 적용하기

계획은 확정된 작업 트리 루트, 배포본 ID, 프로필·호스트·접두어, 관찰한 경로, 적용 전후의 파일 내용·권한·링크를 담습니다. 계획 내용의 다이제스트가 계획 ID입니다. **Receipt**는 해당 설치 작업의 보존 기록이며, 나중에 이 ID로 복원할 수 있습니다.

네이티브 관리 도구 `installation_plan`은 내부 경로를 노출하지 않는 `plan_ref`와 경로별 변경 요약을 반환합니다. 원본 파일 내용은 비공개 계획 파일에 남습니다. `installation_apply`는 같은 작업 주체와 작업 트리에서 준비한 계획을 받습니다. [정확한 입력](setup-reference.md#설치된-작업-트리-관리하기)을 참고하세요.

비공개 계획에는 원래 설정과 자격 증명이 포함될 수 있습니다. `write_plan`은 완성된 `0600` 파일을 게시하며 기존 파일이나 심볼릭 링크를 덮어쓰지 않습니다. 기본 비공개 계획 디렉터리는 `0700` 권한을 사용합니다. 보고서에는 변경 요약을 쓰고 계획 원문은 비공개 상태에 보관하는 이유입니다.

적용은 설치 잠금을 잡고 관찰한 대상 상태를 다시 확인한 뒤, 현재 배포본으로 예상 계획을 재생성합니다. 파일 교체 전에 트랜잭션을 저널에 기록하고, 각 경로를 쓰기 직전에도 다시 비교합니다. 같은 설치를 변경 없이 반복하면 `changed: 0`을 반환합니다.

쓰기 실패 시 롤백은 경로가 계획의 적용 전후 값과 일치할 때만 원상복구합니다. 다른 편집이 생겼다면 그 내용을 유지하고 복구할 충돌을 남깁니다. `stale plan`, `stale or modified plan`, `concurrent change`는 이 비교가 서로 다른 단계에서 실패했음을 나타냅니다.

## 사용자 편집과 관리 대상 편집 구분하기

Neurath 지침 블록 바깥의 편집은 업데이트나 제거 시 보존할 수 있습니다. 소유한 블록 안의 변경, 관리 훅·서버 설정의 변경, 설치된 스킬 수정은 명시적인 해결이 필요합니다. 설치기가 사용자의 새 내용을 자신의 이전 버전으로 교체해도 된다고 추측하지 않습니다.

프로젝트 연결 설정은 편집을 전제로 합니다. 사용자가 변경한 `.neurath/project.json`은 업데이트와 제거 후에도 남습니다. 제거는 현재 상태가 허용하는 범위에서 보존한 원본을 복원하고 소유한 추가분을 없앱니다. 복원은 임의의 옛 패키지를 고르는 대신 선택한 설치 기록의 변경을 되돌립니다. 접두어도 설치 ID의 일부이므로 설치 후 바꾸려면 먼저 제거해야 합니다.

## 복구 전에 비공개 상태 이해하기

변경 가능한 런타임 상태의 기준 데이터베이스는 Git 공통 디렉터리에서 결정한 제어 루트의 `.neurath/local/runtime.sqlite3`입니다. 연결된 작업 트리가 이를 공유하지만 루트, 이름 공간, 코덱, 리비전, 다이제스트를 통해 각 기록의 의미를 구분합니다. 별도 복제본이나 컴퓨터는 저장소 이름이 같다는 이유로 동기화되지 않습니다.

설치 상태, 저널, receipt는 SQLite의 기준 기록입니다. `.neurath/install.json`은 `authority: "reference-only"`, `state_ref`, 다이제스트를 담은 스키마 2 참조 투영본입니다. 이 파일을 편집해도 기준 설치 상태가 바뀌지는 않습니다. 계획, 복원 원본, 비공개 프로세스 자료는 여전히 목적에 맞는 파일에 보관합니다. 하나의 데이터베이스를 쓴다고 모든 비공개 파일이 그 안으로 이동한 것은 아닙니다.

`installation_recover`는 영향받는 모든 경로가 알려진 적용 전후 값인지 확인한 뒤 중단된 저널의 변경을 되돌립니다. 다른 내용이 있는 경로는 `recovery conflict`를 반환합니다. 해당 내용을 보존하고 저널과 현재 대상을 조사한 뒤 진행해야 합니다. 이 오류 자체는 동시 편집을 덮어쓸 권한을 주지 않습니다.

## 옛 SQLite 저장소의 쓰기 경로 정리하기

기존 상태를 가져오는 일과 옛 프로세스가 다시 쓰지 못하도록 하는 일은 다릅니다. 공유 저장소 **cutover**는 보존된 레거시 데이터베이스와 실행기를 명시적으로 퇴역시키는 절차이며, 사용하지 않는 연결 작업 트리도 확인 대상입니다.

관련 쓰기 프로세스를 중지하고 SQLite 연결을 닫은 뒤 초기 관리 절차를 사용합니다.

```sh
neurath cutover inspect
neurath cutover prepare
neurath cutover inspect
neurath cutover apply --expected-token RETURNED_INSPECTION_TOKEN
```

초기 레거시 가져오기가 필요할 때 `prepare`를 사용합니다. 이후 다시 조사하고, 반환된 토큰에 해당하는 내용을 검토한 뒤 적용합니다. Unix `lsof`가 필요하며 열린 핸들, 저널, 모르는 실행기, 변경된 가드, 확인되지 않은 늦은 행을 거부합니다. 알려진 실행기를 잠시 차단하고 원본을 보존한 뒤, 기존 SQLite 경로를 디렉터리 표식으로 바꾸고 기준 가드와 감사 기록을 커밋합니다.

중단되면 `neurath cutover recover`가 커밋 전 원본을 되돌리거나 커밋 후 실행기 복원을 마칩니다. 변경된 경로나 손상된 백업은 명시적 복구 오류로 남습니다. 정리가 끝난 뒤 영향받는 작업 트리의 실행기를 지원하는 설치 경로로 갱신하고 파일 배치, 프로토콜, 실제 활성화를 각각 확인합니다. 이 선행 조건이 해결되지 않으면 일반 설치는 cutover 필요 오류로 멈춥니다.

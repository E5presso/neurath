# 마이그레이션과 복구

[문서 안내](index.md) · [English](../en/recovery.md)

활성 설치를 변경하기 전에 기존 데이터베이스와 미완료 작업을 보존하세요. 새 저장 설계는 SQLAlchemy와 Alembic을 사용합니다. 활성 데이터베이스 이름은 `neurath.sqlite3`이며, 새 파일이 생겼다는 이유만으로 이전 데이터베이스가 마이그레이션됐다고 판단하면 안 됩니다.

## 적용 전 준비

에이전트에게 변경할 원본과 대상, 스키마 버전, 백업 위치, 미완료 작업 수를 보여 달라고 요청하세요. 새 모델에 직접 대응하지 않는 데이터를 포함하여 원래 데이터베이스 전체를 복구 가능한 형태로 보관해야 합니다. 기존 데이터는 검사하거나 복원할 수 있어야 합니다.

> 마이그레이션을 준비하고 원래 데이터베이스 전체를 보존해 줘. 각 미완료 작업이 어떻게 옮겨지는지 보여 주고, 모호한 소유권과 누락된 근거는 그대로 드러내 줘.

올바른 준비 결과는 어떤 기록이 운영 작업이 되는지와 전체 원본 기록이 어디에 남는지를 설명합니다. 이전 완료 표시를 현재 검증 근거로 간주하거나 이전 문장을 새로운 사람의 동의로 가져오면 안 됩니다.

## 결과 검증

기존 미완료 작업과 새 기록 사이의 명시적인 대응 관계를 요청하세요. 이전 출처가 보존되는지, 작업 수가 설명되는지, 마이그레이션 반복으로 작업이 중복되지 않는지 확인하세요. 복구에 의존하기 전에 원본 보관본을 읽을 수 있는지 확인해야 합니다.

> 마이그레이션 목록과 미완료 작업 대응표를 보여 줘. 보존된 원본 기록과 새 모델에서 활성화된 기록을 구분해 줘.

새 데이터베이스에 작업이 보존됐더라도 소유권, 권한, 근거를 해결하기 전에는 진행할 수 없을 수 있습니다. 보존은 완료 권한을 부여하지 않습니다.

## 저장 장애에서 복구

데이터베이스를 읽을 수 없거나, 잠겼거나, 호환되지 않거나, 없는 경우 설치 환경의 긴급 우회로 호스트 제어를 회복하세요. 우회는 정상적인 운영 데이터베이스에 의존하지 않아야 합니다. 에이전트에게 우회 활성 여부를 확인하고 수리 전에 장애 근거를 보존하도록 요청하세요.

> 데이터베이스와 독립적인 복구 우회를 켜고 영향을 받은 파일을 보존해 줘. 무엇이든 교체하기 전에 복구 선택지를 설명해 줘.

식별하고 검증한 보관본으로만 복원하고, 어느 설치가 복원본을 읽을지 기록하세요. 설치된 소프트웨어보다 스키마가 새로운 데이터베이스는 수정하지 않고 거절해야 합니다. 호환되는 소프트웨어를 사용하거나 명시적으로 준비한 복원을 수행하세요. 버전 메타데이터를 수정해 강제로 다운그레이드하면 안 됩니다.

우회는 작업을 완료하거나 수리를 검증하지 않습니다. 저장을 복원한 뒤에는 프로토콜과 실제 호스트 활성화를 별도로 확인하고 복구 모드를 종료해야 합니다.

## 추가 워크트리 정리

체크아웃을 제거하기 전에 복구 가능한 내용과 Git 상태·로컬 변경을 식별하는 목록을 보존하세요. 추적 파일과 미추적 파일뿐 아니라 필요한 무시 파일도 포함해야 합니다. 보관본을 검증한 뒤 의도한 체크아웃만 제거하세요.

> 추가 워크트리를 복구할 수 있게 보관해 줘. 각 체크아웃을 제거하기 전에 무엇을 저장했고 어떻게 복원할 수 있는지 보여 줘.

작업 트리가 깨끗해 보인다는 이유만으로 디렉터리에 보존할 내용이 없다고 판단하면 안 됩니다. 보존한 작업의 처리 방향이 정해질 때까지 복구 자료를 유지하세요.

## 복구 근거의 기준

복구 보고에는 보존한 원본, 활성 대상, 마이그레이션 결과, 미해결 작업, 수행한 검증, 복원 방법이 있어야 합니다. 로컬 테스트와 실제 호스트 관찰을 구분해야 합니다. 개발 절차와 지원하는 명령 문법은 [기여 안내](../../CONTRIBUTING.ko.md)에 둡니다.

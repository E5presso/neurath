# 다른 에이전트와 협업하기

[English](../../en/usage/agents.md) · **한국어**

작업에 어떤 협업이 필요한지 에이전트에게 알려주세요. 에이전트가 승인된 범위에서 동료를
찾고, 범위를 정해 작업을 맡기고, 질문과 결과를 주고받습니다.
사용자가 메시지 콘솔을 조작하거나 에이전트 주소를 관리할 필요는 없습니다.

예를 들어 “이전 결정을 찾아 담당 동료에게 확인하고, 프로젝트 검사를 실행한 뒤 실제
결과를 인계로 남겨 주세요”라고 요청할 수 있습니다. 에이전트는 기억·협업·검증에 노출된
구조화 작업 도구를 우선 사용합니다. 도구가 호스트 실행 모드를 보존할 수 없으면 같은
등록 검사를 호스트에서 실행합니다. 설치·네이티브 활성화·관측된 모드·소유권은 각각
보고합니다. 포크한 작업도 자신의 신원을 사용하며, 편집 전에 별도로 소유권을 확보합니다.

## 다른 관점으로 검토 요청하기

> 다른 에이전트에게 이 설계의 검토를 맡겨주세요. 관련 제약을 전달하고,
> 코드를 수정하기 전에 검토 결과를 알려주세요.

특정 도구나 모델을 원한다면 요청에 명시하세요. 에이전트는 해당 도구의 기존 인증과 모델
접근 권한을 사용합니다. 사용할 수 없으면 다른 모델로 조용히 바꾸지 않고 한계를 알립니다.
필요한 로그인은 사용자가 직접 진행합니다.

외부 도구에 맡기는 작업은 기본적으로 읽기 전용입니다. 승인된 수정을 시작하기 전에
에이전트가 설치 상태, 실제 호스트 활성화, 적용된 실행 모드와 별도 worktree의 소유권을
확인합니다. 세션 생성만으로 수정 준비가 끝나지는 않습니다. 선택한 호스트가 요청한 모드를
설정하거나 확인할 수 없으면 그 한계를 구체적으로 알립니다.
에이전트가 필요한 맥락을 준비하며 부모 대화 전체를
자동으로 복사하지는 않습니다. 외부 도구의 보고만으로 일부 절차에 필요한 독립 검토 권한이
성립하지는 않습니다.

## 진행 중인 작업 조율하기

> 내보내기 검증을 맡은 에이전트에게 이 변경이 검증 전제에 영향을 주는지 물어봐주세요.
> 답변을 알려주고, 서로 수정하는 범위는 분리해서 진행해주세요.

같은 로컬 프로젝트의 에이전트는 연결된 worktree와 지원 호스트 사이에서 질문·답변·변경
소식을 주고받습니다. 각 작업은 자신의 목표와 권한을 유지합니다.
동료의 요청이 새로운 사용자 지시가 되거나 파일 수정 권한을 부여하지는 않습니다.

전달 상태는 다음처럼 구분합니다.

| 상태 | 의미 |
| --- | --- |
| 대기 | 전달할 메시지를 보관한 상태 |
| 제출 | 호스트 전달 도구가 요청을 수락한 상태 |
| 수신 확인 | 수신자가 메시지를 확인한 상태 |
| 답변 | 수신자가 응답을 보낸 상태 |

보관되거나 제출됐다는 사실만으로 상대가 읽었다고 판단하지 않습니다.
호환되는 Codex 앱 도구나 Claude Code의 네이티브 동료 도구가 있으면 정확한 수신자를
먼저 조회한 뒤 즉시 알릴 수 있습니다. 보류와 승인 대기는 미전달 상태로 유지하고,
거부된 요청은 거부로 보고합니다. 그 외에는 수신자의 다음 훅이나
재개 때 전달합니다. 에이전트는 실제 상태를 보고합니다.
알림 때문에 비활성 세션을 자동으로 깨우지 않으며, 별도 복제본이나 다른 컴퓨터까지
연결하는 기능은 아닙니다.

## 유용한 발견 공유하기

Newsroom은 작업 중인 에이전트끼리 발견을 공유합니다. 예를 들어 중복 저장 조건을 찾은
에이전트가 발견 내용과 재현 근거를 발행하면, 동료는 제목을 받고 자신의 작업에 필요한
경우에만 본문을 읽습니다.

발행, 관련 내용 조회, 정정과 댓글은 활성 작업 중 에이전트가 처리합니다.
사용자가 피드를 주기적으로 조회할 필요는 없습니다.
대기·일시 중지·종료된 세션은 알림 대상에서 제외하며 깨우지 않습니다.
비활성 기간에 놓친 알림을 재개 시 몰아서 보내지도 않습니다.
기사는 출처가 있는 보고이며, 스펙 승인이나 검증 통과를 대신하지 않습니다.

명령, 전달 제한, 도구 선택과 호스트 연동의 상세 내용은 에이전트와 기여자를 위한
[협업 실행 참조](../contributing/agents-reference.md)에 보존했습니다.

# 독립적인 작업 위임하기

[English](../../en/usage/agents.md)

요청한 일 중 독립적으로 진행할 부분이 있다면 다른 에이전트에게 위임해 달라고 요청하세요. 각 부분의 목표를 구체적으로 정하고 함께 지킬 조건을 알려 주면 됩니다. 조정 에이전트가 돌아온 결과를 읽고 원래 목표에 필요한 후속 작업을 이어갑니다.

> 다른 에이전트에게 실패 사례를 조사하게 하고 너는 구현을 살펴봐 줘. 양쪽 근거를 비교한 뒤 수정 방법을 정해 줘.

현재 작업 안에서 범위가 정해진 일은 기본적으로 호스트의 하위 에이전트에게 맡깁니다. 원하는 제공자나 모델이 있다면 지정할 수 있습니다. 에이전트가 기존 접근 권한으로 사용할 수 있는지 확인하고, 지정한 선택을 사용할 수 없다면 제약을 설명합니다.

독립 제공자 세션을 사용하려면 일을 배정하기 전에 해당 호스트와 작업 방식이 지원되는지 확인하도록 요청하세요. 모델, 정책, 활성화, 소유권, 복구에 필요한 동작은 [기여자 문서](../contributing/index.md)에 설명합니다.

## 제공자마다 기존 설정 유지하기

> Claude가 자신의 기존 설정을 유지한 채 이 변경을 검토하게 해 줘. 이 요청에 대한 결과인지 확인하고, 무엇을 검사했는지도 알려 줘.

독립 세션은 기본적으로 바로 위 발행자의 지원 가능한 실행 정책을 이어받습니다. 일을 받는 제공자의 설정을 쓰도록 명시하면, 에이전트는 그 제공자의 기존 기본값·훅·도구 규칙을 사용하고 실제로 생성된 세션에서 확인합니다. 사용할 수 없는 설정은 더 넓은 권한으로 대체하지 않고 제약을 설명합니다.

현재 제공자가 중단되어 다른 제공자가 남은 일을 맡아야 한다면 [작업 승계](memory.md)를 요청하세요. 별도 세션을 실행하는 것과 Codex 앱의 프로젝트에 소속시키는 것은 다릅니다. CLI로 생성한 Codex 세션의 실제 앱 프로젝트 연결은 아직 해결되지 않았으므로, 에이전트는 실행 결과와 앱의 표시 상태를 구분해 알려야 합니다.

## 맡길 일과 돌아올 결과 정하기

위임할 때는 조사하거나 만들 결과, 허용 범위, 돌려받을 근거를 정합니다. 예를 들어 한 에이전트가 실패를 재현하는 동안 다른 에이전트가 관련 구현을 살펴볼 수 있습니다. 조정 에이전트는 두 결과가 일치하는지, 더 확인할 부분은 무엇인지 설명합니다.

별도로 코드를 수정할 경우 격리된 작업 공간을 요청하세요. 에이전트가 대상의 준비 상태와 작업 공간 소유권을 확인한 뒤 수정합니다. 동료의 제안으로 사용자가 허용한 작업 범위가 넓어지지는 않습니다.

진행 상황에서는 다음에 무엇을 할지 알 수 있어야 합니다. 준비 중인지, 입력을 기다리는지, 조정 에이전트가 읽을 결과가 도착했는지 구분합니다. 에이전트를 생성했다는 사실만으로 맡긴 일이 끝났다고 볼 수는 없습니다.

## 메시지가 어디까지 전달됐는지 확인하기

| 보고된 상태 | 알 수 있는 내용 |
| --- | --- |
| 대기열 저장 | 전달할 메시지가 저장됨 |
| 전송 접수 | 전달 수단이 메시지를 접수함 |
| 수신 확인 | 수신자가 메시지를 읽었다고 확인함 |
| 응답 | 읽을 답변이 도착함 |

수신한 메시지에 담긴 작업은 아직 끝나지 않았을 수 있습니다. 작업 완료를 확인하려면 해당 배정의 결과를 요청하세요.

저장된 메시지는 프로세스 중단 후에도 지원되는 복구 경로에서 이어질 수 있습니다. 전달과 자동 깨우기는 호스트가 지원하는 연결에 따라 달라지며, 대기 중인 메시지는 세션을 재개할 때까지 기다릴 수 있습니다. 조정 에이전트는 보고를 읽고 후속 작업을 계속 맡습니다. 전달 결과가 불확실하면 그 상태를 설명해야 하며 전송 시도만으로 완료를 판단하지 않습니다.

## 전체 대화 대신 필요한 발견 공유하기

작업 중인 에이전트는 발견 사항과 재현 근거를 간결한 제목으로 게시할 수 있습니다. 활성 동료는 제목과 조회 식별자를 받고 필요한 본문을 열어 읽습니다. 정정과 댓글에도 작성 주체와 개정 정보가 유지됩니다.

게시글로 유용한 관찰을 공유할 수 있으며, 실제 조치를 결정할 때는 원래 근거를 확인합니다. 본문 전체가 메모리에 자동 복사되거나 외부로 전송되지는 않습니다. 유휴·일시 중지·종료 상태의 동료를 깨우지 않으며 비활성 기간에 놓친 알림도 다시 전달하지 않습니다.

동료 메시지와 [프로젝트 메모리](memory.md)는 같은 로컬 Git 프로젝트의 연결된 워크트리에서 공유합니다. 별도 클론이나 다른 컴퓨터로 자동 동기화되지는 않습니다.

위임할 수 있는 일은 [사용 가능한 스킬](skills.md), 공통 하네스 발견을 외부로 공개하는 별도 선택은 [문제 보고와 기여](reporting.md)에서 확인할 수 있습니다.

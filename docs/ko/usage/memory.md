# 기록된 결정에서 작업 이어가기

[English](../../en/usage/memory.md)

지난 결정이나 끝내지 못한 일을 확인한 뒤 현재 프로젝트 상태와 비교하도록 요청하세요.

> 이 변경에서 무엇을 결정했고 왜 그렇게 정했는지, 남은 일은 무엇인지 알려 줘. 이어서 작업하기 전에 현재 구현도 확인해 줘.

프로젝트 메모리는 목표, 결정, 관찰한 요청과 명령, 인계 결과, 남은 작업, 배운 점을 기록합니다. 다음 세션은 시작할 때 관련 이력을 자동으로 제공받고, 요청하면 더 자세한 내용을 찾을 수 있습니다. 답변에서는 저장된 결정과 에이전트가 방금 확인한 사실을 구분해 볼 수 있습니다.

## 중단한 지점에서 다시 시작하기

로컬에 저장한 기록은 세션이 중단돼도 남습니다. 다음 세션이 무엇을 시도했고 어떤 결과를 보고했으며 어디서 멈췄는지 파악하는 출발점이 됩니다. 관찰하거나 저장하지 못한 작업은 복원할 수 없습니다.

인계 기록은 이전 에이전트의 진행 상황을 담습니다. 새 세션은 현재 소스와 최신 요청을 확인한 뒤 행동합니다. 과거 승인이나 작업 공간 소유권이 기록과 함께 이전되지는 않습니다.

같은 로컬 Git 프로젝트의 연결된 워크트리는 메모리를 공유합니다. 별도 클론과 다른 컴퓨터로 자동 동기화되지는 않으므로, 위치를 옮겼다면 기록된 맥락이 그곳에도 있는지 확인하세요.

## 다른 제공자에게 남은 일 넘기기

작업 도중 한 제공자의 사용량 한도가 소진됐다면, 같은 원래 worktree에서 일을 이어받을 세션을 열고 요청하세요.

> 멈춘 Codex 세션의 남은 일을 이어받아 줘. 저장된 맥락과 중단 지점을 확인하고, 너의 기존 설정은 유지해 줘. 수정하기 전에 작업 공간을 넘겨받았는지도 확인해 줘.

새 에이전트가 프로젝트에 저장된 작업과 기억을 가져오고, 필요한 경우 정확히 등록된 대화 기록에서 맥락을 보충합니다. 멈춘 에이전트가 마지막 인계 기록을 쓰거나 맥락을 보내 줄 필요는 없습니다. 먼저 내용을 미리 확인한 뒤, 원본의 도구 실행·자식·위임 작업이 모두 정리됐는지 확인하고 소유권을 넘겨받습니다.

승계 후 새 에이전트는 자신의 미완료 작업 목록과 해당 worktree의 수정 권한을 갖습니다. 원본의 완료 이력은 원래 출처를 유지하고, 승계된 원본 세션은 다시 쓰거나 작업 공간을 되찾지 못합니다. 두 세션이 같은 쓰기를 이어가는 일을 막기 위한 처리입니다. 미리보기나 일반 기억 조회만으로는 소유권이 바뀌지 않습니다.

복구할 수 있는 범위는 저장된 데이터까지입니다. 제공자가 남기지 않은 기록을 완전히 재구성할 수는 없으며, 대화 내용만으로 도구의 성공을 판단하지도 않습니다. 미리보기·승계·복구 범위는 [작업 승계 참조](../contributing/provider-continuity.md)에서 설명합니다. 가져온 복구 경험을 학습 지침으로 삼을 때도 아래의 검증 조건이 그대로 적용됩니다.

## 실제로 성공한 복구에서 배우기

메모리와 학습은 별도 활성화 단계 없이 일반 활성 세션에서 동작합니다. 예를 들어 프로젝트가 의도한 환경 밖에서 실행해 테스트가 실패했다면, 같은 테스트를 올바른 환경으로 실행한 결과가 복구 사례가 될 수 있습니다. 더 쉬운 테스트나 다른 테스트를 선택한 결과로 원래 실패를 해결했다고 볼 수는 없습니다.

성공한 대안이 생기면 먼저 원래 세션의 설정된 프로젝트 검사가 통과해야 합니다. 이후 다른 세션에서도 같은 복구 방법을 사용하고 대응하는 검사에 통과해야 활성 지침이 됩니다. 에이전트 자신의 첫 회고를 넘어 실제로 다시 사용한 근거를 갖추는 과정입니다.

다음처럼 물어볼 수 있습니다.

> 이 복구 방법을 추천하는 이유가 뭐야? 다른 세션에서도 성공했는지, 프로젝트 검사 조건이 지금도 같은지 알려 줘.

복구나 그다음 검사가 실패하면 지침을 철회합니다. 검증 조건이 달라지면 이전 경험이 오래된 정보가 될 수 있습니다. 필요한 검사를 사용할 수 없거나 금지됐다면 이유를 기록하고 미검증으로 남깁니다.

학습은 작업 중 사용할 실행 지침을 개선합니다. 소스 코드, 프로젝트 규칙, 권한을 직접 바꾸거나 무인 세션을 시작하지는 않습니다. 반복된 경험을 프로젝트 규칙으로 만들고 싶다면 [사용 가능한 스킬](skills.md)에 있는 별도 검토를 요청하세요.

## 프로젝트 이력을 로컬에 보관하기

흔한 자격 증명 패턴은 가리지만 로컬 기록에는 비공개 프로젝트 맥락이 남을 수 있습니다. 비공개 추론은 제외하며 사용자에게 보이는 보고는 기록될 수 있습니다. 동료 게시글의 본문 전체가 메모리에 자동 복사되거나 외부로 전송되지는 않습니다.

외부 공개를 위한 별도 선택과 내용 검토는 [문제 보고와 기여](reporting.md)에 설명합니다. 저장 구조, 문맥 한도, 학습 검증의 상세 사항은 [기여자 문서](../contributing/index.md), 여러 세션에 걸친 메시지 전달은 [에이전트와 공동 작업](agents.md)을 참고하세요.

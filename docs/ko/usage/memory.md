# 원래 목적을 유지하며 조사로 돌아오기

다음 날 개발 중인 웹앱의 저장 필터 문제로 돌아왔다고 합시다. 이전 에이전트는 저장 요청을 추적하고 불러오기 경로 일부를 수정했지만, 브라우저 새로고침 검증은 남겨 두었습니다. 다시 시작할 지점은 이미 모은 근거와 함께 이 미완료 결과를 확인하는 곳입니다.

> 이전 세션의 저장 필터 조사를 이어가 주세요. 확인된 사실, 변경 내용, 남은 검사를 찾아 주세요. 새로고침 뒤에도 선택이 유지되어야 한다는 원래 요구사항을 유지하고, 수정하기 전에 현재 상태를 확인해 주세요.

**세션**은 Claude Code나 Codex가 유지하는 상호작용 상태입니다. 에이전트가 지금 답변할 때 사용할 수 있는 정보를 **컨텍스트**, 즉 현재 맥락이라고 합니다. 다음 세션이 이전 대화를 모두 자동으로 포함하는 것은 아니며, 긴 대화는 현재 맥락이 축약될 수도 있습니다. Neurath는 이전 요청, 관찰, 보고 중 필요한 프로젝트 **이력**을 보관하여, 에이전트가 작업을 처음부터 다시 시작하지 않고 관련 정보를 찾도록 돕습니다.

## 평소 작업에서 남는 기록

지원되는 호스트 훅이 활성화되어 있으면 Neurath는 제출된 프롬프트와 관측된 명령 이벤트를 기록합니다. 맥락 축약 전, 에이전트 정지 시, 세션 종료 시에는 사용자에게 보이는 답변과 작업 흐름의 상태를 참고 기록으로 남길 수 있습니다. 명령 종료를 관측했는지는 실제 호스트의 실행 정보로 판단합니다. 명령 출력에 성공처럼 보이는 문장이 있다는 것과는 다릅니다.

세션이 시작되면 에이전트는 분량이 제한된 프로젝트 기억과 적용 가능한 학습 지침을 받습니다. 필요하면 보관된 이력을 검색해 더 찾을 수 있습니다. 이 자동 맥락은 전체 이력을 불러오거나 이전 보고가 옳다고 보증하는 기능이 아닙니다.

더 명확한 중단 지점을 남기고 싶다면 현재 요약, 결정, 다음 단계, 교훈, 상태를 저장하는 인계 보고인 **체크포인트**를 요청하세요. 필터 예시에서는 확인된 저장 동작과 아직 검증하지 않은 새로고침 동작을 구분해야 합니다. 지원되는 종료 처리도 필요한 시점에 이 보고를 요청할 수 있습니다. 체크포인트의 완료 표시는 보고의 상태이며, 사용자 태스크를 완료하거나 수정 권한을 넘기는 것은 아닙니다.

## 기억이 공유되는 범위

Neurath는 Git 공통 디렉터리에 연결된 로컬 SQLite 데이터베이스에 기록을 저장합니다. Git 공통 디렉터리는 저장소와 연결된 워크트리가 함께 사용하는 Git 저장 공간입니다. 같은 로컬 프로젝트의 Claude Code와 Codex 세션은 출처가 보존된 기록을 워크트리 사이에서 조회할 수 있습니다.

별도 복제본이나 다른 컴퓨터와 이 데이터베이스가 자동으로 동기화되지는 않습니다. 기억 공유와 실행 소유권도 다릅니다. 다른 에이전트의 결정을 읽으면 참고 정보를 얻지만, 그 에이전트의 권한이나 쓰기 소유 기록인 클레임을 얻지는 않습니다. 일반적인 새 세션은 다른 세션을 인수하지 않고도 이 기억 조회를 사용할 수 있습니다. 인수는 멈춘 세션의 미완료 태스크와 쓰기 책임을 넘겨받을 때 수행하는 별도 단계입니다.

알려진 자격 증명 형태는 저장 전에 가리고 비공개 추론은 제외합니다. 사용자에게 보이는 답변은 보관될 수 있습니다. 패턴 검사만으로 모든 비공개 정보를 알아낼 수는 없으므로, 로컬 기억에는 여전히 프로젝트의 비공개 맥락이 포함될 수 있습니다. 뉴스룸 본문은 명시적으로 읽어야 하며 공유 기억에 자동으로 복사되지 않습니다.

## 멈춘 세션의 미완료 작업 복구하기

이전 세션이 체크포인트를 남기지 못하고 멈출 수도 있습니다. 받는 에이전트는 원래 세션에 남은 정보를 모으고 안전한 경우 미완료 태스크를 인수하는 **가져오기 복구**를 요청할 수 있습니다. 원래 세션이 먼저 인계 자료를 보내야 하는 것은 아닙니다.

받는 에이전트는 공유 SQLite의 태스크와 실행 기록, 프로젝트 기억, 통신 기록, 그리고 해당 원본 세션에 등록된 정확한 대화 로그를 사용합니다. 호스트가 작성한 이 대화 기록을 **트랜스크립트**라고 합니다. JSONL 형식으로 한 줄에 구조화된 기록 하나씩 저장합니다. 복구는 등록된 원본 파일이나 지원되는 Codex의 정확한 보관 위치 이동을 따라갑니다. 다른 대화를 넓게 검색해 그럴듯한 대체 자료를 고르지 않습니다.

다음처럼 요청할 수 있습니다.

> 멈춘 세션의 미완료 저장 필터 작업을 원래 체크아웃에서 복구해 주세요. 복구할 수 있는 내용을 확인하고 빠진 근거를 알려 주세요. 원래 세션과 위임한 작업이 안전하게 멈춘 뒤에만 인수해 주세요.

먼저 원본을 목록에서 찾거나 미리 봅니다. 미리보기는 받는 세션 소유의 변경 불가능한 스냅샷이며, 더 긴 저장 내용은 나누어 읽을 수 있습니다. 목록 조회, 미리보기, 읽기는 참고 작업이므로 소유권을 옮기지 않습니다. 생략 안내도 확인해야 합니다. 애초에 저장되지 않았거나 스냅샷에서 빠진 내용은 저장된 미리보기를 더 읽어도 복원되지 않습니다.

인수는 원래 작업한 체크아웃에서 신원이 확인된 다른 주 세션이 수행해야 합니다. 원본에는 호스트 안의 하위 에이전트, 다른 호스트를 통한 독립 실행, 기존 동료에게 맡긴 배정, 결과를 아직 모르는 명령을 포함해 미결 실행이 없어야 합니다. 원본 상태, 트랜스크립트 관측, 체크아웃 소유권이 미리보기 당시와 같아야 하고 받는 쪽도 현재 태스크 상태를 사용해야 합니다. 달라졌다면 새 미리보기가 필요합니다. 강제 인수 경로는 없습니다.

조건을 충족하면 미완료 작업과 체크아웃의 쓰기 소유권을 하나의 트랜잭션에서 함께 옮깁니다. 받는 세션 소유로 새로 만들어진 태스크는 원래 목표와 완료 조건을 유지하며, 의존 관계도 새 식별자에 맞게 연결됩니다. 이미 끝난 원본 이력은 원래 출처를 보존합니다. 이전 세션은 옮겨진 작업을 변경하거나 체크아웃을 다시 차지할 수 없습니다. 받는 세션이 나중에 소유권을 해제해도 이 제한은 유지됩니다.

받는 세션은 자신의 네이티브 설정을 유지합니다. 인수가 자격 증명을 복사하거나 권한을 더하거나, 알 수 없던 이전 도구 결과를 관측된 것으로 만들거나, 저장되지 않은 프로바이더 내용을 복원하지는 않습니다. 한 번에 인수할 수 있는 미완료 태스크는 최대 64개입니다. 더 크거나 실행이 정리되지 않은 원본은 지원 범위 안에서 처리해야 합니다. 이전 대화의 모든 의미가 보존되었다고 보장할 수도 없습니다. 에이전트는 현재 파일을 살피고 남은 새로고침 동작을 검증해야 합니다.

정확한 분할 읽기 제한, 원본 검사, 복구 입력은 [기억 참조](../contributing/memory-reference.md)에 있습니다. 기억에 남은 다른 세션의 쓰기 클레임으로 인수를 대신해서는 안 됩니다.

## 수정 경험을 근거에 맞게 학습하기

같은 조사 중 프로젝트 환경을 잘못 사용해서 검증 명령이 실패했다고 합시다. 에이전트가 환경을 바로잡고 같은 검증 작업을 다시 실행해 성공했습니다. 이 경험을 사용하는 방식은 세 가지로 구분됩니다.

**회고**는 무엇이 잘못됐고 무엇이 도움이 됐는지 에이전트가 설명해 보고나 체크포인트에 남기는 것입니다. 유용한 맥락이지만 여전히 해석에 해당합니다.

**실행 학습**은 관측된 실패와 복구 근거를 사용합니다. 같은 세션, 워크트리, 명령 계열에서 실패에 대응하는 수정된 명령이 성공하고 등록된 프로젝트 검증 기준과 연결되면 Neurath가 후보를 자동으로 기록할 수 있습니다. 다른 테스트를 실행하거나 관련 없는 성공 출력을 얻는 것만으로는 복구가 성립하지 않습니다.

원래 세션에서 설정된 프로젝트 검사가 통과하면 후보는 시험 적용 지침이 됩니다. 다른 세션이 그 지침을 실제로 전달받고, 같은 복구 방법을 성공적으로 사용하고, 일치하는 검사를 통과해야 활성 지침으로 올라갑니다. 세션 시작 시 적용 가능한 시험 또는 활성 지침을 제공하여 이후 작업을 도울 수 있습니다. 실패할 때마다 학습을 켜 달라고 요청할 필요는 없지만, 승격에는 실제 근거가 필요합니다.

복구 방법이 다시 실패하거나 시험 적용 뒤 검사가 실패하면 지침을 철회할 수 있습니다. 원래 워크트리의 검증 기준이 달라지면 이전 지침은 유효성이 지난 상태가 됩니다. 관련 없는 연결 워크트리의 변경만으로는 그렇게 되지 않습니다. 종료 시점에 검증이 필요한 학습이 있으면 Neurath는 승인된 등록 검사와 정확한 인계 기록을 요청할 수 있습니다. 검사가 없거나 금지되어 있거나 실패·보류되었다면 그에 맞게 미검증 상태를 남깁니다. 학습을 위해 권한을 넓히거나 무인 세션을 만들거나 성공할 때까지 실험을 반복하지 않습니다.

**승인된 프로젝트 규칙**은 저장소에 지속적으로 적용할 지침입니다. 반복되는 경험을 규칙으로 만들고 싶다면 `memory-to-rules`를 요청하세요. 에이전트는 재사용할 문구를 준비하고 비공개 내용을 제거한 뒤, 요청한 저장소 변경의 권한을 따릅니다. 제안만 요청했다면 저장소를 바꾸지 않습니다. 자동 학습만으로 소스 파일이나 프로젝트 규칙을 편집하지 않으며, 학습 지침보다 현재 사용자 지시, 저장소 규칙, 권한이 우선합니다.

필터 조사로 돌아왔을 때 기대할 결과는 같은 내용을 덜 반복하고 다음 단계를 더 정확히 고르는 것입니다. 완료 여부는 여전히 원래 요구사항으로 판단합니다. 저장한 선택이 새로고침 뒤에도 남아야 합니다. 이전 작업을 어떻게 나누었는지는 [에이전트 협업](agents.md), 학습에 쓰는 검증 기준은 [프로젝트 기준](profiles.md)에서 설명합니다.

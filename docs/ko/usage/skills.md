# 필요한 작업 요청하기

애플리케이션에서 저장한 필터가 새로고침 뒤 사라진다면, 문제와 원하는 결과부터 설명하세요.

> 저장한 필터가 브라우저 새로고침 뒤 사라지는 이유를 조사해 주세요. 저장과 불러오기 흐름을 추적하고 원인을 수정한 뒤, 기존 화면을 바꾸지 않으면서 선택이 유지되는지 보여 주세요.

특정 종류의 작업을 에이전트가 수행하도록 안내하는 재사용 절차를 **스킬**이라고 합니다. Neurath는 조사, 구현, 검토, 문서화, 작업 연속성을 위한 스킬을 설치합니다. 에이전트는 요청의 목적과 입력이 가진 권위를 기준으로 스킬을 고릅니다. 단어가 일치한다는 이유만으로 시작하지는 않습니다.

## 관찰한 문제에서 검증된 변경까지

에이전트는 `debug`를 사용해 필터가 사라지는 현상을 재현하고 저장 및 불러오기 흐름을 추적할 수 있습니다. 관련 코드를 먼저 설명해야 한다면 `explain-code`가 그 요청을 지원합니다. `graphify`는 코드 관계를 살피는 데 사용합니다. 이런 절차는 조사를 돕지만, 처음 의심한 원인이 맞다고 보장하지는 않습니다.

Graphify가 생성 파일을 만들거나 갱신할 때 `graphify-out`은 현재 작업 공간 안의 실제 디렉터리여야 합니다. Neurath는 Git 메타데이터, 다른 작업 공간 또는 외부 공유 디렉터리를 가리키는 심볼릭 링크를 통한 쓰기를 거부합니다. 따라서 생성된 분석 파일이 Git 설정, 훅, 인덱스와 분리됩니다.

원인이 드러나면 승인된 범위에 따라 구현과 검토를 이어갑니다. 같은 필터 조사도 이슈를 기록한 뒤 구현할 수 있고, 바로 수정하는 작업으로 진행할 수 있습니다. 이슈, 커밋, 풀 리퀘스트 생성은 각각 별도 행동이므로 필요할 때 요청에 포함하세요.

| 다음에 필요한 일 | 관련 스킬 |
| --- | --- |
| 요구사항을 확인하고 승인된 작업 정리하기 | `review-spec`, `plan`, `create-issue` |
| 기록된 이슈를 구현하거나 별도 체크아웃 준비하기 | `implement-issue`, `create-worktree` |
| 필터 화면을 검토하거나 변경하기 | `design-ui`, `implement-ui`, `review-ui`, `sync-design` |
| 코드를 검토하고 요청한 동작 검사하기 | `review-code`, `qa` |
| 커밋을 기록하거나 풀 리퀘스트 준비하기 | `commit`, `create-pr` |
| 풀 리퀘스트를 검토하고 피드백에 대응하거나 진행 확인하기 | `review-pr`, `pr-feedback`, `watch-pr` |

전체 목록과 각 절차의 입력은 [스킬 참조](../contributing/skills-reference.md)에 있습니다. 의존성 점검과 업데이트, 문서, 프로젝트 상태, Neurath 자체 작업 지원인 하네스 평가도 그곳에서 다룹니다. 작업을 요청하기 전에 목록을 외울 필요는 없습니다.

## 어디까지 수행할지 알려 주기

“원인을 찾아 주세요”와 “수정하고 검증해 주세요”는 수행할 범위가 다릅니다. 설명에서 멈출지, 변경할지, 검토 자료까지 준비할지 알려 주세요. 승인된 여러 단계를 이어갈 때는 `autopilot`이 해당 절차를 진행하도록 돕습니다. 관련 없는 작업이나 공개 행동의 권한까지 새로 만들지는 않습니다.

기존 스킬과 이름이 겹치지 않도록 설치 시 접두어가 붙을 수 있습니다. 원본 디렉터리 이름으로 추측하지 말고 실제 설치된 이름을 확인해 달라고 하세요. 설치된 접두어를 바꾸려면 먼저 해당 설치를 제거해야 합니다. 접두어가 서로 다른 하네스의 지침 충돌을 해결해 주지는 않습니다. 설치된 절차보다 현재 사용자 지시, 저장소 규칙, 호스트 권한이 우선합니다.

## 다음 대화에서 이어갈 근거 남기기

필터 조사를 잠시 멈추기 전에 이렇게 요청할 수 있습니다.

> 확인된 원인, 수정한 내용, 실제로 끝낸 검사, 새로고침 뒤에 아직 입증해야 할 내용을 저장해서 다음 세션이 이어갈 수 있게 해 주세요.

`checkpoint`는 나중에 읽을 인계 보고를 남기는 데 사용합니다. `finish-session`은 실제 상태를 기록하며 현재 작업 세션을 마무리하도록 돕습니다. 사용자의 미완료 작업은 계속 드러나 있어야 합니다. `memory-to-rules`는 재사용할 지침을 제안하거나 승인된 범위에서 규칙으로 반영할 때 사용하며, 별도 검토가 필요합니다. 이 기록이 태스크 완료나 검증된 학습과 어떻게 다른지는 [작업 재개](memory.md)에서 설명합니다.

API와 브라우저를 독립적으로 확인하면 도움이 된다면 [다른 에이전트와 함께 작업하기](agents.md)를 읽으세요.

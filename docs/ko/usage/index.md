# 프로젝트에서 Neurath 사용하기

[English](../../en/usage/index.md) · **한국어**

<!-- date: 2026-09-07; synced_from: source and documentation at e1487a1718056b37b999d1343a1007b7e25f5c8c; English and Korean editions updated together -->

[사용 안내](index.md) · [기여자 안내](../contributing/index.md)

**에이전트에게 원하는 결과를 요청하세요.** 에이전트가 작업에 맞는 스킬을 선택하고
Neurath 설치, 프로젝트 설정, 검증, 기억 조회, 협업을 처리합니다. 사용자가 Neurath 명령을
실행하거나 설정 파일을 편집하고 내부 절차를 관리할 필요는 없습니다.

## 1. 에이전트에게 설치 요청하기

Codex 또는 Claude Code에서 프로젝트를 열고 다음과 같이 요청하세요.

> https://github.com/E5presso/neurath 의 설치 실행 참조를 읽고 이 프로젝트에 Neurath를
> 설치해주세요. 기존 지침·훅·권한·스킬·의존성을 보존하고, 프로젝트의 실제 문서와
> 검사를 연결해주세요. 저장소에서 확인할 수 없는 정보만 질문하고,
> 설치 진단 결과와 제가 직접 해야 할 호스트 신뢰 설정을 알려주세요.

에이전트가 프로젝트를 조사하고 설치를 준비한 뒤 기존 검사를 연결하고 확인 가능한 항목을
검증합니다. 파일 충돌로 결정이 필요하면 구체적인 충돌 내용을 설명합니다.
호스트 로그인이나 신뢰 설정처럼 사용자 조작이 필요한 단계는 직접 진행하고,
에이전트가 필요성을 안내하면 새 세션을 시작하세요.
설치 후 확인할 결과와 복구 방법은 [설치와 유지 관리](installation.md)에 정리했습니다.

## 2. 목표와 제약 전달하기

> 작업 기록 내보내기를 재시도하면 행이 중복됩니다. 문제를 재현하고, 내보내기 형식을
> 바꾸지 않으면서 수정한 뒤 프로젝트 테스트로 검증해주세요. 달라진 동작, 실행한 검사와
> 아직 확인하지 못한 부분을 알려주세요.

에이전트는 요청의 목적과 확인된 근거에 맞춰 절차를 선택합니다.
사용자가 스킬을 고르거나 호출 이름을 외울 필요는 없습니다.

| 하려는 일 | 요청 예시 |
| --- | --- |
| 기능 계획 | “이 요구사항으로 구현 계획을 세우고 빠진 조건을 검토해주세요.” |
| 오류 수정 | “이 오류를 재현하고 원인을 설명한 뒤 수정 결과를 검증해주세요.” |
| 합의된 작업 구현 | “이 승인된 이슈를 구현하고 완료 조건을 확인해주세요.” |
| 코드 이해·검토 | “이 모듈을 설명해주세요.” 또는 “이 변경에서 결함을 찾아주세요.” |
| 실제 제품 확인 | “앱에서 이 시나리오를 실행하고 결과가 올바르게 저장됐는지 확인해주세요.” |
| 변경 전달 | “검사를 마치고 변경을 커밋한 뒤 푸시해주세요.” |

[스킬 목록](skills.md)은 에이전트가 수행할 수 있는 작업을 설명합니다.
설치 자체가 변경 게시나 권한 변경까지 허용하지는 않으므로, 필요한 전달 작업은 요청에 명시하세요.

## 3. 결과 확인하기

에이전트가 프로젝트에 연결된 검사를 실행하고 무엇을 확인했는지 보고합니다.
검사 방법이나 기준 문서를 찾을 수 없으면 필요한 정보를 질문하고 미확인 항목을 남깁니다.

최종 보고에서는 달라진 동작, 실제로 실행한 검사, 검토 결과와 남은 한계를 확인하세요.
테스트, 독립 검토, 설치 진단, 호스트 활성화, 원격 푸시는 각각 다른 사실을 확인합니다.
테스트 통과만으로 필요한 독립 검토를 대신하지 않습니다.

## 4. 작업 이어가기와 협업

> 작업 기록 내보내기 수정을 이어서 진행해주세요. 저장된 결정과 남은 일을 현재 코드와
> 대조하고, 미완료 검증을 마쳐주세요.

에이전트는 작업 중에 인계를 남기고 관련 기억을 자동으로 조회합니다.
“지난번에 무엇을 결정했나요?”, “어떤 복구 방법이 검증됐나요?”라고 물어볼 수도 있습니다.
기억은 같은 로컬 Git 저장소와 연결된 worktree에서 공유하며, 별도 복제본이나 다른 컴퓨터에
자동으로 동기화하지 않습니다. 자세한 범위는 [기억과 학습](memory.md)을 참고하세요.

> 다른 에이전트에게 이 설계의 검토를 맡기고, 코드를 바꾸기 전에 결과를 알려주세요.

에이전트가 승인된 작업 범위 안에서 동료 탐색, 위임, 메시지 전달과 필요한 수정 공간 분리를
처리합니다. [에이전트 협업](agents.md)에서 기대할 수 있는 동작을 설명합니다.

## 문제가 생겼을 때

증상을 에이전트에게 알려주세요. 진단은 에이전트가 수행합니다.

| 증상 | 요청할 내용 |
| --- | --- |
| 스킬이나 훅이 보이지 않음 | “이 프로젝트의 설치 상태와 호스트 활성화를 확인하고, 제가 해야 할 신뢰 설정이나 세션 재시작을 알려주세요.” |
| 설치 중 충돌 발생 | “어떤 내용이 충돌하는지, 기존 내용을 어떻게 보존할 수 있는지 설명해주세요.” |
| 검증을 실행하지 못함 | “프로젝트의 실제 검사 절차를 찾아 연결하고, 부족한 전제 조건을 알려주세요.” |
| 동료가 답하지 않음 | “메시지가 대기·제출·수신 확인·답변 중 어느 상태인지 확인해주세요.” |
| 새 세션에 맥락이 부족함 | “저장된 프로젝트 기록을 확인하고 무엇이 남아 있는지 설명해주세요.” |

문제를 제보하려면 에이전트에게 최소 재현 방법, 버전, 기대·실제 동작, 필요한 진단 결과를
정리하도록 요청하세요. 공개할 내용에서는 비공개 정보를 제거해야 합니다.
설치 계획과 로컬 상태에는 민감한 프로젝트 자료가 들어갈 수 있으므로 공개 보고에 포함하지 않습니다.

# Neurath로 프로젝트 작업하기

[English](../../en/usage/index.md)

Git 프로젝트에서 이루려는 일을 Claude Code나 Codex에게 알려 주세요. Neurath는 프로젝트의 기존 문서와 검사 방법을 사용해 조사, 구현, 검토, 작업 재개를 돕습니다. 언어나 프레임워크에 관계없이 기존 프로젝트에 설치해 사용할 수 있습니다.

## 확인할 수 있는 결과로 요청하기

> 저장한 필터가 새로고침하면 사라져. 문제를 재현하고 원인을 수정한 다음 새 세션에서도 값이 유지되는지 확인해 줘. 현재 화면 구성은 유지해 줘.

에이전트가 현재 동작을 조사하고 요청한 변경을 수행한 뒤 결과를 검사합니다. 작업 결과에서 달라진 점, 실제 수행한 검사, 아직 해결하지 못한 부분을 확인할 수 있습니다. 커밋, 푸시, 풀 리퀘스트까지 원한다면 전달 작업도 요청에 포함해 주세요.

작업 도중 질문하거나 조건을 추가해도 됩니다. 기존 요청은 완료하거나 취소하거나 다른 목표로 바꿀 때까지 계속 추적합니다. 화면의 TODO 목록에서 끝난 일과 남은 일을 볼 수 있습니다.

## 목표를 유지하며 접근 바꾸기

Neurath는 작업을 시작한 이유와 완료 조건을 에이전트에게 주기적으로 환기합니다. 위 필터 문제의 목표는 저장값을 유지하는 것입니다. 조사를 반복하거나 테스트 계획을 더 다듬는 일도 그 결과에 도움이 되는 동안에 의미가 있습니다.

이 기능은 에이전트의 자기 점검을 돕습니다. 목표 달성을 완벽하게 채점하지는 않습니다. 별도로 환기를 요청하거나 성찰 보고서를 받을 필요도 없습니다. 시간과 토큰 한도는 낭비를 줄이는 기준이며, 완료 조건을 낮추거나 한 번 실패한 시도 때문에 원래 작업을 포기할 근거가 되지는 않습니다.

## 지금 필요한 작업 고르기

| 현재 상황 | 요청 예시 |
| --- | --- |
| 낯선 코드를 이해해야 할 때 | 현재 소스와 테스트를 근거로 이 흐름을 설명해 줘. |
| 의도한 동작이 불분명할 때 | 요구사항을 검토하고 구현 전에 정할 결정을 알려 줘. |
| 구현할 이슈가 준비됐을 때 | 승인한 이 이슈를 구현하고 완료 조건을 확인해 줘. |
| 변경을 검토할 때 | 이 변경의 결함을 검토하고 근거를 보여 줘. |
| 기능이 배포됐을 때 | 화면, API 응답, 저장된 결과를 전체 흐름으로 확인해 줘. |
| 미완료 작업으로 돌아왔을 때 | 지난 결정을 확인하고 현재 상태를 살펴 남은 작업을 이어 줘. |

에이전트가 필요한 [스킬](skills.md)을 선택하므로 이름을 외울 필요는 없습니다. 독립적으로 나눌 부분이 있다면 [다른 에이전트에게 위임](agents.md)하도록 명시적으로 요청할 수 있습니다.

## 어디까지 준비됐는지 확인하기

결과에는 도달한 단계가 드러납니다. “테스트 통과, 변경은 아직 로컬에 있음”이면 검사는 마쳤고 전달은 남아 있다는 뜻입니다. “설치 파일 준비 완료, 새 호스트 세션 시작 필요”이면 새 세션에서 통합을 확인할 차례입니다. [중간 저장](skills.md)은 다시 이어갈 지점을 남기며, 작업 완료 결과에는 요청한 동작과 그 검증이 포함됩니다.

필요한 검사를 실행할 수 없다면 결과에서 그 공백을 확인할 수 있어야 합니다. 모든 일반 작업에 독립 검토자가 추가되지는 않습니다. 리뷰가 필요하면 작업 범위에 포함해 요청하세요.

## 설치하고 이어서 사용하기

[설치](installation.md)한 뒤 [프로젝트 문서와 검사 방법을 연결](profiles.md)하세요. 기록된 결정과 남은 작업이 다음 세션으로 어떻게 이어지는지는 [프로젝트 메모리](memory.md)에 설명합니다. 공통 하네스 문제를 Neurath 프로젝트에 알릴지는 [문제 보고와 기여](reporting.md)에서 선택할 수 있습니다.

한 워크트리에서 Neurath 훅을 잠시 멈춰야 한다면 중단 후 복원해 달라고 요청할 수 있습니다. 호스트 권한, 사용자 지시, 작업 이력은 유지됩니다. 설치나 일반 작업만으로 권한 정책 변경이나 외부 공개가 허용되지는 않습니다.

패키지 소개는 [프로젝트 개요](../../../README.ko.md), 낯선 기록 이름은 [용어 안내](../terminology.md), 실행과 검증의 세부 사항은 [기여자 문서](../contributing/index.md)에서 확인할 수 있습니다.

# 프로젝트에서 Neurath 사용하기

[English](../../en/usage/index.md) · **한국어**

<!-- date: 2026-09-07; synced_from: source and documentation at 2456ae73ffaf818c04ea4419574218df36852805; English and Korean editions updated together -->

[사용 안내](index.md) · [기여자 안내](../contributing/index.md)


이 안내는 **자신의 프로젝트**에서 Claude Code나 Codex를 사용하면서 기억을 공유하고,
에이전트의 작업을 조율하며, 실제 검사 결과를 남기려는 사용자를 위한 문서입니다.
사용자가 작업 목표와 프로젝트 관례를 정하면 Neurath가 에이전트의 작업을 여기에 연결합니다.
Neurath의 설치기·훅·스킬 자체를 수정하려면 [기여자 안내](../contributing/index.md)를 읽으세요.

## 1. 설치하고 프로젝트 연결하기

내려받은 Neurath 소스 폴더에서 실행합니다.

```sh
./setup /absolute/path/to/your-project
```

macOS 또는 Linux, Git, 인증된 Codex 또는 Claude Code가 필요합니다. 설치기는
Python 3.14와 Neurath를 독립된 환경에 준비합니다. 대상 프로젝트의 언어, 의존성과 `.venv`는
그대로 유지합니다. 호스트 선택, 스킬 접두어, 미리보기, 업데이트와 제거는
[설치 안내](installation.md)에 설명합니다.

호스트에서 대상 프로젝트를 열고 설치된 훅을 검토한 뒤 새 세션을 시작하세요.
그다음 에이전트에게 요청합니다.

> 이 프로젝트의 지침과 `.neurath/project.json`을 읽고, 기존 제품 문서와 검사 명령을 연결해줘.
> 그 검사가 무엇을 확인하는지 설명하고, 알 수 없는 항목만 내게 물어봐.

연결 설정은 **이 프로젝트**에서 참고할 문서와 수행할 검사를 정합니다. 설치 성공만으로
프로젝트 테스트나 실제 호스트 활성화까지 확인된 것은 아닙니다. 작업을 시작하기 전에
에이전트와 `.neurath/project.json`을 검토하세요. 설정할 수 있는 항목은
[프로젝트 연결](profiles.md)에서 확인할 수 있습니다.

## 2. 원하는 결과와 제약부터 설명하기

기대하는 결과, 현재 문제와 지켜야 할 범위를 알려주세요. 예를 들면 다음과 같습니다.

> 작업 기록 내보내기를 재시도하면 행이 중복돼. 문제를 재현하고, 내보내기 형식을 바꾸지 않고
> 수정한 뒤 이 프로젝트의 테스트로 확인해줘. 변경 파일, 실행한 검사와 남은 불확실성을 알려줘.

에이전트는 작업 목적과 확보한 근거에 맞춰 스킬을 선택합니다. 스킬을 직접 호출할 수도
있습니다. 설치할 때 `neurath-` 접두어를 선택했다면 `/neurath-debug`처럼 사용하세요.

| 하려는 일 | 시작할 스킬 | 전달할 내용 |
| --- | --- | --- |
| 구현 전에 기능 요구사항 정리 | `/plan`, 이후 `/review-spec` | 원하는 동작, 제약과 기존 스펙 |
| 재현되는 문제 수정 | `/debug` | 재현 순서, 기대 결과, 실제 결과와 관련 오류 |
| 승인된 이슈 구현 | `/implement-issue` | 이슈와 완료 조건 |
| 코드 이해 또는 검토 | `/explain-code`, `/review-code` | 살펴볼 파일이나 변경과 확인할 질문 |
| 실행 중인 제품의 동작 확인 | `/qa` | 시나리오, 환경, 기대하는 화면이나 저장 결과 |
| 변경 작업 마무리 | `/finish-session` | 커밋이나 PR 생성 등 승인한 전달 범위 |

모든 작업에서 이 순서를 따를 필요는 없습니다. 목적에 맞는 출발점을 고르면 됩니다.
[스킬 목록](skills.md)에서 각 역할을 확인할 수 있습니다. 설치 자체가 변경 게시나
프로젝트 권한 변경을 승인하는 것은 아닙니다.

## 3. 결과와 검증 근거 확인하기

`check` 연결을 설정한 뒤, 대상 프로젝트에서 사용자나 에이전트가 실행할 수 있습니다.

```sh
.neurath/run verify check
```

프로젝트가 지정한 명령, 작업 디렉터리, 성공 조건과 시간 제한으로 검사합니다.
검사 중 저장소 파일이 바뀌면 종료 코드가 성공이어도 통과로 처리하지 않습니다.
`check`가 없다면 실제 검사 명령을 먼저 연결하세요. 설치된 도구만 보고 검사를 정하지 않습니다.

작업을 전달받을 때는 바뀐 동작, 실제 실행한 검사, 검토에서 발견한 문제와 남은 한계를
확인하세요. 테스트 결과, 다른 에이전트의 보고, 원격에 올라간 커밋은 서로 다른 사실을
증명합니다. 독립 검토가 필요한 작업에서는 테스트 통과로 검토를 대신할 수 없습니다.

## 4. 작업을 이어가고 에이전트와 협업하기

다음 세션에서도 이어서 달성할 결과를 분명히 말합니다.

> 작업 기록 내보내기 수정을 이어가자. 저장된 결정과 남은 일을 읽고 현재 코드와 대조한 뒤,
> 아직 하지 않은 검증을 마쳐줘.

활성화된 훅은 작업 기록을 저장하고 관련 프로젝트 기억을 불러옵니다. 에이전트는 명령을
사용한 작업을 마칠 때 간결한 인계 기록을 남깁니다. 관련 기록과 학습 상태를 직접 조회할 수도 있습니다.

```sh
.neurath/run memory recall --query "작업 기록 내보내기"
.neurath/run learning status
```

기억은 같은 로컬 Git 저장소와 연결된 worktree 사이에서 공유합니다. 별도 복제본이나
다른 컴퓨터에는 자동으로 공유되지 않습니다. 저장된 결정은 참고 맥락이며 새로운 승인이
아닙니다. 보관 범위와 검증된 실행 방법의 학습 과정은 [기억과 학습](memory.md)에 설명합니다.

여러 작업을 동시에 진행하려면 책임을 나누고 수정 작업에는 별도 worktree를 사용하세요.
필요할 때 동료 작업이나 다른 provider에게 의견을 구하도록 에이전트에게 요청할 수 있습니다.
Newsroom은 활성 동료에게 발견의 제목을 알리고, 각 에이전트가 관련 본문을 조회합니다.
명령, 전달 상태와 provider 준비 조건은 [에이전트 협업](agents.md)을 참고하세요.

## 잘 되지 않을 때

| 증상 | 확인할 내용 |
| --- | --- |
| `neurath` 명령을 찾지 못함 | 설치 출력의 실행 파일 전체 경로를 사용하거나, 설치된 프로젝트에서 `.neurath/run`을 사용합니다. |
| 스킬이나 훅이 나타나지 않음 | 선택한 호스트, 설치 접두어, 프로젝트 신뢰와 훅 로딩을 확인하고 새 세션을 시작합니다. |
| 설치 중 파일 충돌 발생 | 파일을 보존하고 설치 계획을 보며 내용을 조정합니다. [업데이트와 복구](installation.md)를 확인하고 강제로 덮어쓰지 않습니다. |
| 검증 명령이 연결되지 않음 | `.neurath/project.json`에 실제 프로젝트 검사 명령을 설정한 뒤 실행합니다. |
| 동료가 메시지 수신을 확인하지 않음 | 전달 상태를 확인합니다. 보관 또는 전송 상태는 수신 확인이 아니며, 비활성 세션을 자동으로 깨우지 않습니다. |
| 새 세션이 이전 작업을 충분히 기억하지 못함 | 같은 로컬 저장소 또는 연결된 worktree인지, 기록 당시 훅이 활성화돼 있었는지 확인하고 부족한 맥락을 직접 전달합니다. |

로컬 설치 상태를 진단하려면 다음을 실행합니다.

```sh
.neurath/run doctor --protocol
```

설치 파일 배치와 훅 프로토콜 동작을 검사하는 명령입니다. 실제 호스트의 신뢰와 활성화는
호스트에서 별도로 확인해야 합니다. 문제를 보고할 때는 실행한 명령, 기대·실제 동작,
Neurath와 호스트 버전, 최소 재현 절차를 포함하세요. 인용할 출력에서 개인 경로·자격 증명·
비공개 내용을 제거하고, 설치 계획이나 로컬 상태 파일은 올리지 마세요.

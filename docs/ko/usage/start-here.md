# 버그 하나를 끝까지 고치는 과정

[English](../../en/usage/start-here.md) · [사용 안내](index.md)

코딩 에이전트에게 버그를 고쳐 달라고 하면 원인을 조사하고, 방법을 시도하고, 다른 에이전트의 도움을 받기도 합니다. 작업이 길어지면 새 세션에서 이어 가야 할 수도 있습니다. 그때마다 사용자가 원한 동작, 실패한 시도, 유용한 발견, 다음 수정을 맡을 주체 중 무언가가 빠질 수 있습니다.

Neurath는 Claude Code와 Codex 주위에서 이런 정보를 이어 주는 하네스입니다. 요청한 결과를 작업 기록과 담당 주체에 연결해 둡니다. 버그의 원인을 판단하고 수정 결과를 확인하는 일은 여전히 에이전트가 해야 합니다.

이 문서는 **여러분이 개발 중이라고 가정한 웹앱**을 예로 듭니다. 저장한 필터가 브라우저를 새로고침하면 사라집니다. 이 앱과 버그는 설명을 위한 가상 사례이며 Neurath의 기능이 아닙니다. 여기서 실제 앱을 구현하지도 않습니다.

## 원하는 동작부터 정합니다

**목표**는 얻고 싶은 결과입니다. **완료 조건**은 그 결과를 얻었다고 판단할 수 있는 관찰입니다. **태스크**는 요청한 작업과 완료 조건을 기록하고, 다른 작업과의 의존 관계와 최종 결과를 함께 관리하는 단위입니다.

에이전트에게 이렇게 요청합니다.

> 개발 중인 웹앱에서 저장한 필터가 새로고침하면 사라져요. 문제를 재현하고 원인을 찾아 수정한 뒤, 새로고침해도 저장한 선택이 유지되는지 확인해 주세요. 기존 화면은 유지해 주세요.

목표는 새로고침 뒤에도 필터가 유지되는 것입니다. 완료 조건은 문제 재현, 근거가 있는 원인 설명, 수정 후 새로고침 결과, 기존 화면 유지입니다. Neurath는 조사 중에도 이 내용을 태스크에 연결해 둡니다. 체크박스에 표시하거나 관계없는 테스트를 통과하는 것만으로는 이 조건을 충족할 수 없습니다.

**세션**은 코딩 에이전트와 진행하는 하나의 실행 대화입니다. **워크트리**는 그 에이전트가 작업하는 Git 체크아웃입니다. 여러 세션이 참여할 때는 어느 세션이 그 워크트리에 쓸 권한을 갖고 있는지 **클레임**으로 기록합니다. 에이전트는 수정 전에 이를 확인합니다. 유용한 정보를 얻은 것과 다음 수정을 맡은 것은 구분됩니다.

## 조사가 길어져도 요청으로 돌아옵니다

에이전트가 필터가 사라지는 현상을 재현한 뒤, 여러 도구를 쓰며 필터 저장 방식 전체를 다시 설계하는 데 몰두했다고 가정해 보겠습니다. 흥미로운 방향일 수 있지만 아직 여러분의 요청을 해결하지는 못했습니다.

Neurath는 조건에 맞는 작업 중에 **목표 리마인더**를 자동으로 제공합니다. 원래 요청과 관련된 미완료 태스크를 에이전트가 참고할 수 있도록 다시 보여 줍니다. 제공 시점이 되면 다음 조건에 맞는 네이티브 활동이나 훅 이벤트에서 전달하며, 별도의 타이머가 세션을 깨우지는 않습니다. 태스크를 정의하거나 시작하거나 결과를 확정하기 직전에도 제공합니다. 매번 사용자에게 리마인더 요청을 받지는 않습니다.

이 사례에서는 에이전트가 리마인더를 보고 현재 조사와 완료 조건을 비교해야 합니다. 다음 단계를 저장값이 사라지는 지점 찾기로 좁히고, 접근 방식을 바꿔야 한다면 그 이유를 설명하며, 새로고침 검증을 남겨 둡니다. 이렇게 하면 조사 방향이 저장 필터 버그에 계속 연결됩니다. 리마인더 자체가 잘못된 설계를 판정하거나, 수정을 검증하거나, 태스크 상태를 바꾸는 것은 아닙니다.

## 다른 에이전트에게 질문 하나를 맡깁니다

현재 에이전트는 두 가능성을 찾았습니다. 저장 요청이 값을 보관하지 못했거나, 값은 저장됐지만 페이지가 다시 열릴 때 복원하지 못했을 수 있습니다. 두 질문은 나누어 조사할 수 있습니다.

이렇게 요청할 수 있습니다.

> 다른 에이전트에게 저장한 필터가 API 응답에 남아 있는지 확인해 달라고 해 주세요. 현재 에이전트는 새로고침할 때의 동작을 조사하고, 수정 방향을 바꾸기 전에 두 결과를 합쳐 판단해 주세요.

**피어**는 작업에 참여하는 다른 에이전트 세션입니다. 현재 에이전트는 이용 가능한 피어에게 범위가 정해진 일을 직접 맡길 수 있습니다. 현재 대화에 딸린 보조 에이전트를 쓰거나 Codex·Claude Code 세션을 별도로 실행할 수도 있습니다. 실행 주체 사이의 관계가 다르므로 선택한 방식의 실제 환경, 권한, 수정 책임을 확인합니다. 보조 에이전트의 준비만 끝났다면 아직 조사를 수행한 것은 아닙니다. 각 방식과 기술 이름은 [협업 안내](agents.md)에서 설명합니다.

두 번째 에이전트가 API 응답에 저장값이 남아 있다고 보고했다고 합시다. 첫 에이전트는 근거를 읽어야 새로고침 과정이 원인인지 판단할 수 있습니다. 직접 보낸 답변으로 근거를 전달할 수 있습니다. 다른 활성 피어에게도 도움이 되는 발견이라면 작성자가 로컬 공유 공간인 **뉴스룸**에 게시할 수도 있습니다. 활성 피어에게는 제목이 자동 전달되고, 필요한 피어가 본문을 따로 읽습니다. 비활성 피어를 깨우거나 모든 대화에 본문을 자동 삽입하지는 않습니다.

결과를 받은 에이전트는 내용을 읽고 수신을 확인한 다음 자신의 관찰과 대조하여 맡겼던 일의 결과를 기록합니다. 메시지가 접수되거나 전달되었다는 상태는 전달 단계만 나타냅니다. 원래 태스크에는 여전히 수정과 새로고침 검증이 남아 있습니다. 방법을 고르고 진행 상태를 확인하는 자세한 설명은 [다른 에이전트와 작업하기](agents.md)에 있습니다.

## 새 세션에서 작업을 이어 갑니다

수정을 끝내기 전에 현재 세션을 종료해야 한다고 가정해 보겠습니다. **맥락**은 에이전트가 지금 판단에 사용할 수 있는 정보입니다. **메모리**는 다음 세션에서도 찾아볼 수 있도록 남겨 둔 프로젝트 이력입니다. **체크포인트**는 결정한 내용, 불확실한 점, 다음 할 일을 에이전트가 적은 인수인계 보고입니다. **대화 기록**에는 세션의 대화와 도구 활동이 담기므로 요약에서 빠진 세부 사항을 확인하는 데 도움이 됩니다.

이렇게 요청할 수 있습니다.

> API에서 확인한 내용, 새로고침 동작 조사, 이미 수정한 부분, 아직 하지 못한 검증을 남겨 주세요. 새 세션에서 같은 저장 필터 태스크를 이어 가 주세요.

호스트의 네이티브 훅이 활성화되어 있으면 Neurath는 사용자 요청, 명령 실행 결과, 세션 생명주기 시점의 인수인계 보고 등 지원되는 관찰을 자동 기록합니다. 새 세션을 시작할 때는 남아 있는 맥락의 일부를 정해진 분량 안에서 불러옵니다. 필요하면 에이전트가 추가 이력을 조회하거나 체크포인트를 작성할 수 있습니다. 에이전트의 보고는 보고로 남습니다. 실행을 관찰하지 못한 검증이 보고만으로 실행 사실이 되지는 않습니다.

일반적인 새 세션은 다른 세션의 작업을 인수하지 않고도 자동 회상과 추가 이력 조회를 사용할 수 있습니다. 중단된 세션의 미완료 태스크와 파일 수정 책임까지 이어받아야 할 때는 새 세션이 **메모리 풀**을 사용합니다. 이전 세션에 남은 작업 정보를 스냅샷으로 가져오고, 사용할 수 있는 대화 기록도 함께 참고합니다. 이전 세션이 마지막 체크포인트를 작성하거나 먼저 정보를 보내야만 가능한 것은 아닙니다. 목록 확인, 미리보기, 본문 읽기는 참고 자료를 얻는 단계이며 소유권을 넘기지는 않습니다.

새 세션이 수정하기 전에는 이전 세션의 실행이 멈추고, 그 세션에 연결된 자식 작업, 프로바이더 작업, 피어에게 맡긴 일이 정리되어 있어야 합니다. Neurath는 스냅샷과 현재 상태가 여전히 일치하는지 확인합니다. 인수할 때는 미완료 태스크와 워크트리 쓰기 권한을 함께 이전하고, 의존 관계를 보존하며, 이전 세션이 다시 쓰기를 시작하지 못하게 합니다. 새 세션의 네이티브 설정은 그대로 유지됩니다. 이전 상태가 바뀌었다면 다시 미리보기를 해야 하며, 강제로 빼앗아 오는 경로는 없습니다.

이 사례에서 새 세션은 어떤 API 근거를 가져왔는지, 새로고침 관련 수정이 어디까지 되어 있는지, 어떤 완료 조건이 남았는지 설명할 수 있어야 합니다. 실제 체크아웃을 확인한 뒤 작업을 계속합니다. 없거나 기록되지 않은 내용까지 복원되지는 않으며, 모든 맥락을 완벽히 기억하고 이해한다고 보장하지 않습니다.

이 기록은 같은 Git 공통 디렉터리를 사용하는 로컬 프로젝트의 Claude Code·Codex 세션과 연결된 워크트리 사이에서 공유됩니다. 별도 클론이나 다른 컴퓨터와 자동 동기화되지는 않습니다. 알려진 자격 증명 패턴은 가리고 비공개 추론은 제외하지만, 남은 프로젝트 맥락도 비공개 정보일 수 있습니다. 저장 범위, 읽기 분량, 인수 조건은 [메모리 안내](memory.md)에서 확인할 수 있습니다.

## 실제 실패를 복구한 경험을 남깁니다

이어받은 에이전트가 저장 필터 회귀 테스트를 실행했는데, 테스트 실행기가 웹앱 디렉터리를 요구하는데 저장소 루트에서 실행해 명령이 실패했다고 합시다. 에이전트가 실행 디렉터리를 고쳐 **같은 테스트를 다시 선택해 실행**했고 이번에는 성공했습니다. 더 쉬운 다른 테스트로 바꾸어 통과했다면 앞선 실패를 복구했다고 볼 수 없습니다.

**회고**는 에이전트가 무슨 일이 있었고 다음에는 어떻게 할지 설명하는 것입니다. Neurath의 **복구 학습**은 실제 관찰이 있어야 진행됩니다. 같은 세션·워크트리·명령 계열에서 실패한 명령을 바꾸어 성공했고, 그 실행이 프로젝트의 검증 기준과 연결되어 있어야 합니다.

이때 생기는 것은 후보이며, 아직 확립된 규칙이 아닙니다. 그 경험이 나온 세션에서 설정된 프로젝트 검사를 통과하면 시험 적용 안내가 됩니다. 그 안내를 접한 다른 세션이 같은 복구 방법으로 성공하고 일치하는 검사까지 통과해야 활성 안내가 됩니다. 복구 방법이 다시 실패하거나 시험 적용 뒤 검사가 실패하면 안내를 철회합니다. 검증 기준이 달라지면 오래된 안내로 처리합니다.

이 과정은 실제 작업에서 관찰된 근거를 따라 진행됩니다. 근거를 만들려고 별도 세션이나 관계없는 실험을 자동 생성하지 않습니다. 종료 시점에 기존 권한 안에서 필요한 학습 검사를 요청할 수 있지만, 실행할 수 없거나 허용되지 않은 검사는 검증되지 않은 상태로 남깁니다. 바뀌는 것은 저장된 안내이며, 모델을 재훈련하거나 에이전트의 권한을 늘리지 않습니다.

별도로 다음과 같이 요청할 수도 있습니다.

> 이 경험을 프로젝트 지침에 넣을 만한지 검토해 주세요. 반복해서 쓸 수 있는 규칙을 제안하고, 승인된 변경을 적용하기 전에 이번 사건의 비공개 정보는 제거해 주세요.

이 요청은 반복되는 관찰을 프로젝트에 지속적으로 적용할 규칙으로 제안하는 작업입니다. 실제 지침을 바꾸려면 권한과 개인정보 검토가 필요합니다. 회고, 자동으로 검증되는 복구 안내, 승인된 프로젝트 규칙 변경은 서로 다릅니다. 메모리를 규칙으로 옮기는 작업 절차는 [스킬 안내](skills.md)에서 설명합니다.

## 처음 요청한 결과를 확인합니다

이 가상 사례에서는 페이지 초기화가 복원한 선택을 기본값으로 덮어쓰는 것이 원인으로 드러납니다. 에이전트가 초기화 순서를 고칩니다. 선택을 저장한 뒤 새로고침해 같은 선택이 남아 있음을 확인하고, 기존 조작 요소와 화면 배치도 유지되었음을 확인합니다. 보고에는 이 관찰을 처음의 실패와 연결하고 무엇을 바꿨는지 설명합니다.

세션 교체와 두 번째 조사는 그 결과에 도달하기 위한 방법이었습니다. 최종 근거에는 여전히 새로고침 뒤 저장한 선택이 유지되는 결과와 기존 화면을 확인한 방법이 있어야 합니다. 인수인계가 성공했거나 테스트 명령 하나가 통과했더라도 완료 조건의 근거가 빠졌다면 작업이 남아 있습니다.

각 기능의 관계도 이 사례 안에서 드러납니다. **태스크**는 요청한 결과를 담고, **목표 리마인더**는 그 결과를 다시 보게 합니다. **협업**은 범위가 정해진 조사 결과를 더하고, **메모리와 체크포인트**는 필요한 맥락을 남깁니다. **인수**는 다음 작업의 책임과 권한을 확정하며, **복구 학습**은 반복되는 실행 실패를 넘긴 검증된 방법을 남깁니다. 어느 기능도 처음 요청한 동작의 최종 확인을 대신하지 않습니다.

## 내 프로젝트에서 시작합니다

[설치 안내](installation.md)를 따라 에이전트에게 자신의 저장소와 사용할 호스트에 맞게 Neurath를 준비해 달라고 요청하세요. 에이전트는 기존 지침, 훅, 권한, 의존성을 보존하고 설치 파일, 실행 가능한 런타임, 실제로 관찰한 호스트 활성화를 구분해 확인해야 합니다.

그다음 실제 작업 하나를 고르고 원하는 동작과 만족할 수 있는 확인 결과를 설명하세요. 저장소의 기존 지침과 검사는 [프로젝트 연결 안내](profiles.md)에 따라 연결합니다. 작업에 필요할 때 다른 에이전트의 도움, 체크포인트, 인수를 요청하면 됩니다. 이런 행동은 허가된 작업 범위에서 이루어집니다. 훅을 통한 기록과 회상, 목표 리마인더, 조건에 맞는 복구 관찰은 필요한 호스트 참여가 활성화된 환경에서 자동으로 작동합니다.

Neurath는 맥락과 책임을 이어 가도록 돕습니다. 결과가 의미상 옳다고 보장하거나, 없는 검증을 만들거나, 권한을 늘리거나, 미완료 목표를 성공으로 바꾸지는 않습니다. 이 예시를 읽은 뒤에는 [사용 안내](index.md)에서 필요한 작업을 찾고, 보고에 나온 기술 이름이 궁금할 때 [용어 찾기](../terminology.md)를 참고하세요.

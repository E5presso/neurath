# 조사를 시작하기 전에 에이전트 준비하기

개발 중인 웹앱에서 저장한 필터가 사라지는 문제를 맡기기 전에, 실제로 작업할 저장소에 Neurath가 연결되어 있는지 확인하세요. Neurath는 Claude Code나 Codex에 작업 지침, 반복해서 사용할 절차, 이벤트 처리를 더합니다. 에이전트를 실행하는 애플리케이션을 **호스트**라고 합니다.

프로젝트 폴더를 Codex나 Claude Code에서 열고, 아래 요청문을 그대로 보내세요.

> https://github.com/E5presso/neurath 의 설치 문서를 읽고, 현재 프로젝트에 Codex와 Claude Code용 Neurath를 설치해 주세요. 아직 Git 저장소가 아니면 먼저 초기화해 주세요. 기존 지침·훅·권한·개발 환경은 보존하고, 프로젝트의 문서와 검사 명령을 연결해 주세요. 설치 후 새 세션에서 훅과 MCP 도구가 실제로 활성화되는지 확인하고, 제가 직접 해야 하는 신뢰 승인이 있으면 안내해 주세요.

호스트 하나만 지정해도 됩니다. 에이전트는 대상이 지원되는 macOS 또는 Linux의 Git 저장소인지 확인하고 Neurath의 독립된 실행 환경을 준비합니다. 현재 이 실행 환경에는 Python 3.14가 필요하지만, 애플리케이션의 언어나 의존성을 여기에 맞출 필요는 없습니다. 호스트 로그인과 프로젝트 신뢰 설정은 해당 호스트가 관리합니다. 설치가 자격 증명을 제공하거나 사용자를 대신해 신뢰를 승인하지는 않습니다.

## 적용할 변경 확인하기

에이전트는 기존 프로젝트 지침과 설정을 살핀 뒤 설치 계획을 준비합니다. 먼저 검토하고 싶다면 바뀔 파일의 미리보기를 요청하세요. 기존 지침, 권한, 프로젝트 의존성은 보존됩니다. 세션 시작이나 도구 실행 완료 같은 호스트 이벤트에 반응하는 처리기인 **훅**도 기존 구성을 보존하면서 연결합니다.

관리 대상과 이름이 겹치는 파일이 있거나 Neurath가 관리하던 파일을 수정했다면 설치 또는 업데이트에서 충돌이 발생할 수 있습니다. 에이전트는 충돌한 내용을 확인하고 요청 범위 안에서 해결해야 합니다. 계획이 만들어졌다는 이유로 내용을 조용히 덮어쓰면 안 됩니다.

설치 과정에서는 기존 프로젝트 문서와 검사를 연결합니다. 이후 작업이 저장소의 기준을 따르도록 하기 위해서입니다. 필요한 결정이나 검사가 없다면 무엇이 빠져 있는지 알려야 합니다. 연결의 의미는 [프로젝트 기준](profiles.md)에서 설명합니다.

## 실제로 활성화되었는지 확인하기

설치 결과에서는 다음 네 가지를 구분해서 확인하세요.

- 계획한 파일이 저장소에 배치되었는지
- 설치된 Neurath 실행 환경이 동작하는지
- 선택한 호스트에서 발생한 실제 이벤트가 Neurath 훅에 도달했는지
- 현재 호스트 연결에서 Neurath 도구를 사용할 수 있는지

이 도구는 호스트가 Neurath를 호출하는 연결 규약인 **MCP**를 통해 제공됩니다. 파일을 바꿔도 이미 열려 있던 호스트가 이전 연결을 유지할 수 있습니다. 필요하면 에이전트에게 연결을 다시 맺거나 새 호스트 세션에서 확인하도록 요청하세요. 에이전트가 호스트를 직접 재시작할 수 있는지는 해당 호스트가 제공하는 제어 수단에 달려 있습니다.

이때 Neurath 공통 문제를 공개 보고해도 되는지 한 번 물을 수 있습니다. 거절하거나 답하지 않아도 Neurath 사용은 계속할 수 있습니다. [보고 설정](reporting.md)을 참고하세요.

## 설치 업데이트하기

지원되는 훅은 작업 중 에이전트에게 릴리스 확인 시점이 되었음을 알려 줄 수 있습니다. 이후 에이전트가 안정 버전의 새 릴리스를 확인하고 업데이트 알림을 제시합니다. 훅 자체가 네트워크 요청을 하거나 다른 세션을 만들지는 않습니다. 일반 확인은 최소 하루 간격이며, 새로 확인해 달라고 요청할 수도 있습니다. 알림만으로 업데이트가 설치되지는 않습니다. 네트워크 확인에 실패하면 새 버전의 유무는 미확인으로 남으며 원래 작업은 계속합니다.

> 사용 가능한 Neurath 업데이트와 이 설치에 미치는 영향을 보여 주세요. 제가 선택하면 준비된 버전을 적용하고, 이후 실제 호스트 연결도 확인해 주세요.

사용자의 선택은 준비된 릴리스에 적용됩니다. 미리보기가 달라지면 다시 선택해야 합니다. 미룬 버전은 보류 상태를 유지합니다. 업데이트에서도 프로젝트 연결과 로컬 설정을 보존하며, 수정된 관리 파일은 해결해야 할 충돌로 남습니다.

## 복구하거나 제거하기

설치가 중단되었다면 복구를, 이전 설치로 돌아가려면 복원을, 더 사용하지 않으려면 제거를 요청할 수 있습니다. 복구는 저장된 작업 상태를 사용합니다. 복원과 제거는 관련 없는 수정 및 사용자가 편집한 프로젝트 연결을 보존합니다. 로컬 설치 이력이나 빈 디렉터리는 남을 수 있으므로, 제거가 모든 로컬 기록의 삭제를 의미하지는 않습니다.

준비를 마치면 [첫 조사 이야기](start-here.md)로 돌아가세요. 실행 가능한 설치 절차가 필요한 에이전트는 [설치 참조](../contributing/installation.md), [설정 참조](../contributing/setup-reference.md), [릴리스 참조](../contributing/releases-reference.md)를 사용합니다.

## 하네스가 이상동작할 때

에이전트는 Neurath의 이상동작을 감지하면 별도 허가를 묻지 않고 스스로 하네스를 임시로 끌 수 있습니다. 전환 이유를 알리고 미완료 작업을 보존하며, 복구를 확인한 뒤 다시 켭니다. 특정 오류에 한정하지 않으며, 모순된 지침, 무진전 반복, 중지 방해 등 하네스의 이상동작 전반에 적용됩니다. 호스트 보안과 사용자의 지시는 그대로 유지됩니다.

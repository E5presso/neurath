# 사용자 작업 흐름

[문서 안내](index.md) · [English](../en/workflows.md)

아래는 [제품 명세](specification.md)에 따른 계획된 흐름입니다. 현재 체크아웃의 공개 CLI·호스트 연동은 미구현이며, 지금 호출할 수 있는 내부 API는 [프로젝트·세션 기반](core-foundation.md)과 [태스크 원장](task-ledger.md)에 있습니다.

## 요청하고 진행 확인하기

> 이 문제를 조사하고 수정한 뒤, 원래 문제가 해결됐는지 확인해 줘.

설치된 rules를 받은 에이전트가 요청에 맞는 스킬을 선택합니다. 태스크에는 사용자 원문과 필요한 결과를 연결하고 TODO로 전체 진행을 표시합니다. 선택한 스킬의 단계와 시도는 runner가 관리합니다. 단순 질문이나 상태 확인은 새 작업이나 워크플로를 만들지 않습니다. [스킬 선택 기준](interfaces.md#2-스킬)을 참고하세요.

## 정정하거나 중단하기

> API는 그대로 두고 화면만 수정해 줘.

정정한 부분만 현재 작업에 반영하고, 나머지 요구와 이전 시도는 보존합니다. 명시적인 중단은 실제 호스트 실행을 멈추는 경로로 처리합니다. 외부 결과를 기다릴 때는 남은 일과 대기 이유를 알리고, 같은 상태로 에이전트를 반복 호출하지 않습니다.

## 위임하고 결과 확인하기

> 다른 에이전트에게 검토를 맡기고 지적된 문제를 고쳐 줘.

위임받은 에이전트는 원래 요청과 맡은 범위 안에서 수행·검사·보고합니다. 메시지 전달이나 결과 보고만으로 상위 작업이 완료되지는 않습니다. 작업 묶음을 마무리할 때 별도 평가자가 원문·최신 정정·TODO·산출물을 대조합니다. 실행자는 확인된 미달 항목을 보완합니다. [실행·결과 평가](architecture.md#3-skills와-phase-runner의-실행-계약)에 세부 흐름이 있습니다.

## 이어서 수행하기

> 이 작업의 남은 부분을 기존 결과를 유지하며 이어서 해 줘.

컨텍스트 압축 뒤에는 훅이 최신 enclave를 자동 적재합니다. 세션을 재개하거나 인수할 때는 원문·미완료 작업·runner·현재 사실을 이어받고 이전 실행과 중복 작성하지 않게 조정합니다. 재개 전 맥락 조회는 작업 인수와 구분합니다. [기억·인계](architecture.md#5-enclave기억graphifypull)를 참고하세요.

## 마무리하고 회고 선택하기

종료 훅은 최신 태스크 상태를 결정론적으로 확인합니다. 실제 외부 대기·사용자 중단·장애로 제어권을 반환한 경우에는 미완료를 보존합니다. 세션 중 개선할 문제가 드러났으면 말미에 회고를 한 번 제안합니다. 사용자가 요청하거나 수락하면 별도 평가자의 회고를 바탕으로 개선·검증하고, 거절하거나 답하지 않으면 원래 작업을 마무리합니다. [회고 절차](interfaces.md#6-사용자가-선택하는-회고)를 따릅니다.

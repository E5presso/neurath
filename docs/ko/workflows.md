# 사용자 작업 흐름

[문서 안내](index.md) · [English](../en/workflows.md)

원하는 결과를 자연어로 설명하세요. 연결된 에이전트가 요청을 Neurath에서 지원하는 연산으로 옮깁니다. 호스트가 어떤 동작을 수행할 수 없다면 성공을 만들어 기록하지 않고 제약을 설명해야 합니다.

## 작업 시작하기

> 이 문제를 조사하고 수정안을 제시한 다음 구현해 줘. 원래 문제가 더 이상 발생하지 않는지 검증하고, 단계와 성공 조건을 계속 보여 줘.

작업에는 출처와 소유자가 기록되어야 합니다. 단계는 모든 작업에 강제되는 공통 체크리스트가 아니라 해당 작업에 맞춰 정한 순서 목록입니다. 각 단계는 대기, 진행, 완료 상태를 가집니다. 이후 단계는 앞선 단계가 완료돼야 시작할 수 있습니다. 근거에는 뒷받침하는 작업과 단계가 드러나야 합니다.

작업 상태는 대기, 진행, 입력·결과 대기, 완료, 철회입니다. 입력·결과를 기다리는 작업에는 여전히 주의나 입력이 필요하며, 철회한 작업은 성공한 완료가 아닙니다.

## 미완료 작업 이어가기

> 이 세션이 소유한 미완료 작업을 보여 주고 각각의 다음 단계를 설명해 줘. 선택한 작업은 기존 근거를 유지하면서 이어서 진행해 줘.

계속하기 전에 소유자와 현재 리비전을 확인하세요. 저장된 작업을 복구했다고 소유권이 자동으로 이전되거나 해제된 임대를 다시 얻는 것은 아닙니다. 마이그레이션에서 판단하지 못한 값은 해소하는 동안에도 불확실성을 표시해야 합니다.

## 위임하고 검토하기

> 다른 에이전트에게 이 결과의 검토를 맡겨 줘. 검토 내용을 기록한 다음 이 작업의 조건을 충족하는지 판단해서 수락해 줘.

위임은 준비에서 실행을 거쳐 결과 보고로 이동합니다. 소유자는 보고를 수락하거나 거절할 수 있습니다. 거절된 결과는 다시 작업할 수 있습니다. 소유자는 열린 위임을 취소할 수 있습니다. 결과 보고가 상위 작업을 완료하지 않으며, 메시지를 읽는 행위가 작업 수락을 의미하지도 않습니다.

로컬 생명주기 기록 자체가 외부 에이전트를 실행하지는 않습니다. 실제 전달과 실행에는 지원되는 호스트 연동이 필요합니다. 그런 연동이 없다면 에이전트는 인계 기록은 남길 수 있지만 이 프로토콜만으로 실행할 수는 없다고 설명해야 합니다.

## 완료할 수 있는지 판단하기

> 모든 성공 조건을 근거와 대조하고, 해결되지 않은 위임을 확인해서 이 작업을 완료할 수 있는지 설명해 줘.

소유자가 명시적으로 완료를 결정합니다. 모든 단계가 완료되어야 하고, 각 조건에는 단순 보고를 넘는 적용 가능한 성공 근거가 있어야 하며, 위임은 수락되거나 취소되어야 합니다. 다른 작업이나 단계의 근거로 조건을 자동 충족할 수 없습니다.

## 지원 범위 이해하기

새 설계는 세션, 작업, 순서가 있는 단계, 근거, 위임, 통신, 체크포인트, 수신증, 호출, 임대를 위한 로컬 기록을 제공합니다. 실제 호출 가능한 기능은 [기여 안내](../../CONTRIBUTING.ko.md)에 명시합니다.

이 기록이 있다는 이유만으로 자동 공개 배포, 원격 배포, 외부 에이전트 실행, 독립적인 호스트 증명, 사람의 승인을 추정하지 마세요. 로컬에 설치한 후보는 공개 릴리스가 아닙니다. 수용 계약은 [명세](specification.md), 보존 요구사항은 [복구 안내](recovery.md)를 참고하세요.

# 필요한 용어 찾기

[English](../en/terminology.md) · [사용 안내](usage/index.md)

보고나 참조 문서에서 낯선 말이 나왔을 때 찾아보는 페이지입니다. Neurath가 처음이라면 [저장 필터 예시](usage/start-here.md)를 먼저 읽으세요. 개념이 필요한 순간에 맞춰 설명합니다.

## 요청한 일과 결과

| 용어 | 작업에서의 뜻 | 기술 이름과 적용 범위 |
| --- | --- | --- |
| 목표 | 새로고침해도 저장한 선택이 유지되는 것처럼 사용자가 원하는 결과입니다. | 태스크의 `goal`에 기록합니다. 조사 방법이 원래 목표를 대신하지 않습니다. |
| 완료 조건 | 원하는 결과를 얻었는지 판단할 수 있는 관찰 조건입니다. | 태스크의 `acceptance`이며, 성공에는 그 조건에 맞는 근거가 필요합니다. |
| 태스크 | 요청의 출처, 완료 조건, 의존 관계, 결과를 함께 관리하는 작업 단위입니다. | 태스크 원장과 `task_define`, `task_start`, `task_resolve`로 관리합니다. |
| TODO | 호스트 화면에 나타나는 태스크 목록입니다. | 태스크 원장을 표시한 것으로, 별도의 완료 판정 기준이 아닙니다. |
| 목표 리마인더 | 원래 요청과 관련 미완료 작업을 다시 참고하도록 제공하는 맥락입니다. | 훅이 자동 제공하는 참고 정보입니다. 태스크 상태를 바꾸거나 성공을 보증하지 않습니다. |
| 결과 | 담당 주체가 작업이 어떻게 끝났는지 기록한 보고입니다. | `succeeded`, `failed`, `invalidated`가 있습니다. 종료 상태라고 모두 성공은 아닙니다. |
| 리시트 | 특정 사건을 기록한 자료입니다. | 실제로 무엇을 관찰했는지에 따라 의미가 달라집니다. 메시지 전달 기록으로 수정 검증을 증명할 수 없습니다. |
| 출처 | 사실이나 요구사항이 어디서 나왔는지 나타내는 정보입니다. | `provenance`이며 태스크, 보고, 관찰과 함께 보존합니다. |

## 누가 어디서 작업하는가

| 용어 | 작업에서의 뜻 | 기술 이름과 적용 범위 |
| --- | --- | --- |
| 호스트 | 네이티브 세션과 도구 이벤트를 제공하는 코딩 에이전트 앱입니다. | Claude Code 또는 Codex입니다. |
| 세션 | 호스트에서 진행하는 하나의 네이티브 대화 상태입니다. | 재개한 세션은 작업을 유지할 수 있으며 새 세션은 별도의 식별 주체입니다. |
| 루트 | 한 세션의 주된 실행 주체입니다. | 확인된 네이티브 루트가 자신의 태스크 변경을 담당합니다. |
| 네이티브 자식 | 현재 세션에 직접 딸린 하위 에이전트입니다. | 호스트가 직접 부모·자식 관계를 확인합니다. 준비만 끝났다면 자식이 실행된 것은 아닙니다. |
| 피어 | 발견을 주고받거나 일을 맡을 수 있는 다른 에이전트 세션입니다. | 피어를 찾거나 메시지를 수락했다고 파일 소유권까지 얻지는 않습니다. |
| 프로바이더 세션 | 맡긴 일을 수행하기 위해 별도로 실행한 네이티브 세션입니다. | 독립된 네이티브 루트입니다. 활성화, 설정, 모델, 소유권을 따로 확인합니다. |
| 워크트리 | 세션이 작업하는 Git 체크아웃입니다. | 체크아웃의 식별 단위이며, 연결된 워크트리끼리는 로컬 프로젝트 상태를 공유할 수 있습니다. |
| 클레임 / 리스 | 현재 워크트리에 쓸 수 있는 권한입니다. | `worktree_claim`으로 얻습니다. 해제할 때 실제 반환된 리스 세대와 `fencing_token`을 사용합니다. |
| 펜싱 토큰 | 오래된 소유자의 쓰기나 해제 요청을 거부하는 데 쓰는 값입니다. | 소유권 제어 정보입니다. 주체 이름을 복사하거나 이전 소유권 보고를 제시해 대신할 수 없습니다. |
| 실행 정책 | 프로바이더 실행에 적용하는 권한과 도구·훅 규칙입니다. | `inherit`는 바로 생성한 주체를 따르고, 명시적으로 고른 `target-native`는 대상 호스트의 기존 기본값을 사용합니다. |
| 모델 선택 | 맡길 작업에 사용할 모델을 정하는 일입니다. | `selection.model="inherit"`는 실행 정책과 별개이며 실제 실행 모델과 대조해야 합니다. |
| 뉴스룸 | 다른 활성 피어에게 도움이 될 발견을 게시하는 로컬 공간입니다. | 활성 피어에게 제목을 자동 알립니다. 본문은 `newsroom_read`로 명시적으로 읽습니다. |
| 수신 확인 | 수신자가 메시지 본문 전체를 읽었다고 확인하는 단계입니다. | ACK라고 부릅니다. 일을 맡겠다는 수락, 실제 완료와는 별개입니다. |

## 다음 작업으로 가져가는 정보

| 용어 | 작업에서의 뜻 | 기술 이름과 적용 범위 |
| --- | --- | --- |
| 맥락 | 에이전트가 현재 판단에 사용할 수 있는 정보입니다. | 지금 관찰한 내용과 다시 불러온 참고 자료를 포함할 수 있습니다. |
| 프로젝트 메모리 | 다른 로컬 세션이 찾아볼 수 있도록 출처와 함께 남긴 프로젝트 이력입니다. | Git 공통 디렉터리를 기준으로 선택한 로컬 SQLite 상태입니다. 클론·컴퓨터 간 자동 동기화는 없습니다. |
| 체크포인트 | 결정, 다음 할 일, 남은 작업을 정리한 에이전트의 인수인계 보고입니다. | `memory_checkpoint`입니다. 보고의 `completed`는 태스크 확정이나 클레임 해제를 뜻하지 않습니다. |
| 대화 기록 | 네이티브 대화와 도구 활동의 기록입니다. | 인수 과정에서 등록된 원본을 읽고, 비공개 추론과 알려진 자격 증명 패턴을 제외하며, 출처와 누락 정보를 보존합니다. |
| 메모리 풀 | 새 세션이 이전 세션에 남은 작업 정보를 가져오는 과정입니다. | `memory_pull`의 list/preview/read는 참고 단계입니다. 이전 세션의 마지막 체크포인트가 필수는 아닙니다. |
| 인수 | 새 세션이 미완료 작업을 계속할 수 있도록 확인을 거쳐 넘기는 단계입니다. | `memory_pull`의 adopt입니다. 이전 실행이 정리된 뒤 미완료 태스크와 워크트리 리스를 함께 이전하고 이전 세션의 재작업을 막습니다. |
| 스냅샷 | 인수할 작업을 살펴보기 위해 보관한 이전 상태의 모습입니다. | 수신자에게 귀속된 불변 미리보기입니다. 이전 상태가 바뀌면 인수 전에 새 미리보기가 필요합니다. |
| 인클레이브 | 세션의 현재 사실을 정해진 범위 안에서 담은 기록입니다. | 리비전과 다이제스트로 변경을 제어합니다. 과거 메모리만으로 현재 사실을 덮어쓸 수 없습니다. |

## 더 나은 작업 방법을 남기는 과정

| 용어 | 작업에서의 뜻 | 기술 이름과 적용 범위 |
| --- | --- | --- |
| 회고 | 경험과 거기서 얻을 수 있는 교훈을 설명하는 일입니다. | 에이전트의 보고이며 자동으로 검증된 안내가 되지는 않습니다. |
| 복구 학습 | 실패한 동일 작업을 실제로 고쳐 성공한 방법을 남기는 과정입니다. | 후보 → 원래 세션의 프로젝트 검사 후 시험 적용 → 안내를 접한 다른 세션의 같은 복구·검사 성공 후 활성화 순서입니다. |
| 철회되거나 오래된 안내 | 이전 상태대로 더 이상 의존해서는 안 되는 교훈입니다. | 복구나 검사 실패로 `reverted`, 검증 기준 변경으로 `stale`이 될 수 있습니다. |
| 메모리를 규칙으로 | 반복된 관찰에서 지속적으로 적용할 프로젝트 지침을 제안하는 일입니다. | 공개 스킬 이름은 `memory-to-rules`, 원본 ID는 `promote-memory`입니다. 저장소 변경에는 권한과 개인정보 검토가 필요합니다. |
| 스킬 | 특정 종류의 일을 수행하는 재사용 절차입니다. | 공개 스킬 이름으로 절차를 고릅니다. 이름 자체가 작업 의도나 권한을 부여하지는 않습니다. |
| 검증 계약 | 프로젝트 검사를 어떻게 수행하고 판단할지 저장소에 설정한 기준입니다. | 복구 근거를 대조할 때 사용합니다. 일반 소스 수정과 테스트는 계속 네이티브 도구로 수행합니다. |

정확한 인자와 상태 전이는 [태스크 도구 참조](contributing/task-tools.md)를 보세요. 실제 사용 맥락은 [협업](usage/agents.md), [메모리](usage/memory.md), [스킬](usage/skills.md) 안내로 돌아가 확인할 수 있습니다.

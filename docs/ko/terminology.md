# 기록과 도구를 읽기 위한 용어

[English](../en/terminology.md)

Neurath는 에이전트가 요청한 일, 도구가 실행한 작업, 이후 확인한 결과를 기록합니다. 이 문서는 각 기록의 뜻과 도구 결과·소스에서 볼 수 있는 정확한 식별자를 연결합니다. 기록에는 성공뿐 아니라 실패나 아직 확인하지 못한 결과도 담깁니다.

## 결과와 이력을 나타내는 말

| 문서에서 쓰는 말 | 도구·소스의 식별자 | 담고 있는 내용 |
| --- | --- | --- |
| 설치 이력 | `install receipt`, `neurath-receipts` | 설치한 파일과 복원에 필요한 이전 내용, 모드, 링크. |
| 실행 결과 | `tool receipt`, `ToolReceipt` | 도구 호출 상태, 출력 지문, 관찰한 변경. |
| 검증 기록 | `verification receipt` | 확인한 대상과 조건, 실제 결과. |
| 검토 결과 | `review receipt` | 검토에서 발견한 문제와 판정. |
| 처리 기록 | `source receipt`, `prompt receipt` | 처리한 입력이나 사건. |
| 출처 정보 | `provenance` | 사실, 결과, 산출물을 얻은 곳. |
| 호스트 확인 | `attestation`, `HOST_ATTESTED` | 실제 호스트에서 관찰해 세션, 행위자, 사건을 확인한 근거. |
| 인계 기록 | `checkpoint` | 진행 상황, 결정, 근거, 남은 일에 대한 에이전트의 보고. |

`receipt`는 보관한 기록을 가리키는 기술 용어로, 이 문서에서는 결제 영수증이라는 뜻으로 쓰지 않습니다. 기록이 무엇을 대상으로 하는지에 따라 해석해야 합니다. 설치 이력의 성공은 파일 배치에 관한 결과이며, 활성화 여부는 실제 호스트 관찰로 확인합니다. 인계 기록은 다음 에이전트에게 보고자가 관찰한 내용을 전합니다. 그 보고에 대한 독립 검토 결과를 뜻하지는 않습니다.

문서에서 쉬운 말을 쓰더라도 도구 인자 이름은 바꾸지 않습니다. 예를 들어 `--installation-id`는 설치 이력을 식별하며, 이전부터 지원한 `--receipt` 별칭도 같은 설치 작업을 가리킵니다.

## 작업을 수행하고 판단하는 주체

| 용어 | 도구·소스의 식별자 | 뜻 |
| --- | --- | --- |
| 작업 | task ledger의 항목 | 요청을 확인 가능한 단위로 나눈 것으로, 출처·완료 조건·의존 관계·결과를 가집니다. |
| TODO | 호스트의 plan 또는 TODO 표시 | 호스트 UI에 보여주는 작업 목록입니다. 기준 상태는 작업 원장에 남습니다. |
| 작업 공간 소유권 | `worktree claim` | 현재 세션이 해당 worktree에 쓸 수 있는 권리입니다. |
| 소유권 확인 키 | `fencing token` | 소유권 세대와 함께 사용해 이전 소유자의 오래된 작업을 거부하는 키입니다. |
| 현재 턴 | `foreground turn` | 호스트에서 확인한 현재 세션의 활성 상호작용 단위입니다. |
| 세션 작업 상태 | `enclave` | 해당 세션에 필요한 최신 사실을 정해진 범위 안에 보관한 상태입니다. |
| 도구 호출 | `invocation` | 정확한 입력과 실행 맥락을 가진 한 번의 호출입니다. |
| 검토자 | `evaluator` | 검토 절차에서 배정된 후보와 근거를 평가하는 주체입니다. |
| 판정 주체 | `oracle_owner`, `OracleOwner` | 특정 결과를 판단하도록 정해진 사용자, 검토자, 실행 결과 또는 공식 출처입니다. |

작업 결과는 인증된 소유자가 기록합니다. 독립 검토를 명시적으로 요구하는 절차에는 그에 맞는 검토 계약이 추가로 적용됩니다. 일반 작업마다 이러한 절차를 모두 거치는 것은 아닙니다. 에이전트 메시지는 정보를 전달하거나 일을 요청할 수 있지만, 사용자의 승인이나 작업 공간 소유권, 검토자 권한을 넘겨주지는 않습니다.

프로젝트 기억은 이후 세션에서 검색할 수 있는 이력을 보관합니다. 세션 작업 상태는 현재 세션에 필요한 최신 사실을 제한된 범위로 유지합니다. 관계 그래프는 소스와 문서의 연결을 탐색하는 데 쓰입니다. 각 역할이 다르므로 기억이나 그래프에서 얻은 내용으로 결정할 때는 현재 요청과 소스에도 맞는지 확인합니다.

## 목표 환기와 작업 승계

다음 용어는 작업이 원래 목적을 유지하고 제공자 사이에서 이어지는 방식을 설명합니다.

| 용어 | 식별자 | 뜻 |
| --- | --- | --- |
| 목표 환기 | `goal_reminders` | 루트 에이전트가 원래 태스크를 기준으로 자신의 방법을 돌아보게 하는 주기적 맥락. 의미상 성공을 채점하거나 태스크 상태를 바꾸지 않습니다. |
| 대상 고유 설정으로 실행 | `target-native` | 수신 제공자의 기존 네이티브 기본값·훅·도구 규칙을 사용하도록 명시적으로 선택한 실행입니다. |
| 작업 승계 | `memory_pull`의 `adopt` | 원본 실행이 정리된 뒤 확인된 수신자에게 미완료 작업과 worktree 소유권을 넘깁니다. 일반 미리보기와 기억 조회는 소유권을 바꾸지 않습니다. |

승계와 원본 재개 차단은 [작업 승계 참조](contributing/provider-continuity.md), 제한된 목표 환기는 [런타임 수명주기](contributing/runtime-lifecycle.md)에서 설명합니다.

## 메시지 전달 상태

전달 상태는 메시지가 어느 단계까지 도달했는지 보여줍니다. 요청한 일의 완료 여부는 응답 내용과 작업 결과에서 확인합니다.

| 상태 | 확인된 사건 |
| --- | --- |
| `queued` | 메시지를 전달할 수 있도록 영속 저장했습니다. |
| `submitted` | 전송 수단이 메시지를 수락했습니다. |
| `received` | 수신자가 본문 전체를 읽었다고 확인했습니다. |
| `replied` | 수신자가 응답을 보냈습니다. |

응답에는 완료 보고, 발견한 문제, 추가 입력 요청 등이 담길 수 있습니다. 일을 맡긴 에이전트는 내용을 읽고 필요한 후속 작업을 이어갑니다. 사용 방법은 [에이전트 협업](usage/agents.md), 프로토콜 세부 사항은 [전달 계약](contributing/collaboration-contract.md)을 참고하세요.

설치 용어가 실제로 어떻게 쓰이는지는 [설치 안내](usage/installation.md)에서, 작업 필드와 상태 전이는 [작업·TODO 계약](contributing/task-todo-contract.md)에서 설명합니다. 설치 대상 프로젝트의 업무 용어는 그 프로젝트의 용어집을 따릅니다. 작업 기록 내보내기와 같은 예시는 에이전트가 대상 프로젝트에서 수행할 수 있는 작업이며, 별도의 Neurath 제품 기능을 뜻하지 않습니다.

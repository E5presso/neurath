# Finalization after worker cleanup

[한국어](../../ko/contributing/post-cleanup-finalization.md)

A merged ticket's cleanup can remove the checkout used by its native tool dispatcher.
The physical cleanup result remains valid even when the worker cannot subsequently
record its final phase or task result.

The original provider issuer uses `worktree_finalize_read` from the surviving primary
checkout with the original provider `run_id` and exact `workflow_id`. The tool derives
the source native session from persisted ownership. It requires recorded process and
connection closure, the original workflow owner, and an exact cleanup release fence.
It returns the source workflow and task revisions without resuming the worker.

The issuer first delegates an independent task association review to a fresh native
child. The exact JSON assignment is `{"kind":"post-cleanup-task-scope","scope":SCOPE}`,
where `SCOPE` is the matching object returned in `task_scopes`. The reviewer checks
that every acceptance criterion of that exact task is covered by the completed
workflow and its remaining terminal bookkeeping. It stores an artifact with schema
`neurath.post-cleanup-task-scope.v1`, that exact `scope`, a boolean
`task_matches_terminal_workflow`, and a substantive `reason`, then reports its verdict.
Only a consumed, host-attested direct child's `pass` with no blocking findings is
accepted. A shared prompt or identical goal text does not bind a task to a workflow.

The issuer then calls `worktree_finalize` with those revisions, the unique unfinished
task, `task_scope_delegation_id`, an idempotency key, and explicit reports of the observed terminal evidence.
Cleanup, merged-state and adaptive receipt labels are generated by the tool from
verified producers. Existing phase evidence and adaptive completion gates still apply.
The typed finalization event records the actual issuer separately from the original
owner. The phase, workflow, task result and recovery receipt commit atomically.

The immutable evaluator candidate remains authoritative only when its exact payload
hash matches the source before the two canonical cleanup transitions. Cleanup and
final phase bookkeeping cannot change instructions, adaptive evidence, or earlier
phase results. Changed source authority fails closed. This also supports existing
cleaned workers whose receipts predate the recovery tools.

The route never recreates a checkout, deletes a branch, repeats cleanup, resumes a
native worker, or changes permissions. Reclaimed fences, recreated paths or branches,
wrong issuers, stale revisions, unverified closure, ambiguous unfinished tasks and
unfinished delegation waves are rejected. Replaying the exact key returns the stored
result; a changed request using that key is rejected.
